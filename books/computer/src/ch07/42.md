# 8.2 操作系统的系统角色：资源抽象、调度与保护

打开一台计算机，同时播放音乐、编辑文档、下载文件，你会看到几个应用各自工作，仿佛都拥有处理器、内存和存储空间。但在主板上，它们往往共用同一组硬件。谁决定哪个程序先运行？谁记录一块内存属于谁？为什么一个应用通常不能直接改写另一个应用的数据？这些问题指向操作系统的三项核心职责：把硬件资源变成可使用的对象，安排资源的使用，并建立访问边界。

## 8.2.1 从硬件对象到软件可用的资源

前一节介绍的固件完成初始配置，并通过启动过程把控制权交给操作系统。此后，操作系统内核逐步承担处理器、内存和设备等资源的管理。内核是操作系统中具有较高权限、负责关键管理工作的核心部分；桌面、命令行和系统工具则为使用者提供不同的操作入口。

观察正在使用的计算机，可以打开任务管理器或同类系统监视工具。屏幕上显示的是进程、内存占用、磁盘活动与网络流量，而不是晶体管和电信号。这种观察方式已经体现了操作系统的作用：它在物理硬件之上，建立了一套便于程序和使用者理解的资源视图。

| 物理资源或能力 | 操作系统提供的常见抽象 | 程序因此能够做什么 |
|---|---|---|
| 处理器的执行能力 | 进程、线程及其运行环境 | 组织任务并获得执行机会 |
| DRAM等内存资源 | 虚拟地址空间 | 用地址访问自身所需的数据 |
| 存储设备上的数据空间 | 文件与目录 | 按名称保存、寻找和组织数据 |
| 网络设备的通信能力 | 套接字等通信接口 | 通过约定接口发送、接收数据 |

抽象保留了完成任务所需的特征，同时隐藏部分实现细节。例如，程序保存文件时，不必自行决定数据写入哪颗闪存芯片。文件系统负责组织名称、位置和相关信息，设备驱动等组件再参与实际的数据传输。抽象降低了使用难度，但硬件的容量、延迟和故障仍会影响最终结果。

## 8.2.2 调度：让共享资源有序服务

一个应用内部可以有多个线程，分别负责界面响应、计算或后台工作。线程是操作系统安排处理器执行机会的基本对象之一；进程则通常承载程序运行所需的地址空间和其他资源。二者相关，却不能简单等同。

当可运行的线程多于可用的处理器执行位置时，调度器需要作出选择。它会结合调度策略、优先级、等待情况等因素，决定让谁运行，以及何时切换。切换时，系统保存当前线程的必要执行状态，再恢复另一个线程的状态，使后者能够接着工作。

在单个处理器核心上，多个任务可以通过交替执行取得进展，这称为并发；拥有多个核心时，部分任务还可以在同一时刻并行执行。不过，线程等待文件读取或网络响应时，即使还有计算要做，也可能暂时无法继续。操作系统可以让其他就绪线程使用处理器，而不必让整个系统一起等待。

因此，播放音乐时仍能编辑文档，并不意味着每个应用始终独占一个核心。调度、缓冲与设备自身的工作机制共同维持了这种体验。任务管理器中的处理器利用率只是观察线索：利用率低，可能意味着任务正在等待输入输出，不能直接证明计算机没有性能瓶颈。

调度也不只涉及处理器。存储请求需要排队，内存紧张时需要回收可释放的空间，网络数据也需要缓冲和处理。不同资源之间存在依赖关系，一处等待可能沿着任务链传播。

## 8.2.3 保护：为程序建立访问边界

共享硬件带来了效率，也带来了风险。如果任何程序都能随意修改内核、访问全部内存或控制设备，一个普通错误就可能破坏整个系统。操作系统需要区分访问者、检查权限，并借助硬件限制越界操作。

常见机制包括处理器特权级、内存访问保护，以及文件和设备的访问控制。普通应用通常在受限权限下运行；需要读取文件、创建进程或请求设备服务时，通过系统调用进入内核提供的受控入口。内核检查请求涉及的对象、参数和权限，再决定是否执行。

例如，文档编辑器请求保存文件时，系统不仅要找到存储位置，还要判断当前身份是否有权写入目标目录。如果程序传入无效地址或试图访问不允许的区域，系统可能拒绝请求，或终止相关进程。保护机制由软件规则与硬件能力共同实现，虚拟内存和MMU的具体配合将在后文展开。

这些边界使许多应用故障能够被限制在局部范围，但不能保证所有错误都被隔离。内核或驱动中的缺陷、过高的授权，以及硬件故障，仍可能影响整个系统。权限越高，出错后波及的范围往往也越大。

## 8.2.4 用一次保存操作连接三项职责

按下“保存”时，可以沿一条简化路径理解操作系统的工作：

**应用发起请求 → 系统检查权限 → 文件系统组织写入 → 驱动与设备完成传输 → 系统报告结果。**

这里，文件是资源抽象，处理器与输入输出请求的安排体现调度，身份和写入权限的检查体现保护。实际路径还可能包含缓存和异步处理：应用收到写入完成的通知，并不总等于数据已经进入断电后仍可保留的介质，具体保证取决于接口语义与后续操作。

可以把这条路径交给AI继续展开：

> 你是一名计算机系统教师。请以“编辑器保存一个本地文件”为对象，分别标出资源抽象、调度和保护出现的位置，用表格解释应用、内核、文件系统、驱动与硬件的职责。区分教学简化与具体系统实现；涉及特定操作系统时，请给出可核验的官方资料。

理解操作系统的关键，是看清它如何把有限的硬件能力组织成可共享、可控制的运行环境。下一步进入驱动程序，便能进一步追踪：统一的软件请求，如何落实为具体设备能够执行的操作。
