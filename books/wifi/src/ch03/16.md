# 3.2 关联：认证、连接与获取地址

在手机的 Wi-Fi 列表里点下家里的网络名称，输入密码，几秒钟后状态栏出现扇形图标，网页就能打开了。这几秒钟看起来只是“连上了”，其实手机和路由器之间完成了好几道手续：先确认彼此能对话，再登记建立连接，接着核对密码、生成加密钥匙，最后向网络申请一个地址。上一节讲的“发现”只是看到了门牌，这一节要讲的是怎样被请进门、领到一个座位号。

## 3.2.1 四道手续：一张流程表

可以把连上 Wi-Fi 想象成入住酒店：前台先确认你是来住店的客人，再办理入住登记，然后核对身份、发房卡，最后告诉你房间号。对应到 Wi-Fi，大致是下面四步：

| 步骤 | 英文名称 | 做什么 | 酒店类比 |
|---|---|---|---|
| ① 开放认证 | Open System Authentication | 双方交换一对简单的认证帧，确认“能互相说话” | 走到前台打招呼 |
| ② 关联 | Association | 终端提交自己支持的速率、标准和能力，接入点登记并分配关联编号 | 填写入住登记表 |
| ③ 密钥协商 | 四次握手（4-Way Handshake） | 双方证明都知道密码，并生成本次连接专用的加密密钥 | 核对身份、领取房卡 |
| ④ 获取地址 | DHCP | 向路由器申请 IP 地址、网关和 DNS 服务器 | 被告知房间号和服务电话 |

前三步发生在 802.11 协议内部，属于“无线链路层”的事；第四步已经进入 IP 网络层，Wi-Fi 只是负责把这些消息运过去。手机界面上“正在连接”“正在获取 IP 地址”“已连接”几种提示，正好对应了这几个阶段。

## 3.2.2 认证与关联：先登记，再说话

第一步的名字叫“认证”，但容易让人误会。在今天的家用网络里，802.11 层面的开放认证几乎不检查任何东西，只是一个礼节性的问答。早期 WEP 时代曾有一种“共享密钥认证”，后来被证明反而会泄露信息，已经弃用。真正的身份核对被挪到了后面的密钥协商环节。

第二步“关联”才是正式登记。手机发送关联请求帧（Association Request），里面写着：我支持哪些速率、哪个 Wi-Fi 代际、几根天线、是否支持省电功能等。接入点（AP，Access Point）根据自己的能力和当前负载决定是否接纳，回复关联响应帧（Association Response），并给这台设备分配一个关联标识（AID，Association ID）。从此，接入点的“住客名单”里多了这台手机，它们之后按双方都支持的方式通信。

如果已经连着一个接入点，移动到另一个接入点覆盖区，终端会发起“重关联”（Reassociation），这是下一节讲漫游时的基础。

## 3.2.3 四次握手：不传密码也能证明知道密码

家用网络最常见的模式是“个人版”（Personal），全家共用一个密码。这里有个巧妙之处：**密码本身从不在空中传送**。

在 WPA2 个人版中，双方先各自用密码和网络名称算出同一把“主钥匙”（PMK，成对主密钥）。接着进行四次握手：接入点和手机各自发出一个随机数，双方把主钥匙、两个随机数和彼此的硬件地址一起计算，得出本次连接专用的临时密钥（PTK，成对临时密钥）。双方再互相发送用这把密钥计算出的校验值——如果对得上，说明对方确实知道同一个密码。握手中还会下发用于广播通信的组密钥（GTK）。

打个比方：两个人不念出口令，而是各自用口令把同一道题算一遍，再对答案。旁人听到了题目和答案的片段，却得不到口令本身。由于每次连接的随机数不同，每台设备、每次连接的密钥都不一样，邻居即使也连在同一网络里，也不能直接读你的数据。

WPA3 个人版则用一种叫 SAE（Simultaneous Authentication of Equals，对等实体同时认证）的交换取代了第一步的开放认证，在关联之前就生成主钥匙，之后再进行四次握手。它的设计让旁观者无法拿录下的握手过程反复离线猜测密码，从原理上提高了弱密码场景下的安全性。具体演进将在 3.4 节展开。对普通读者来说，有效的防护依然朴素：设置足够长的密码，路由器和终端都支持时选用 WPA3，并及时更新固件。

企业网络常用“企业版”（Enterprise），每个人用自己的账号或证书登录，由专门的认证服务器（通常是 RADIUS 服务器）通过 802.1X 机制核验，之后同样进入四次握手。区别只在“主钥匙从哪里来”。

## 3.2.4 DHCP：领到 IP 地址才算真正上网

完成握手后，链路层已经接通，但手机还不能上网——它还没有网络层的地址。这时它广播一条 DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）请求，经典流程有四个消息，常被记作 DORA：

1. **发现（Discover）**：手机广播“谁能给我分配地址？”
2. **提供（Offer）**：家里的路由器（它内置了 DHCP 服务器）回应一个可用地址，例如 192.168.1.x 这类私有地址。
3. **请求（Request）**：手机确认“我要这个地址”。
4. **确认（Acknowledge）**：路由器登记，并告诉手机网关地址、DNS 服务器地址和租期。

“租期”意味着地址是借来的，到期前手机会续租。路由器后台的“已连接设备”列表，往往就是根据 DHCP 分配记录和关联名单拼出来的。手机连上 Wi-Fi 却显示“无法上网”或长时间停在“正在获取 IP 地址”，常见原因就在这一步：路由器地址池耗尽、DHCP 服务异常，或者路由器到上游的线路本身断了。这些与互联网的衔接，会在第四章和《互联网》一册中进一步展开。

## 3.2.5 小结：几秒钟里的分层协作

回头看这几秒钟：认证与关联建立了“谁和谁连着”，四次握手建立了“说话用哪把锁”，DHCP 建立了“在网络里叫什么名字”。三者分属不同层次，按顺序衔接，任何一步失败都会表现为“连不上”，但原因截然不同——提示“密码错误”多半卡在握手，提示“无法获取地址”则多半卡在 DHCP。分清这几道手续，排障时就有了方向。连接建立之后，数据怎样一帧一帧地发出去、对方怎样确认收到，是下一节要讲的内容。
