# 5.3 数据帧流：一个网页请求在无线链路上的旅程

晚上你坐在沙发上，用手机打开一个新闻网页。手指点下去不到一秒，页面开始出现。这一秒里，手机和客厅的路由器之间来回传了几十到几百个数据帧。上一节讲的管理帧和控制帧负责“打招呼”和“维持秩序”，真正搬运网页内容的是**数据帧（Data Frame）**。本节跟着一次网页请求走一趟，看它怎样被装进无线数据帧、怎样过空口，又怎样在路由器里换成网线上的格式。

## 5.3.1 请求在手机里被层层打包

浏览器先要知道网站的地址。它请求域名系统（DNS，Domain Name System）把网址翻译成 IP 地址，然后和服务器建立传输连接，通常还要做一次 TLS 加密握手，最后才发出“请把这个页面给我”的 HTTP 请求。DNS、TCP、TLS、HTTP 这些上层细节在本系列第二十五册《互联网》中有专门讲解。对 Wi-Fi 来说，它们都只是一包包要搬运的 IP 数据包。

这些数据包交给手机里的无线网卡后，网卡的 MAC 层（介质访问控制层）会给每个包加一个“无线信封”。这个过程可以这样排列：

| 层次 | 加上的内容 | 作用 |
|---|---|---|
| 应用层 | HTTP 请求 | 说明“要什么” |
| 传输层 / 网络层 | TCP 头、IP 头 | 写明服务器的 IP 地址和端口 |
| 802.11 MAC 层 | MAC 头、加密字段、帧校验序列 | 写明这一跳无线链路上“谁发、谁收” |
| 物理层 | 前导码、信号字段 | 让接收方锁定信号、知道用什么速率解调 |

这里要分清两类地址。IP 地址决定数据包最终送到哪台服务器，一路基本不变。MAC 地址只管“这一跳”交给谁，每经过一个设备就可能换一次。

## 5.3.2 无线数据帧的“信封”上写了什么

以太网帧的头部一般只有两个 MAC 地址：源和目的。802.11 数据帧的头部通常有三个，有时有四个。原因是无线链路上多了一个中转者，也就是接入点（AP）。

手机发出请求时，三个地址大致是：

- **接收地址**：路由器无线接口的 MAC 地址，也就是这一跳的接收者，同时作为网络标识（BSSID）；
- **发送地址**：手机自己的 MAC 地址；
- **目的地址**：数据最终要交给的有线侧设备，在家里通常是路由器的网关接口。

帧控制字段里有两个标志位“去往分布式系统”和“来自分布式系统”（To DS / From DS），用来告诉接收方这一帧是从终端发往 AP，还是从 AP 发往终端，接收方据此解读各个地址的含义。Mesh 节点之间转发时，四个地址都会用上。

信封里还有几个重要部分：

- **序列号**：用来识别重传的重复帧；
- **服务质量控制字段**：标明数据属于语音、视频、尽力而为还是后台流量；
- **加密头**：在 WPA2/WPA3 网络中，数据正文用 AES 算法加密，并带有完整性校验。被加密的只有正文，MAC 头保持明文，因为别的设备需要读出“这帧是不是发给我”。
- **帧校验序列（FCS）**：放在帧尾，接收方用它检查内容在空中是否出错。

## 5.3.3 过空口，确认与聚合

信封封好后，手机要先按第六章将要讲的 CSMA/CA 规则听信道、等待随机退避，再把帧调制成电磁波发出去。路由器收到后计算校验，如果正确，就在一个很短的固定间隔后回送确认帧（ACK）。手机等不到确认，就认为帧丢了并重传。这和第三章 3.3 节讲的“发送—确认—重传”是同一回事。

如果每个小包都单独抢一次信道、单独确认一次，开销会很大。网页加载时下行数据密集，802.11n 起引入了**帧聚合**，常见形式是 A-MPDU（聚合 MAC 协议数据单元）：把多个数据帧连成一串，一次抢到信道就连续发出，接收方再用一个**块确认（Block Ack）**告诉发送方哪几个收到了、哪几个要补发。可以把它理解为快递员一次送一整车货，最后让收件人在一张清单上打钩，而不是每送一件都等一次签字。高代 Wi-Fi 能把吞吐量做上去，聚合是重要原因之一。

## 5.3.4 在路由器里“换信封”，再原路返回

路由器收到无线帧后先解密、校验，然后拆掉 802.11 的头，换上以太网头，交给内部的交换和路由部分。家用路由器通常还会做网络地址转换（NAT），把手机的内网 IP 换成宽带的外网地址，再经光猫送进运营商网络。光纤与运营商网络的部分不是本书重点，可参阅本系列相关各册。

服务器返回的网页数据沿反方向回来。路由器把以太网帧换回 802.11 数据帧，这时地址的角色倒过来：发送方是 AP，接收方是你的手机。路由器再用自己的密钥加密、抢信道、聚合发送，手机回复块确认。一个页面往往还牵涉图片、脚本等多个服务器，这一往一返会并行发生许多次。

## 5.3.5 小结：一次点击，许多次“换信封”

把这次旅程连起来，可以看出一条规律：**IP 包是货物，802.11 帧和以太网帧是不同路段上的信封。**无线这一段信封最复杂，原因有三个：要写清“经由谁中转”，所以有三到四个地址；空中谁都能收到，所以正文要加密、帧尾要校验；空口容易出错且要轮流使用，所以有确认、重传和聚合。网页打开得快还是慢，很大程度取决于这些帧在空中是否顺利。下一节我们把视角从一部手机扩大到一屋子设备，看大家怎样轮流使用这条共享的无线链路。
