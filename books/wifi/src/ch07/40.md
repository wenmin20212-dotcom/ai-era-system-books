# 7.3 蓝牙与低功耗蓝牙：耳机、手表与物联网

打开手机的设置页面，Wi-Fi 的下面往往紧挨着另一个开关——蓝牙。摘下无线耳机放回充电盒，耳机自动断开；再拿出来，几秒钟后音乐又从耳机里响起。手腕上的智能手表整天同步心率和步数，却一周才充一次电。这些设备和 Wi-Fi 一样工作在 2.4 GHz 频段，走的却是另一条技术路线。前面几节讲的 Wi-Fi 追求“更快、更多人同时用”，蓝牙要解决的是“短距离、低功耗、设备之间直接配对”。本节就从耳机和手表出发，看看蓝牙这根更细、更省电的“看不见的线”是怎样工作的。

## 7.3.1 从“替代数据线”出发：蓝牙的定位

蓝牙（Bluetooth）最初的设想很朴素：用无线连接取代手机、耳机、电脑之间那些杂乱的短数据线。它的标准由蓝牙技术联盟（Bluetooth SIG，Special Interest Group）制定和维护，这一点类似 Wi-Fi 联盟之于 Wi-Fi，只不过蓝牙的核心规范本身就由 SIG 发布，而不是像 Wi-Fi 那样以 IEEE 802.11 为底座。产品要使用“蓝牙”名称和标识，也需要通过 SIG 的认证流程。

和 Wi-Fi 对照，可以把两者的分工看得更清楚：

| 对比项 | Wi-Fi | 蓝牙 / 低功耗蓝牙 |
|---|---|---|
| 主要目标 | 接入局域网和互联网，高吞吐 | 设备之间短距离直连，低功耗 |
| 典型组织方式 | 以接入点为中心的网络 | 一对一或一对多的直连、广播 |
| 典型距离 | 室内一般覆盖一套住房 | 多在数米到十几米量级（公开资料中的常见说法，受功率、环境影响很大） |
| 典型设备 | 手机、电脑、电视、路由器 | 耳机、手表、键鼠、传感器、门锁 |

简单说，Wi-Fi 是“家里的主干道”，蓝牙是“设备身边的小路”。

## 7.3.2 两套技术，一个名字：经典蓝牙与低功耗蓝牙

今天说的“蓝牙”其实包含两种并不互通的无线技术：

- **经典蓝牙**（Bluetooth Classic，技术规范中称 BR/EDR，即基本速率/增强数据速率）：适合持续传输数据流，传统的蓝牙耳机听音乐、车载免提通话长期依赖它。
- **低功耗蓝牙**（Bluetooth Low Energy，简称 BLE 或 LE）：在蓝牙 4.0 规范中引入，设计重点是“大部分时间睡觉，偶尔醒来发一点数据”。手环、体重秤、蓝牙标签、很多智能家居传感器都用它。

手机里的蓝牙芯片通常两种都支持，所以用户看到的只是一个开关；但一个只支持 BLE 的小传感器，无法和只支持经典蓝牙的老设备直接通信。

BLE 省电的关键思路，与前面讲的 Wi-Fi 6 目标唤醒时间颇为相似：**让无线电尽量少开**。BLE 设备连接后会约定一个“连接间隔”，双方只在约定的时间点醒来交换数据，其余时间关闭射频。手表一周一充、纽扣电池供电的传感器能用很久，都得益于这种“定时碰头”的工作方式。至于具体能用多久，取决于数据量、间隔设置和电池容量，没有统一数字。

## 7.3.3 在拥挤的 2.4 GHz 里生存：跳频与信道

蓝牙和 2.4 GHz 的 Wi-Fi、微波炉挤在同一个免许可频段里，它的应对办法是**跳频**（FHSS，跳频扩频）：不在一个频率上久留，而是按双方约定的序列在许多窄信道之间快速切换。

- 经典蓝牙把频段划分为 79 个 1 MHz 宽的信道。
- BLE 划分为 40 个 2 MHz 宽的信道，其中 3 个是**广播信道**，专门用来让设备“喊一声我在这里”；其余 37 个是数据信道。

从蓝牙 1.2 起引入的**自适应跳频**（AFH）更进一步：设备会发现哪些信道干扰严重——例如正好和某个 Wi-Fi 信道重叠——然后把它们从跳频序列中剔除。这就像在拥挤的走廊里，人不会一直站着等，而是挑人少的地方走。这也解释了为什么 Wi-Fi 和蓝牙能在同一部手机里共存：一方面靠频率上的回避，另一方面手机内部的芯片通常还有协调机制，避免两者同时抢占天线。

## 7.3.4 发现与配对：耳机怎样“认出”你的手机

把新耳机第一次连到手机，背后大致分三步，可以与第三章 Wi-Fi 的“发现—关联—安全”对照着看：

1. **广播**：耳机进入配对模式后，在广播信道上反复发送广播包，里面带有名称和能力信息，相当于 Wi-Fi 的信标帧。
2. **扫描与连接**：手机扫描到后列出设备名，用户点选，双方建立连接。
3. **配对与绑定**：双方协商生成加密密钥，并保存下来（称为“绑定”），下次靠近就能自动重连，不必再操作。

现代蓝牙配对采用基于椭圆曲线密码的“安全简易配对”或 LE 安全连接方式。从防范角度，普通用户值得记住几条：只在需要时让设备进入可被发现的配对模式；配对时如果弹出数字比对，确认两边一致再点确认；不用的旧配对记录及时删除；耳机、手表的固件和手机系统保持更新，因为已知的蓝牙安全问题通常靠更新修复。

BLE 的广播还有一种不连接的用法：设备只是持续广播一小段信息，任何附近的手机都能收到。室内定位信标、物品防丢标签，以及一些手机厂商的“附近设备快速配对”弹窗，都利用了这一机制——后者的具体弹窗体验属于各厂商自己的实现，并非蓝牙标准规定的统一功能。

## 7.3.5 从耳机到物联网：音频与组网的新方向

蓝牙规范仍在演进，写作时有几个值得了解、且已写入 SIG 规范的方向：

- **LE Audio**：让音频也能走低功耗蓝牙，采用新的 LC3 编解码器；其中的 **Auracast** 广播音频允许一个发射端同时向许多耳机或助听器广播声音，设想用于机场、展馆、多人共享收听等场景。实际能否使用，取决于手机和耳机是否都支持，写作时设备支持度仍在逐步扩展。
- **蓝牙 Mesh**：让大量 BLE 设备组成多对多网络，消息可在设备间接力转发，常见于楼宇照明等场景。
- **方向查找与信道探测**：前者利用天线阵列估计信号来向，后者用于更精确地测量距离，服务于室内定位类应用。

需要注意，蓝牙的规范版本号（如 5.0、5.3、5.4）与产品能力不是一一对应的：某个功能在规范中是“可选”的，一台标着新版本号的设备不一定实现了它。购买时应看厂商写明支持的具体功能，而不只看版本数字。

## 7.3.6 小结

蓝牙走的是一条与 Wi-Fi 互补的路线：不追求高速和广覆盖，而是用跳频在拥挤频段里求生存，用“定时醒来”换取超长续航，用配对与绑定让设备之间直接、安全地认识彼此。耳机、手表只是它最显眼的应用，更多蓝牙设备安静地藏在门锁、传感器和各种标签里。智能家居中还有另一类连接技术，同样追求低功耗、并更强调“组网”——这就是下一节要讲的 Zigbee 与 Thread。
