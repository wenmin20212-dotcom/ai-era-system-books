# 7.4 Zigbee、Thread 与智能家居连接

晚上睡前，你对着手机说“关掉客厅的灯”，灯灭了；门窗传感器贴在阳台门上，一节纽扣电池用了一两年还没换；墙上那个温湿度计，你从没给它插过电，也没在路由器后台见过它的名字。打开智能家居 App 添加设备时，说明书上常写着“需要搭配网关”或“需要中枢设备”。这些小设备大多不连 Wi-Fi，它们用的是另一类为“低功耗、小数据、多节点”设计的无线网络。本节介绍其中最常见的两种：Zigbee 和 Thread，以及把它们统一起来的应用标准 Matter。

## 7.4.1 为什么灯泡和传感器不都用 Wi-Fi

Wi-Fi 的设计目标是高速率：看视频、下载文件、视频通话。为此网卡要维持连接、处理较复杂的协议，耗电不低。手机和电脑有大电池或电源，扛得住；一个门磁传感器每天只需报告几次“开了”“关了”，每次几十个字节，若也用 Wi-Fi，电池可能很快耗尽。另外，家里如果有几十个传感器和灯都直接连路由器，也会给接入点增加管理负担。

于是智能家居领域形成了一种分工：

| 需求 | 更合适的连接 |
|---|---|
| 摄像头、电视、音箱等大流量设备 | Wi-Fi |
| 耳机、手表、手机配件 | 蓝牙 / 低功耗蓝牙（见 7.3 节） |
| 灯、开关、门磁、温湿度等大量小设备 | Zigbee、Thread 等低功耗网状网络 |

## 7.4.2 共同的地基：IEEE 802.15.4

Zigbee 和 Thread 的物理层与 MAC 层都建立在同一个标准上：IEEE 802.15.4，一种低速率无线个域网（LR-WPAN，Low-Rate Wireless Personal Area Network）标准。它在全球通用的 2.4 GHz 频段中最常用，单个信道带宽约 2 MHz，原始数据率为 250 kbit/s——这是标准规定的理论值，约为 Wi-Fi 速率的几百分之一到几千分之一，但对“开灯”“报温度”绰绰有余。

802.15.4 的省电之道，在于大部分时间让设备“睡着”。电池供电的传感器平时关闭射频，只在需要上报或定时醒来时短暂收发，这和 6.5 节讲的 Wi-Fi 目标唤醒时间思路相通：通信越稀疏，越能省电。

需要注意，它和 Wi-Fi、蓝牙同处 2.4 GHz，信道可能重叠。有经验的用户会让 Zigbee 信道避开 Wi-Fi 常用的 1、6、11 信道所覆盖的范围，以减少相互干扰——这正是 8.5 节将讨论的免许可频谱“共享的代价”。

## 7.4.3 网状网络：一个传一个地把消息送到

Zigbee 和 Thread 的另一个共同点是网状网络（Mesh）。在这里，“Mesh”与 2.4 节 Wi-Fi Mesh 路由器的思路类似，但规模更细：每一个插电的设备（如灯泡、插座、墙壁开关）都可以充当路由节点，替别人转发消息；电池供电的传感器则通常作为“终端设备”，只挂靠在附近某个路由节点上。

可以把它想象成一屋子人传纸条：卧室的门磁离网关太远，就把纸条交给走廊的灯泡，灯泡再交给客厅的插座，最终送到网关。由此带来两个实用推论：

- **插电设备越多，网络往往越稳**，因为可转发的路径多了；
- **某个节点断电后，网络可以绕路**，但若关键路由节点被墙壁开关物理断电，远处设备可能暂时掉线。

## 7.4.4 Zigbee 与 Thread 的区别：要不要说“IP 语言”

两者地基相同，上层思路却不同：

| 方面 | Zigbee | Thread |
|---|---|---|
| 维护组织 | 连接标准联盟（CSA，原 Zigbee 联盟） | Thread Group |
| 网络层 | 自有网络协议，不使用 IP | 基于 IPv6（经 6LoWPAN 压缩适配） |
| 接入互联网 | 需要网关做协议“翻译” | 通过边界路由器转发 IP 包 |
| 中心节点 | 通常有一个协调器 | 可有多个边界路由器，无单点依赖的设计 |

Zigbee 出现较早，在智能照明、传感器等领域应用广泛；但由于不使用 IP，设备要靠网关把 Zigbee 消息翻译成家里网络能理解的数据，不同厂商的网关和设备之间常存在兼容问题。

Thread 则让每个小设备都拥有 IPv6 地址，直接“说互联网的语言”。家里的边界路由器（Border Router）把 Thread 网络和 Wi-Fi/以太网连起来，就像 4.2 节中路由器把 Wi-Fi 和互联网连起来一样。写作时，一些智能音箱、电视盒子和家居中枢内置了 Thread 边界路由器功能，具体型号以厂商官方说明为准。

## 7.4.5 Matter：让不同品牌说同一种“应用语言”

即使底层都能联网，A 品牌的 App 也未必能控制 B 品牌的灯。为此，CSA 联合多家企业推出了应用层标准 Matter。它规定“开关”“灯光亮度”“温度”等设备功能的统一描述方式，可以运行在 Wi-Fi、Thread 和以太网之上，配网时常借助低功耗蓝牙。于是可以这样理解分层：Thread 或 Wi-Fi 负责“把话送到”，Matter 负责“让双方听懂”。

需要提醒的是，Matter 仍在演进，各平台对设备类型的支持程度不一，一些厂商的特色功能也不一定通过 Matter 提供。选购时应查看设备是否标注 Matter 认证，以及你所用的平台是否支持该类设备。

## 7.4.6 小结

Zigbee 与 Thread 用低速率、低功耗和网状转发，解决了“家里几十个小设备怎样省电又可靠地连起来”的问题；Matter 在其上统一了应用语言。它们和 Wi-Fi 不是替代关系，而是按需分工。可是设备一多，网络出问题时怎样判断是信号、信道还是干扰？下一节我们就拿起工具，学习测量与排障。
