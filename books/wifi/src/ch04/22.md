# 4.2 Wi-Fi 与以太网、互联网的衔接

打开手机浏览器，输入一个网址，一秒钟后页面出现。这一秒里，你的请求先以电磁波的形式穿过客厅，钻进路由器，再顺着一根网线进入光猫，变成光脉冲沿光纤离开你家。上一节我们把 802.11 拆成物理层和 MAC 层，看清了无线链路自身的结构。可无线链路的终点并不在路由器的天线上，它要接到有线世界里去。一段在空中传输的 Wi-Fi 数据，怎样无缝变成网线里的以太网数据，再进入互联网？

## 4.2.1 同一个“地址体系”：为什么 Wi-Fi 能接上以太网

以太网（Ethernet）是有线局域网的标准，对应 IEEE 802.3；Wi-Fi 对应 IEEE 802.11。两者同属 IEEE 802 家族，这层“亲缘关系”是衔接能够顺畅的根本原因。

最关键的共同点是 **MAC 地址**（Media Access Control Address，介质访问控制地址）。无论是手机的无线网卡还是电脑的有线网口，出厂时都有一个 48 位的地址，格式完全相同，常写成 `3C:22:FB:xx:xx:xx` 这样六组十六进制数。因为地址格式统一，交换机和路由器在转发时就不必关心一个设备是“插线的”还是“无线的”，只看地址即可。

另一个共同点是它们承载上层数据的方式相同。以太网和 Wi-Fi 都在帧里用一个标识说明“里面装的是什么”，例如 IPv4 或 IPv6 数据包。上层的 IP 协议看到的，是一条统一的“二层链路”，至于这条链路是铜线还是空气，它并不在乎。

可以打个比方：以太网和 Wi-Fi 像两种不同的交通工具，一个是火车，一个是轮渡，但乘客的身份证（MAC 地址）和行李标签（上层协议标识）全国通用，换乘时不需要重新办证。

## 4.2.2 接入点做的事：“翻译”帧格式

虽然地址体系一致，两种帧的“外包装”却不同。以太网帧只需要两个地址：目的地址和源地址，因为网线两端是确定的。Wi-Fi 帧通常带三个甚至四个地址，原因在于空中多了一个“中转站”——接入点（Access Point，AP）。

| 对比项 | 以太网帧（802.3） | Wi-Fi 数据帧（802.11） |
|---|---|---|
| 地址字段 | 2 个：目的、源 | 通常 3 个，无线桥接等场景用 4 个 |
| 确认机制 | 无逐帧确认，依赖线路可靠 | 每个单播帧需对方回 ACK 确认 |
| 帧头附加信息 | 简单 | 含功率管理、重传、加密等控制位 |
| 加密 | 链路层一般不加密 | 通常由 WPA2/WPA3 加密 |

当手机发出一个数据帧时，三个地址分别表示：接收者（AP）、发送者（手机）、最终目的地（例如路由器的网关接口）。AP 收到后，校验、解密，去掉 802.11 帧头，换成以太网帧头，只保留源地址和目的地址，再送进有线网络。反方向的过程正好相反。这个转换由 IEEE 802.11 标准定义的“分布式系统”（Distribution System，DS）概念来描述：AP 把无线一侧和有线一侧桥接起来，在二层上让它们看起来像同一个局域网。

所以，AP 本质上是一座 **网桥**（Bridge）：它不改变 IP 地址，也不做路由决策，只负责换包装、转发帧。

## 4.2.3 家用路由器里的三段路程

家里那台“无线路由器”通常把几种设备装进了一个盒子（第二章 2.2 节已拆解过）。从衔接的角度看，一个网页请求要经过三段：

1. **无线到交换**：手机的 802.11 帧在 AP 模块里被转换成以太网帧，进入路由器内部的交换芯片。此时它与插在 LAN 口上的台式机已处在同一个局域网，彼此可以直接通信，比如手机投屏到同一网络里的电视。
2. **局域网到广域网**：要访问外网，帧被交给路由模块。这里发生了第三层的动作：路由器查看 IP 地址，把它从内网地址（如 192.168.x.x 这类私有地址）通过 **NAT**（Network Address Translation，网络地址转换）换成运营商分给你的地址。家里十几台设备共用一个对外地址，靠的就是它。
3. **出户到运营商**：数据从路由器的 WAN 口沿网线进入光猫，光猫把电信号转换成光信号，送入运营商的光纤接入网。之后的旅程属于互联网骨干和光纤通信的范畴，分别在本系列第二十五册《互联网》和光纤通信专册中展开。

此外，手机连上 Wi-Fi 后能自动获得地址，靠的是路由器上运行的 **DHCP**（Dynamic Host Configuration Protocol，动态主机配置协议）服务；输入网址能找到服务器，靠的是 **DNS**（Domain Name System，域名系统）。这些都是 IP 层及以上的服务，无论设备用 Wi-Fi 还是网线，过程完全相同——这正说明 Wi-Fi 只替换了“最后几米”的链路，上层一概不变。

## 4.2.4 衔接处的瓶颈：为什么“满格”也可能慢

理解了衔接结构，就能看懂一些常见现象。网速是整条路上最窄的一段决定的，就像水管串联，流量取决于最细的那节。

- **有线口拖后腿**：如果路由器或光猫的网口只支持百兆以太网（100 Mbit/s），即使 Wi-Fi 协商速率显示几百兆以上，实际上网也会被卡在百兆以下。很多家庭升级宽带后测速不达标，原因就在这里，值得检查网口和网线规格。
- **无线段损耗**：Wi-Fi 界面上显示的“连接速率”是物理层速率，扣除竞争、确认帧和帧头开销后，实际吞吐量通常明显低于这个数字，常见说法是只有其一半左右甚至更低，具体取决于环境。
- **运营商带宽**：家庭宽带的签约速率是出户段的上限，局域网内部再快也无法突破它。

因此排查慢的问题时，可以分段测试：同一设备插网线测速与连 Wi-Fi 测速相比，差距大说明问题在无线段；两者都慢，就要往有线侧和宽带上找。第七章 7.5 节会系统介绍这类方法。

## 4.2.5 小结：一条换了包装的连续链路

Wi-Fi 之所以能成为“看不见的网线”，是因为它从设计之初就站在 IEEE 802 家族的统一框架里：共用 MAC 地址体系，向上为 IP 提供同样的服务。接入点负责在两种帧格式之间换包装，路由器负责在局域网和互联网之间转换地址，光猫负责在电和光之间转换信号。每一处转换都只改动一层，其余各层保持不变，这正是分层设计的价值。
