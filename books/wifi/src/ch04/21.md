# 4.1 协议分层：802.11 的物理层与 MAC 层

打开手机的 Wi-Fi 详情页，你可能会看到这样几行信息：“Wi-Fi 6”“5 GHz”“链接速率 864 Mbps”“IP 地址 192.168.1.23”，有时还有一串“MAC 地址”。这几行字看上去互不相干，其实它们分属网络的不同“层”。频段和链接速率说的是信号怎样在空中传，MAC 地址说的是这一帧数据交给谁，IP 地址则属于更上层的互联网。把 Wi-Fi 放回分层的框架中，就能看清 IEEE 802.11 标准管的是哪一段，又把哪些事交给了别人。

## 4.1.1 为什么要分层：一封快递的分工

寄一个包裹，你只管写清收件人、封好箱子。快递员关心的是这一站交给哪个网点，运输车队关心的是走哪条公路、车况如何。每一方只处理自己那一段，靠约定好的“交接格式”衔接。如果某天公路换成了铁路，寄件人完全不必知道。

网络协议的分层（Layering）是同一个思路。每一层只对上一层提供服务，只依赖下一层的服务，层与层之间用接口交接。常用的参考框架是 OSI 七层模型（开放系统互连参考模型），互联网实际使用的是更简化的 TCP/IP 分层，这部分在本系列第二十五册《互联网》中有专门讲解。对 Wi-Fi 来说，最重要的结论只有一句：**IEEE 802.11 只定义最底下两层——物理层和数据链路层中的 MAC 子层。**

| 层次 | 主要负责 | Wi-Fi 场景中的例子 | 谁来定义 |
|---|---|---|---|
| 应用层 | 具体应用的规则 | 网页、视频、微信消息 | 各应用协议 |
| 传输层 | 端到端可靠传输 | TCP、UDP | IETF |
| 网络层 | 跨网络寻址与路由 | IP 地址 | IETF |
| 数据链路层（LLC 子层） | 向上层统一接口 | 区分承载的是 IP 还是其他协议 | IEEE 802.2 等 |
| 数据链路层（MAC 子层） | 谁在什么时候用信道、帧发给谁 | MAC 地址、确认与重传 | **IEEE 802.11** |
| 物理层 | 比特怎样变成电磁波 | 频段、信道宽度、调制、链接速率 | **IEEE 802.11** |

这样一来，手机里的浏览器根本不必知道自己是通过 Wi-Fi、网线还是 5G 上网；只要底层能把 IP 包送到下一站，上层就照常工作。“看不见的网线”之所以能替代真正的网线，正是因为它向上提供了几乎相同的接口。

## 4.1.2 物理层：把比特变成空中的波

物理层（Physical Layer，简称 PHY）回答的问题是：一串 0 和 1 怎样变成天线发出的电磁波，对方又怎样把它还原。它要规定的内容包括：

- **工作频段与信道**：在 2.4 GHz、5 GHz 或 6 GHz 的哪一段，信道宽 20、40、80、160 MHz 还是更宽；
- **调制与编码**：每个“符号”携带几个比特，加多少纠错冗余（第六章细讲）；
- **多天线方式**：是否使用 MIMO，同时传几路数据流；
- **帧的“包装”**：每个无线帧前面都有一段前导码（Preamble），让接收方先“对准频率、校准时钟”，再读后面的内容。

802.11 物理层内部还常再分成两部分：一部分负责把上层交下来的帧加上前导码和物理层头部，另一部分直接和射频、天线打交道。你在设置页看到的“链接速率”，就是物理层当前选定的调制编码与信道宽度组合所对应的速率，它会随距离和干扰不断变化，而且是空口上的理论传输速率，不等于你测速时得到的实际吞吐量。

每一代 Wi-Fi 的“代际差异”大多集中在物理层：802.11b 用的是直接序列扩频，802.11a/g 引入正交频分复用（OFDM），802.11n 加入 MIMO，802.11ac 把信道加宽到 160 MHz，802.11ax（Wi-Fi 6）引入 OFDMA，802.11be（Wi-Fi 7）进一步支持 320 MHz 信道和更高阶调制。物理层变了，上层却不必跟着改，这就是分层的价值。

## 4.1.3 MAC 层：在共享的空气里维持秩序

如果说物理层解决“怎么说话”，那么 MAC 层（Medium Access Control，介质访问控制）解决的是“谁先说、说给谁、对方听清没有”。空气是所有设备共享的介质，不像网线那样一根线一对设备，因此 Wi-Fi 的 MAC 层比有线以太网复杂得多。它的主要职责有：

1. **信道接入**：用 CSMA/CA（载波侦听多路访问/冲突避免）让设备先听后说、随机退避，避免同时开口（详见 6.1 节）；
2. **寻址**：每个帧头里写明 MAC 地址。Wi-Fi 数据帧通常带三个甚至四个地址字段，因为除了“谁发、谁收”，还要写明经过哪个接入点；
3. **确认与重传**：无线链路容易出错，所以接收方收到单播数据帧后要回一个确认帧（ACK），没收到确认就重传（3.3 节已介绍）；
4. **管理功能**：信标、扫描、认证、关联、节能休眠、加密等，都由 MAC 层定义的管理帧和流程完成；
5. **分段与聚合**：把大块数据切小或把多个小帧打包，以适应空口状况、提高效率。

这里顺带说明一下手机设置里的“MAC 地址”。它是数据链路层使用的 48 位硬件地址，只在同一个局域网内有意义，出了路由器就不再出现。截至本书写作时，主流手机和电脑系统普遍提供“随机 MAC 地址”或“私有地址”选项，连接不同网络时使用不同地址，以减少设备被跨场所追踪。这是操作系统层面的隐私做法，并非 802.11 强制规定的行为。

## 4.1.4 上下两层怎样配合：一次发送的分工

把两层放在一起看一次发送过程：浏览器产生的请求经过 TCP、IP 层层封装，变成一个 IP 包，交给网卡。MAC 层给它加上 802.11 帧头（地址、序号、控制字段）和校验码，然后等待信道空闲、完成退避；轮到自己时，交给物理层。物理层根据当前信号质量选定调制编码方式，加上前导码，变成电磁波从天线发出。接收端反向拆包：物理层还原比特，MAC 层核对校验码和目的地址，回复确认，再把里面的 IP 包交给上层。

两层之间并非完全隔绝。MAC 层要依靠物理层报告“信道是否忙”，物理层的速率选择也要参考 MAC 层统计的重传次数。工程上这种跨层协作很常见，但责任边界依然清楚：**物理层对“比特能否送达”负责，MAC 层对“帧能否有序、可靠地交到相邻设备”负责。**

## 4.1.5 小结：Wi-Fi 只是“最后一段路”

分层视角让我们看清 Wi-Fi 的位置：它只负责从你的设备到接入点之间这一跳，管的是物理层和 MAC 层两层。再往上的 IP 地址、域名、网页，都是互联网协议的工作；再往外，帧要换成以太网格式，沿着网线、光猫进入运营商网络。Wi-Fi 帧怎样在路由器里“改头换面”接上以太网和互联网，正是下一节要讲的内容。
