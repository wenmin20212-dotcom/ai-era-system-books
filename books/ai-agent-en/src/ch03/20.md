# 3.6 Chapter Skeleton Summary and Hands-On Exploration Tasks

Remember the task we handed the agent at the start of this chapter? "Combine the data from these three sales reports into a single table, find the region with the fastest growth, and write me a short explanation." In Chapter 2, we took it apart into its components: the model, instructions, tools, memory, the runtime environment, and the orchestration program. This chapter asked a different question: what does each of these components actually do? We saw that completing this job is not a single action but a relay among five functions. The agent first understands the task and the files, then lays out the steps, then carries them out, checks the results, and pauses to ask you whenever it is unsure. Below, we first pull this relay chain together into a framework, and then invite you to test it on a real agent within your reach.

## 3.6.1 Five Functions: A Relay Chain

| Function | Question It Answers | What It Looks Like in the Report Task | Main Components Relied On |
|---|---|---|---|
| Perception | What am I dealing with right now? | Reads the three spreadsheets, identifying column names, units, and missing values | The model's comprehension, file-reading tools, multimodal input |
| Planning | What comes first, and what comes next? | First standardize the formats, then merge, then calculate growth rates, and finally write the explanation | Model reasoning, system prompt, task list |
| Execution | How do I actually get this step done? | Calls a spreadsheet tool or writes a piece of code to perform the calculation | Tools and function calling, code runtime environment |
| Reflection and Error Correction | Did I get it right? If not, what now? | Notices an abnormal figure for one region, traces it back, and finds inconsistent units | Results returned by tools, error messages, verification steps |
| Collaboration with Humans | Where does a person need to decide? | Asks whether "growth" should be measured in absolute amounts or percentages; asks you to confirm before sending | Chat interface, permission settings, human confirmation mechanisms |

There are three points worth remembering about these five functions.

- **Perception is not just "seeing" but also "understanding."** Reading a file's contents in is only the first step; only when the agent can tell which column holds amounts and which row is the total has it truly perceived the task at hand. The same goes for web pages, screenshots, and on-screen interfaces: the messier the information, the more likely perception is to go wrong.
- **Planning and execution alternate.** An agent rarely writes out a complete plan once and then follows it to the end. More often, it takes a step, looks at the result, and adjusts the next step based on what the tool returned. When Chapter 6 covers the "reasoning–action loop," we will break this rhythm down in detail.
- **Reflection and collaboration are the two quality gates.** Reflection relies on the agent checking its results against the goal on its own, while collaboration hands key judgments back to a person. The former reduces careless mistakes, but a model can be "confidently wrong," so for irreversible operations such as deleting, paying, or sending things externally, the second gate cannot be skipped.

## 3.6.2 Mapping Functions to Components: An Easy Point of Confusion

Chapter 2 was about "what it is made of"; this chapter is about "what it does." The two do not map one-to-one. The same large language model takes part in perception, handles planning, and also judges whether results are correct; the same tool can be used both for execution and for checking, for example by rerunning a calculation to verify the totals. Viewing functions and components separately has a practical benefit: when an agent runs into trouble, you can first ask "which function went wrong?" and then ask "which component caused it?" For instance, if a result was miscalculated, the units may have been misread during perception, or the code may have been written incorrectly during execution, and the fixes for these two cases are completely different.

## 3.6.3 Common Failures of the Five Functions

| Function | Typical Failure | How You Can Spot It |
|---|---|---|
| Perception | Missing part of a file; misunderstanding vague wording in the task | Have it restate the task and summarize the data first |
| Planning | Omitting steps, or breaking a simple task into overly fine pieces | Ask it to list a plan before it starts working |
| Execution | Wrong tool parameters; code throwing errors when run | Review the execution log and error messages |
| Reflection and Error Correction | Declaring the job done without checking; repeatedly retrying the same failed approach | Follow up with "How did you verify this result?" |
| Collaboration with Humans | Not asking when it should, and asking repeatedly when it shouldn't | Watch where it stops to ask for your confirmation |

This table is not saying that agents are unreliable. It is a reminder that each of their capabilities has limits, and only by seeing those limits clearly can you use them with confidence.

## 3.6.4 Hands-On Exploration Tasks

Choose any agent-style product you have access to for the tasks below, such as an AI assistant with file analysis or web search features, a coding agent, or the AI features in office software. Interfaces and capabilities vary widely across products and change quickly, so go by what you actually see when you use it. Do not upload files containing personal private information or company confidential data.

1. **Perception test.** Prepare a small spreadsheet containing one obvious error, for example one row where the unit is written as "ten thousand yuan" while all the others are "yuan." Just ask it to "summarize this," without hinting that there is an error, and see whether it spots the problem on its own.
2. **Planning observation.** Give it a task that takes three or more steps to complete, and first ask it to "only list the plan, do not execute." Write down the plan, then have it execute, and compare where the actual steps differ from the plan.
3. **Execution tracing.** If the product shows its execution process, such as which tools it called or what code it ran, copy these steps down one by one and label each with which of the five functions it belongs to.
4. **Error-correction experiment.** Deliberately give an ambiguous or self-contradictory instruction, such as "sort by date, but put the newest last, and also first," and see whether it picks one interpretation on its own or stops to ask you.
5. **Collaboration boundaries.** Look through the product's settings page for permission options such as "confirm before executing" or "allow access to files or the network," and note whether each is on or off by default.

## 3.6.5 Questions You Can Ask an AI Directly

- "Please reorganize the process you just used to complete the task into five stages: perception, planning, execution, checking, and confirming with me, and point out which step is most error-prone."
- "In what situations should an agent stop and ask a person rather than keep going on its own? Please give three examples from everyday life or work."
- "What are the respective limitations of an agent checking its own results versus a person checking an agent's results?"

At this point, we have a clear view of how the parts inside an agent divide up the work. But an agent does not work behind closed doors: it has to connect to tools, tap into knowledge bases, divide labor with other agents, and hand off to people.
