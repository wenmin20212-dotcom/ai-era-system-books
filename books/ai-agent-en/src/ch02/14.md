# 2.6 Chapter Skeleton Summary and Hands-On Exploration Tasks

Let's return to the task from Chapter 1: you asked an agent to organize dozens of quotations in a folder into a single comparison table. On screen, you typed one sentence and, a little later, received a table. Having read this chapter, you should be able to see past this "one sentence in, one table out" shell to the six parts running inside it at the same time: a model that does the thinking, several layers of instructions that constrain it, a set of tools that act on its behalf, several kinds of memory operating on different time scales, a runtime environment that limits where it can operate, and an orchestration program that ties all of this together and drives it repeatedly. This section first condenses that skeleton into key points and a comparison table, then asks you to check each part against a real agent you have on hand.

## 2.6.1 Chapter Skeleton Review

- **The brain: the Large Language Model (LLM).** It takes in a passage of text and predicts and generates the text that comes next. Understanding the task, choosing the next step, and writing tool-call requests all rely on this ability. The model itself cannot open files or go online; it can only "say" what it wants to do. For how models work internally, see Volume 18, *Large Language Models*.
- **Instructions: the System Prompt, role definition, and task description.** The system prompt is written in advance by the developer and specifies identity, rules, and off-limits areas. The task description comes from the user and tells it what to do this time. Layered together, the two determine the angle from which the model understands your sentence.
- **The hands: tools, functions, and external services.** Reading files, searching the web, running code, and calling a service's Application Programming Interface (API) are all registered with the model in the form of "name + description + parameter format." The model issues a call request, the program actually executes it, and the result is handed back to the model.
- **Memory: short-term context, long-term memory, and knowledge bases.** The Context Window is everything the model can "see" at this moment, and its capacity is limited. Long-term memory preserves preferences and experience across conversations. A knowledge base is external material that can be retrieved on demand. The three differ in how long they persist, who writes to them, and how they are accessed.
- **The runtime environment and the orchestration program.** The runtime environment determines where the agent operates, such as a browser, a cloud virtual machine, or your own computer, and also which files and networks it can reach. The Orchestrator drives the loop: it calls the model, parses the reply, executes tools, writes the results back into the context, and hands things back to the model to decide the next step, until the task is complete or human confirmation is needed.

Placing the six parts side by side gives the following comparison table:

| Component | Analogy | Provided by | What happens without it |
|---|---|---|---|
| Model | Brain | Model vendor | Cannot understand tasks or make decisions |
| Instructions | Job description | Developers and users | Behavior has no boundaries; goals are vague |
| Tools | Hands | Developers, third-party services | Can only talk, not act |
| Memory | Notebook and filing cabinet | Orchestration program and storage systems | Forgets earlier steps halfway through |
| Runtime environment | Workstation | Platform or the user's own device | Nowhere to operate, or lacks isolation |
| Orchestration program | Project manager | Agent product or framework | The parts cannot be linked into a loop |

The most important point to remember: **an agent's capability does not depend on the model alone; it is the result of these six parts working together.** The same model, paired with different tools, instructions, and environments, can perform very differently. Each of the following chapters will start from this skeleton to discuss what each part does, how the parts connect to one another, and the information that flows among them.

## 2.6.2 Hands-On Exploration Tasks

None of the following tasks require programming. You can complete them with any agent product you currently use, such as a chat assistant with web search, a coding agent, or an AI assistant in office software. Product interfaces change frequently, so go by what you see when you open it.

1. **Find the "brain."** Check in the settings or a corner of the interface which model is currently in use and whether it can be switched. After switching, give it the same small task twice and record the differences in the number of steps and the wording of the results.
2. **Take inventory of the "hands."** Watch for the prompts it displays while working, such as "Searching," "Reading file," or "Running code." List the tools you see and note roughly what each one is responsible for.
3. **Test the boundaries of memory.** At the start of a long conversation, tell it a detail, such as "express all amounts in the table in units of ten thousand yuan." After twenty or thirty turns, ask it to produce the table and see whether it still remembers. Then open a new conversation and ask the same question to get a feel for the difference between short-term context and long-term memory.
4. **Observe the runtime environment.** Have it generate a file or run a piece of code, then think: where is this file stored—on your computer, in the cloud, or in a temporary space that disappears when you close the page? Can it access other files on your computer?
5. **Draw your own skeleton diagram.** Pick a task you have actually handed to an agent, and for each of the six parts in this chapter, write a sentence or two explaining what it did during that task. Keep this diagram and bring it out again to expand on in Chapter 5, when we discuss "flow."

## 2.6.3 Questions You Can Ask an AI Directly

- "Please use a table to explain which tools you can use in this conversation, what the input and output of each tool are, and which operations require my confirmation."
- "If my conversation gets very long and exceeds your context window, what happens to the earlier content? Please explain based on how your product handles it, and tell me directly where you are unsure."
- "Please map each of the six parts—model, instructions, tools, memory, runtime environment, and orchestration program—to what they correspond to in you, and point out which parts you cannot see yourself and can only infer."

The third question may not get a complete answer. Agents often do not know the details of their own system prompts and orchestration, and their answers are themselves material you need to verify. Having untangled "what it is made of," the next chapter turns to "what each part does": perception, planning, execution, reflection, and collaboration are precisely the functions these six parts exhibit when in operation.
