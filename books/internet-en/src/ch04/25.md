# 4.5 Chapter Skeleton Summary and Hands-On Exploration Tasks

In the first three chapters we kept answering "what is there" and "what does it do": phones, optical network terminals, backbone networks, submarine cables, servers, and functions such as addressing, naming, routing, and reliable delivery. Chapter 4 took a different angle and asked "how are they related to one another." A single web request is divided into layers of responsibility in the layered model, handed along segment by segment between carriers, and exchanged back and forth as questions and answers between client and server, while behind it a whole system of rules and institutions keeps things in order. This section first pulls these four kinds of relationships together into a single skeleton, then invites you to find them for yourself on your own devices.

## 4.5.1 Chapter Skeleton Review: Four Kinds of "Relationships"

### 4.5.1.1 Vertical Relationships: The Layered Model

- The TCP/IP model divides network communication into four layers: the link layer, the network layer, the transport layer, and the application layer. The OSI (Open Systems Interconnection) model divides it into seven layers and serves mainly as a reference for teaching and discussion.
- Each layer serves only the layer above it and depends only on the interface of the layer below it. As data travels down from the top, each layer "puts it in an envelope," which is called encapsulation; when it reaches the other end, each layer "opens the envelope" in turn, which is called decapsulation.
- The point of layering is that each layer can be replaced independently. Switching from Wi-Fi to an Ethernet cable, or from IPv4 to IPv6, requires no change to the web page itself.

### 4.5.1.2 Horizontal Relationships: Interconnection of Autonomous Systems

- The internet is made up of tens of thousands of autonomous systems (AS). Each AS is managed by one or more operators, applies a unified routing policy to the outside world, and holds a globally unique AS number.
- There are two basic business relationships between ASes. "Transit" means paying to buy reachability to the entire internet; "peering" means two parties exchange traffic for their respective users, usually without paying each other. An Internet Exchange Point (IXP) is a place where peering is concentrated.
- These relationships determine which path a packet actually takes. The real path is often decided by contracts and policies, and the route with the shortest physical distance is not necessarily the one chosen.

### 4.5.1.3 Role Relationships: Client, Server, Peer-to-Peer, and Edge

- Browsing the web is a typical client–server pattern: the browser initiates a request, and the server responds.
- In the peer-to-peer (P2P) pattern, every node is both a requester and a provider; it is common in some file distribution and real-time audio/video scenarios.
- Edge computing places computation and caching closer to users to shorten round-trip time and relieve pressure on central nodes. In real systems, these three patterns are often used in combination.

### 4.5.1.4 Institutional Relationships: Internet Governance

- Standards: The IETF (Internet Engineering Task Force) publishes protocol standards as RFC documents, while web-related standards are advanced mainly by organizations such as the W3C (World Wide Web Consortium) and WHATWG.
- Resources: The IANA (Internet Assigned Numbers Authority) functions are currently performed by an affiliate of ICANN (Internet Corporation for Assigned Names and Numbers), which coordinates the allocation of top-level IP address blocks and AS numbers; five Regional Internet Registries (RIRs) then allocate them within their respective regions, with APNIC responsible for the Asia-Pacific. For domain names, each top-level domain is operated by its corresponding registry.
- The internet has no "headquarters"; it runs on multistakeholder collaboration and on everyone's shared adherence to open standards.

To compress the four relationships into one sentence: **between layers, the relationship is one of service; between networks, one of business; between endpoints, one of roles; and between people and the network, one of rules.**

## 4.5.2 Hands-On Exploration Tasks

The following tasks require only a computer or phone. All of them are read-only viewing operations and will not change any settings.

**Task 1: Find the "layers" in your settings** Open the network details page on your phone or computer and locate each of the following: the Wi-Fi name and signal strength (link layer), your device's IP address and gateway (network layer), and the DNS server (naming that serves the application layer). Write them down on paper and mark which layer each belongs to.

**Task 2: Find out which AS your carrier is** Use a search engine to find a public "IP ownership/ASN lookup" website and check the AS number and organization name of your current public egress address. Then check once on home broadband and once on mobile data, and compare whether the results are the same.

**Task 3: Use traceroute to watch the "border crossings"** On the Windows command line, type `tracert` followed by the domain name of a website you often use; on macOS or Linux, use `traceroute`. Observe the addresses of the nodes along the way, then pick a few and look up their ownership using the method from Task 2, marking where the path passes from one AS into another. It is normal for some nodes to show asterisks; this usually means the device is configured not to respond to probes.

**Task 4: Count the "servers" behind a web page** In a desktop browser, press F12 to open the developer tools, switch to the Network panel, and refresh the page. Count how many different domain names these requests come from, and note which of them look like image, script, or content delivery network nodes. You will find that a single web page is usually backed by more than one server.

**Task 5: Look up a domain's "household registration"** Find a public WHOIS or RDAP (Registration Data Access Protocol) lookup page, query the domain of a website you use often, and look at its registrar, registration date, and name servers. Note that, for privacy protection, some registrant information may be hidden.

## 4.5.3 Questions You Can Ask an AI Directly

1. "Here are my traceroute results (text attached). Please help me determine roughly which carriers or autonomous systems the path passes through, and where cross-network interconnection points might be. Please explain the basis for your judgment and mark which parts are uncertain."
2. "Using the analogy of sending a parcel, explain what 'envelope' is added to an HTTPS web request at each of the four TCP/IP layers, and what information is written on each layer's envelope."
3. "What are the main factors two carriers consider when choosing between peering and buying transit? How does this choice affect the speed at which ordinary users access websites?"

When asking, have the AI distinguish between "widely accepted standard facts" and "the specific practices of a particular carrier or region." Once you have the answers, check them against the real results from the tasks.
