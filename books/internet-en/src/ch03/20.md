# 3.6 Chapter Skeleton Summary and Hands-On Exploration Tasks

After you press Enter, the browser must first know "where to go," then "how to get there," and also make sure the data "arrived, and arrived correctly." Only then comes the question of "how to use what was delivered." The five sections of this chapter answered these four questions in turn, through addressing, naming, forwarding and routing, reliable transport, and application services. These five functions are carried out by the components we took apart in Chapter 2, and together they put a web page on your screen. This section first strings the five functions into a skeleton. Then it asks you to find each of them on your own devices.

## 3.6.1 The Chapter Skeleton: Five Functions, One Thread

Think of visiting a web page as sending a parcel. The five functions map roughly as follows:

| Function | Question It Answers | Core Concepts | Parcel Analogy |
|---|---|---|---|
| Addressing | Which device, and which program, should the data go to | IP address, port number | Delivery address and house number |
| Naming | How does a name people can remember become an address | Domain Name System (DNS), recursive resolution, caching | Looking up the address book |
| Forwarding and routing | Where should each hop go | Routing table, longest prefix match, hop-by-hop forwarding | Sorting centers routing parcels by destination |
| Reliable transport | What if data is lost, what if the network is congested | Sequence numbers, acknowledgments, retransmission, congestion control | Delivery receipts, resending lost parcels, dispatching trucks according to traffic |
| Application services | Once received, how is it understood and used | HTTP, email protocols, instant messaging, video segmentation | The contents of the parcel and its instruction manual |

Several key points stand out about these five functions:

- **Addresses locate; names are easy to remember.** An IP address identifies a device on the network (more precisely, a network interface), and a port number distinguishes the programs running on that device. A domain name is only an "alias" for people's convenience. Before any actual communication, DNS must translate it into an address.
- **A router cares only about the next hop.** No single router knows the complete path. Each router consults only its own routing table and hands the packet to a neighbor that is "one step closer" to the destination. The end-to-end path is assembled from a great many local decisions.
- **The network itself does not guarantee delivery.** The IP layer makes only a best effort, so packets may be lost, reordered, or duplicated. The Transmission Control Protocol (TCP) runs on the hosts at both ends. It adds reliability with sequence numbers, acknowledgments, and retransmission, and it uses congestion control so that many senders slow down on their own when the network is congested.
- **The application determines the experience.** Web pages, email, instant messaging, and video differ in what they need in latency, reliability, and bandwidth, so each uses a different combination of protocols. Video, for example, is sent in short segments, and the player switches resolution to match the network speed.
- **The functions divide the work and depend on one another.** Without addressing, routing is impossible. Without naming, people would find the network hard to use. Without reliable transport, web pages would arrive incomplete. Without application protocols, what you receive is just a string of bytes.

Which "layer" each of these five functions belongs to, and how the layers connect, is the subject of Chapter 4, "Layered Models."

## 3.6.2 Hands-On Exploration Tasks

The following tasks need only a computer or phone and your home network. They involve observing your own devices only, not anyone else's systems.

1. **Find your two addresses.** Open the Wi-Fi details page on your phone or the network settings on your computer. On Windows, type `ipconfig` at the Command Prompt. On macOS, look under "System Settings > Network." Note down your device's IP address and the "router/gateway" address. Then search for "what is my IP" in a search engine and check whether the address shown on the web page matches your device's address. Think about why the two differ. (Hint: your home router performs address translation, which Chapter 5 covers in detail.)
2. **Observe a domain name lookup.** On your computer, run `nslookup` followed by the domain name of a website you use often. See how many addresses are returned and whether they are IPv4 or IPv6. Look it up again a few minutes later, or switch to your phone's mobile data and try again. Compare the results, note whether anything changed, and write it down.
3. **Count the hops along the way.** Use `tracert` on Windows or `traceroute` on macOS, followed by the same domain name. Count how many hops the path takes, note which hops show a clear jump in latency, and see which lines show asterisks. An asterisk usually means that router does not respond to probe packets. It does not necessarily indicate a fault.
4. **See which protocols a web page uses.** Open a website in your computer's browser, press F12 to open the developer tools, switch to the "Network" panel, and refresh the page. Observe how many requests a single page makes, which versions appear in the "Protocol" column (such as h2 or h3), and which resources come from other domains.
5. **Experience congestion control.** Watch a high-definition video on one device at home while another device downloads a large file. Notice whether the video resolution drops automatically or buffering increases, and how long it takes to recover after the download stops. Explain what you see using this chapter's sections on "Reliable Transport" and "Application Services."

Record your results on a single sheet of paper in five columns: "Address – Name – Path – Transport – Application." This is your home network's first "function profile."

## 3.6.3 Questions You Can Ask AI Directly

Before you paste the output of the tasks above into an AI tool, delete your public IP address and any other information that might affect your privacy. Then ask:

- "Here is the traceroute output from my computer. Please explain each line: roughly where each hop is located (at home, at the ISP, or on the destination's network), which hops show latency changes worth noting, and what the asterisks mean."
- "For the same domain name, nslookup returns different addresses on my home broadband and on my phone's mobile data. What could explain this? How does it relate to content delivery networks?"
- "Using an analogy a middle school student could understand, explain the differences among IP addresses, port numbers, and domain names, and then point out where the analogy falls short."

AI answers may contain mistakes. For any key conclusion, check it against this chapter or verify it in the relevant RFC documents.
