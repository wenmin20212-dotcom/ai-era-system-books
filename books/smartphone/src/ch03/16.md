# 3.5 核心微型模块系统职能全景对照

前面四节，我们沿着计算、成像、射频、触觉与声学几条线索，把手机里的微型模块逐一认识了一遍。现在不妨把它们放回同一部机器里看。你手中这部手机，在点亮屏幕的那一刻，并不是某一颗芯片在单独工作，而是十几个子系统同时上岗。本节用一张全景对照表把它们的职责、衡量指标和背后的厂商整理到一起，再用一个小场景演示它们如何在毫秒之间交接任务。

## 3.5.1 一张表看清“谁干什么”

下表按功能子系统划分，每一行回答四个问题：硬件实体是什么，它承担什么任务，用什么指标衡量好坏，主要由哪些企业设计或制造。

| 功能子系统 | 核心硬件实体 | 承担任务与功能本质 | 关键性能指标 | 代表性半导体与制造企业 |
|---|---|---|---|---|
| 通用调度与计算 | CPU 大中小核集群 | 复杂逻辑判断、系统响应与多线程调度 | 单核/多核 IPC、最高主频（GHz） | ARM、高通、苹果、联发科 |
| 图形渲染与显示 | 移动 GPU 核心 | 3D 游戏顶点变换、着色器运算与 UI 帧合成 | 浮点算力（TFLOPS）、每瓦性能 | 高通 Adreno、ARM Immortalis |
| 端侧 AI 推理 | 专用 NPU 矩阵单元 | 本地大模型、计算机视觉与语音推理加速 | 稠密算力（TOPS）、量化支持（INT4/8） | 高通 Hexagon、苹果 Neural Engine |
| 成像与光电转换 | CIS 感光芯片 + ISP | 光子捕捉、模数转换、RAW 域计算摄影算法 | 靶面尺寸（如 1 英寸）、动态范围（dB） | 索尼 LYTIA、三星 ISOCELL、豪威 |
| 防抖与变焦机械 | 潜望三棱镜 + 音圈马达 | 毫秒级镜片物理微移，补偿手抖与对焦 | 驱动力、对焦时延（ms）、防抖角度 | 大立光、舜宇光学、阿尔卑斯 |
| 无线微波放大 | 射频 PA 功率放大器 | 将发射信号能量放大数千倍以抵达远端基站 | 输出功率（dBm）、功率附加效率（PAE） | Skyworks、Qorvo、唯捷创芯 |
| 高频信号滤波 | BAW / SAW 滤波器 | 滤除频带外电磁杂波，实现全双工隔离 | 插入损耗（dB）、带外抑制比 | 博通（Broadcom）、村田制作所 |
| 瞬态触觉模拟 | X 轴线性振动马达 | 毫秒级水平定向往复震动，拟真按键反馈 | 稳态加速度（Grms）、启停时延（ms） | 瑞声科技（AAC）、立讯精密 |

## 3.5.2 读表的三把钥匙

这张表信息密集，横着读和竖着读能看到不同的东西。

**第一把钥匙：看“功能本质”列，分清通用与专用。** CPU 像一位什么都能处理的总经理，擅长判断和调度，但做重复性的大批量计算并不划算。GPU 更像流水线工人队伍，同时处理成千上万个像素；NPU（神经网络处理单元，Neural Processing Unit）专门做矩阵乘法；ISP（图像信号处理器，Image Signal Processor）只服务于相机数据。越往下的模块越“专一”，同样的任务交给它们，耗电往往远低于让 CPU 硬算。这正是 3.1 节所说的异构计算思路：让合适的芯片做合适的事。

**第二把钥匙：看“关键指标”列，认出发布会参数的来历。** 发布会上的 GHz、TFLOPS、TOPS、“1 英寸大底”、dB，在这里都能找到归属。需要留意两点：
- 单个峰值数字不等于体验。CPU 主频高，若 IPC（每时钟周期执行的指令数，Instructions Per Cycle）低，实际速度未必快；GPU 浮点算力高，若每瓦性能差，玩久了就会因发热降频。
- 有些指标单位看似陌生，其实都指向“损耗”或“效率”。滤波器的插入损耗越小越好，PA 的功率附加效率（PAE，Power Added Efficiency）越高越省电。射频部分的好坏，很大程度体现在续航和信号上，而不是跑分里。

**第三把钥匙：看“企业”列，体会分工格局。** 计算芯片的架构授权来自 ARM，再由高通、苹果、联发科设计成 SoC；感光芯片由索尼、三星、豪威供应；镜头和马达来自大立光、舜宇光学、阿尔卑斯；射频器件集中在 Skyworks、Qorvo、博通、村田，国内也有唯捷创芯；振动马达则有瑞声科技、立讯精密。一部手机几乎不可能由一家公司从头造到尾，这一点将在第七章展开。

## 3.5.3 小场景：一次夜景快门里的接力

纸面上的分工，要放进真实操作才看得清。设想你在昏暗的街边举起手机，按下快门：

1. **CPU 先接单。** 触摸控制器报告“快门被按下”，CPU 判断这是拍照事件，唤醒相机流程，并调度各单元的频率。
2. **机械部件同步动作。** 音圈马达推动镜片完成对焦，光学防抖持续反向补偿手的抖动；若使用长焦，光线还要经过潜望三棱镜转折。
3. **CIS 连续曝光。** 弱光下，传感器会快速采集多帧画面，把光子转成电信号再转成数字信号。
4. **ISP 与 NPU 分工处理。** ISP 在 RAW 域对多帧进行对齐、降噪和合成；NPU 识别场景中的天空、人脸、灯光，分区域优化。
5. **GPU 负责呈现。** 预览画面与成片缩略图由 GPU 合成到屏幕上。
6. **触觉末梢收尾。** X 轴线性马达给出一下短促的“咔嗒”感，告诉你拍摄完成。

整个过程中，射频 PA 若正在上传云相册，也会同时工作。此时发热的主角通常是 ISP、NPU 与持续工作的 CIS 所在的 SoC 区域；系统面临的物理瓶颈，是在极小的密闭机身里同时控制功耗和温度。这也是第六章要讨论的温控机制的出发点。

## 3.5.5 小结

本章回答了“每个模块做什么”：CPU 调度，GPU 渲染，NPU 推理，CIS 与 ISP 成像，马达与棱镜管机械，PA 与滤波器管电磁波，线性马达管触觉。分工清楚之后，新的问题随之而来：这么多模块，究竟如何塞进不到一厘米厚的机身？下一章，我们进入物理与空间集成的世界。
