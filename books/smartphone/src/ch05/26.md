# 5.4 熄屏时的休眠脉动：微安级的“假死”与唤醒

晚上睡前，你把手机扣在床头柜上，屏幕一黑，房间安静下来。第二天早上拿起来，电量只掉了一小截。可就在这一夜里，它没有真正“关机”：微信消息照样推送进来，来电照样能接通，你一抬手，屏幕还会自己亮起。

这说明熄屏后的手机处在一种“假死”状态：大部分器官停止工作，少数哨兵继续值班。前面几节讲的是射频、快充、拍照这些高强度的流动，本节反过来看机身里最微弱、持续时间却最长的一种流动，也就是待机时的电流。

## 5.4.1 熄屏之后，谁被“拉闸”了

先打个比方。一栋写字楼到了深夜，办公区的灯、空调、电梯都关了，只剩门口保安室亮着一盏小灯。保安盯着监控，有人刷卡进门，他才去开一层楼的灯。

手机熄屏时的做法与此类似。屏幕熄灭后，几个耗电大户的**供电轨**会被彻底切断。供电轨（Power Rail）指电源管理芯片给某一组电路单独分配的供电线路，可以理解为大楼里分区的电闸。被切断的主要有三类：

- **主 SoC 的高性能计算核心**：平时跑应用、算界面的 CPU 大核和中核；
- **GPU（图形处理器，Graphics Processing Unit）**：负责渲染画面，屏幕不亮时没有活可干；
- **屏幕本身的供电**：显示面板和驱动电路是手机里最耗电的部件之一。

这里说的是“切断”，不是“降频”。降频好比把灯调暗，电闸断开才是彻底不耗电。数字电路即使不做运算，晶体管也会有微小的漏电，芯片规模越大，漏电总量越可观。所以在待机这件事上，把整块电路断电比让它“低速空转”省电得多。

## 5.4.2 常开硬件岛：SoC 里的“保安室”

主系统都断了电，那抬手亮屏是谁检测到的？答案藏在 SoC 内部一块特殊区域，叫**常开硬件岛**（Always-On Island）。

“岛”这个字很贴切。SoC 被划分成许多电源域，每一块都可以单独开关。常开岛是其中供电永不中断的一小块，和周围断电的区域互相隔离，好比夜里停电的城市中，一座靠自备电源运转的小岛。

岛上驻扎着一颗低功耗微控制器，通常称为 **Sensor Hub（传感器中枢）**。它的结构比主 CPU 简单得多，主频低、晶体管少，干活的方式也很专一：

1. 持续读取**加速度计**和**陀螺仪**的数据。加速度计感知手机在各方向上的加速度和重力方向，陀螺仪感知手机旋转的角速度；
2. 把这些数据串成随时间变化的曲线，在里面寻找“抬手”这一动作的特征；
3. 只有当它算出抬手旋转特征曲线出现**上升沿**，也就是数值从平稳状态突然明显升高、符合“把手机从平放翻转到面前”的规律时，才发出信号唤醒主系统，点亮屏幕。

整个过程中，Sensor Hub 的电流消耗只有**微安级（μA）**。1 微安是 1 毫安的千分之一。手机打游戏时电流常以“安”或数百毫安计，与之相比，Sensor Hub 就像保安室里那盏小台灯和整栋大楼的中央空调之间的差距。

为什么不让主 CPU 自己来盯传感器？因为传感器数据是连续不断涌来的。如果每来一点数据就叫醒一次主 CPU，它的大量电路要反复上电、恢复状态、处理数据、再断电，单次唤醒本身就有不小的开销。交给一个小而专一的微控制器全天候筛选，只把真正重要的事件上报，才能兼顾灵敏和省电。这正是第三章讲过的“专芯专用”能效哲学在待机场景里的体现。

## 5.4.3 5G 基带的“打盹”节奏：非连续接收

还有一个问题：手机熄屏后为什么还能接到电话？来电时，基站会通过**寻呼信道**（Paging Channel）广播一条消息，大意是“某某号码的手机，你有来电，请应答”。手机必须听到这条广播，才能接起电话。

但如果基带芯片一直开着接收机，射频通路长期处于工作状态，电量会很快耗尽。于是 5G 基带采用了**非连续接收**机制，英文是 Discontinuous Reception，简称 **DRX**。

DRX 的思路可以用一个场景说明：你在等一封重要的信，但不必整天守在信箱旁，只要和邮递员约好每隔一段时间来查看一次就行。手机和基站之间正是这样“约好”的：

- 在**绝大部分时间**里（具体比例取决于网络配置的 DRX 周期），基带处于深度睡眠，接收电路基本关闭；
- 每隔**几百毫秒**，基带短暂苏醒**几毫秒**，打开接收机，监听一下寻呼信道上有没有自己的消息；
- 如果没有，马上回去睡觉；如果有，就完全唤醒，建立连接，把来电或数据交给主系统。

基站知道手机按什么节奏醒来，会在对应的时刻发送寻呼消息，双方的时钟必须对得上。这种节奏也带来一个可以感知的折中：苏醒间隔越长越省电，但消息被听到的时间也会稍晚一些。几百毫秒的延迟，对接电话来说几乎感觉不到，换来的是待机时间的大幅延长。

## 5.4.4 两条脉动线的对照

把熄屏状态下仍在工作的两个“哨兵”放在一起看：

| 对比项 | Sensor Hub（常开硬件岛） | 5G 基带 DRX |
|---|---|---|
| 所在位置 | SoC 内部常开硬件岛 | 基带调制解调电路 |
| 监听对象 | 加速度计、陀螺仪数据 | 基站寻呼信道 |
| 工作方式 | 全天候低功耗读取与计算 | 绝大部分时间深睡，周期性短暂苏醒 |
| 时间尺度 | 持续运行 | 每隔几百毫秒醒来几毫秒 |
| 功耗量级 | 微安级（μA） | 平均功耗极低，靠大幅缩短工作时间实现 |
| 唤醒条件 | 识别出抬手旋转特征的上升沿 | 寻呼信道中出现本机消息 |
| 省电思路 | 用小芯片代替大芯片值班 | 用时间上的“断续”代替“常开” |

两者的手段不同，一个是**空间上的分工**，让最小的电路值班；一个是**时间上的切片**，让必须工作的电路只在关键时刻上岗。手机的待机续航，基本就是这两种思路叠加的结果。

## 5.4.5 小结：省电的关键在于“该睡就睡”

熄屏后的手机看起来静止，内部其实保持着一种低而稳定的脉动：常开岛上的 Sensor Hub 以微安级电流持续守望，基带按 DRX 的节奏一呼一吸，其余部分则被拉闸断电。一旦出现抬手动作或来电寻呼，这套体系能迅速把整台手机唤醒。

本章前几节看到的都是高峰时刻的能量与数据洪流，而这一节说明，系统设计同样要处理低谷时刻的问题。下一节将把射频、快充、计算摄影和休眠这四种流动放在同一张表里，比较它们在时间、功率和数据量上的差异。
