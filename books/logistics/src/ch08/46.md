# 8.3 网络设计：选址与轴辐式网络

你在手机上查看一件快递的轨迹：卖家和收件人明明在相邻的两个城市，包裹却先去了更远处的分拨中心，再折回来。它走错路了吗？不一定。物流网络要安排的不是这一件包裹，而是同一时段成千上万件货物。对单件货物看似绕行的路线，可能让整批货物用更少的车辆、更稳定的班次送达。

这就是**物流网络设计**：决定仓库、分拨中心等作业地点设在哪里、承担什么任务，以及各地点之间怎样连接。它既要回答“从哪儿走”，也要回答更早的一步——“为什么要在那里建一个点”。

## 8.3.1 先分清“点”和“线”

在物流网络中，仓库、集运仓、分拨中心和港口是**节点**，货物在这里集聚、暂存或改变运输方式；公路运输线路、海运航线等是**线路**，负责把节点连接起来。同一个地点可以兼有多种功能，但功能不同，选址考虑也不同。

仓库主要存放货物，通常要兼顾货源、客户分布和库存周转；分拨中心主要把到达的货物按去向重新组合，更看重进出线路是否顺畅、能否衔接班次；港口则受航道、码头设施和腹地交通等条件制约。不能因为地图上两个地点距离近，就断定它们适合承担同一种任务。

回到那个从中国网购、经集运仓合包后海运到马来西亚的包裹：中国境内的快递网点负责收寄，集运仓把不同订单的商品汇集成待出口的货件，海运把货物送往目的国，随后再由当地网络完成分拨和派送。这些节点由不同企业运营也很常见。对读者而言，轨迹上的每次“到达”和“离开”，就是观察网络节点及其连接方式的一扇窗。

## 8.3.2 选址不是在地图上找中心点

假设要为一片区域设置分拨中心，把图钉插在地图正中央，看起来很公平，却未必经济。订单可能主要集中在一侧；另一侧虽远，货量却少。还要考虑道路、用地、车辆进出、作业能力，以及到客户所在地的实际行驶时间。

选址时通常同时权衡几类成本和约束：

| 要考虑什么 | 它会怎样影响选址 |
| --- | --- |
| 建设与运营 | 场地、设备、人员等费用是否可承受 |
| 运输 | 货从哪里来、往哪里去，各段运输需要多少资源 |
| 时效 | 能否接上既定班次，在承诺时间内送达 |
| 容量 | 高峰时能否容纳货物、车辆与作业人员 |
| 风险 | 某个节点受阻时，是否还有可用的替代路径 |

其中，场地租用和设备投入等，不会随着某一天的包裹数量同步增减；运输、装卸等费用则通常随业务量变化。**设施选址问题**就是在候选地点中作选择，让网络在满足容量、时效等要求的前提下，控制总体成本。它不是寻找一个对所有包裹都最近的地点，而是在许多包裹、许多日期和多项约束之间求平衡。

这也解释了为什么企业不能只凭平均货量决定建点。平日够用的分拨中心，在网购促销等高峰期可能出现车辆排队、货物积压；若处处按极端高峰配置，又会在多数日子闲置。网络设计必须给波动留出余地，同时避免过度建设。

## 8.3.3 轴辐式网络为什么允许“绕路”

想象几个城市之间都有货要运。如果每两个城市都开设直达班次，路线会很多，但每条线上的货量可能不足以装满车辆。另一种做法是设置一个或几个枢纽：各地先把货送到枢纽，再按目的地重新组合，发往下一站。这叫**轴辐式网络**（hub-and-spoke network）：枢纽像车轮的轴，连接各地的线路像辐条。

它的优势不是让每件货都走最短距离，而是**汇聚货量**。多地的小批量货物在枢纽合并后，可能支撑更稳定的班次和更充分的车辆装载。快递分拨、航空运输和一些公路货运网络都能见到类似组织方式。前面那件“先走远再折返”的快递，可能就是先进入枢纽，换乘一条集中运往目的地区域的线路。

但绕行并非总是划算。经过枢纽会增加一次装卸和等待；枢纽处理能力不足，还可能造成拥堵。如果两个地点之间货量充足、时效要求高，**直达线路**——不经过中间分拨节点的运输连接——就可能更合适。因此，现实网络往往同时保留枢纽中转和部分直达线路，而不是只选一种。

集运仓也体现了“先集中、再发运”的思想，但不要把它与快递分拨中心画等号。集运仓可能要等待多个订单到齐、核对并合包；分拨中心则主要按去向分拣，让货物接上下一段运输。两者都在汇聚货量，作业目的和停留时间却可能不同。

## 8.3.4 一张网络图，为什么要反复修改

网络一旦建成，也不会永久不变。订单分布改变、新的道路或航线投入使用、港口与清关环节的处理能力变化，都可能使原先合适的方案不再合适。物流企业因此会比较不同方案：增设节点能否缩短派送距离？减少一次中转能否抵消新增直达班次的费用？某个枢纽停运时，货物能否改走别的路径？

比较时，不能只看地图上的直线距离。货物的实际行程还包括等待发车、装卸、分拣和排队。尤其对跨境包裹而言，中国境内集货、国际海运和马来西亚境内派送属于不同路段，各段的班次与作业约束都要纳入考虑。一条路程较短的线路，如果错过衔接班次，实际到达时间反而可能更晚。

所以，网络设计的核心问题不是“怎样让每件包裹都不绕路”，而是“怎样让整张网络在成本、时效和承载能力之间取得可行的平衡”。下次看到物流轨迹中的折返或中转，可以先标出节点，再问：货物在这里汇聚了什么、换乘了什么，以及这次中转可能为整张网络节省了什么。
