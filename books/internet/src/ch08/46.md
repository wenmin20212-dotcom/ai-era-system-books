# 8.3 图论与路由算法：最短路径与距离向量

打开手机地图，输入目的地，软件几乎瞬间就给出一条“最快路线”。它并没有把所有可能的走法一条条试过去，而是把城市看成一张由路口和道路组成的“图”，再用一套算法从中挑出代价最小的那条。互联网里的路由器每天做的是同一件事：把成千上万台路由器和它们之间的链路看成一张图，算出数据包该往哪个方向走。第三章讲过路由器“查表转发”，第五章讲过路由协议怎样交换“地图”。这一节往下再挖一层，看看那张表背后的数学：图论（Graph Theory）和两类经典的路由算法。

## 8.3.1 把网络画成一张图

图论里的“图”不是图片，而是一种抽象结构，只有两种元素：

- **节点（Node，也叫顶点 Vertex）**：网络中的路由器，或者整个自治系统；
- **边（Edge）**：连接两个节点的链路，比如一根光纤、一条专线。

每条边可以附上一个数字，叫**权重（Weight）**或**代价（Cost）**，表示走这条边要付出多少“成本”。成本怎么定义，由网络管理员决定，常见的依据有：

| 代价依据 | 含义 | 典型用法 |
|---|---|---|
| 跳数 | 每经过一台路由器算 1 | 早期的 RIP 协议 |
| 带宽 | 带宽越大，代价越小 | OSPF 常用的默认思路 |
| 时延 | 链路越慢，代价越大 | 部分网络按测得的时延设定 |
| 管理策略 | 人为调高或调低 | 引导流量避开某条昂贵线路 |

有了这张带权重的图，“找路”就变成一个定义清晰的数学问题：**从起点到终点，哪条路径上各条边的代价之和最小？**这就是**最短路径问题（Shortest Path Problem）**。这里的“最短”并不一定是物理距离最短，而是总代价最小。

举个小例子：家里的路由器 A 要把数据送到 D。A—B 代价 1，B—D 代价 5，A—C 代价 2，C—D 代价 1。直觉上经过 B 好像也行，但总代价是 6；经过 C 只有 3。算法要做的，就是在大规模网络里稳定、快速地得出这种结论。

## 8.3.2 链路状态：每人手里一张全图，各自算

第一类思路叫**链路状态（Link State）**。做法分三步：

1. 每台路由器先摸清自己有哪些邻居、各条链路代价多少；
2. 把这份“自我介绍”广播给网络里的所有路由器，这个过程叫**泛洪（Flooding）**；
3. 每台路由器收集齐所有人的介绍后，在自己内部拼出一张完整的全网地图，再独立计算到每个目的地的最短路径。

第三步用到的，就是计算机科学家**迪杰斯特拉（Edsger W. Dijkstra）**在 1959 年发表的算法，通常称为 **Dijkstra 算法**。它的思路可以用“水波扩散”来类比：从起点出发，先确定离自己最近的节点，再以已确定的节点为基础，一圈一圈向外推进；每次都挑出“目前已知总代价最小、尚未确定”的那个节点，把它的最短路径定下来，并用它去更新邻居的估计值。直到所有节点都被确定，一棵以自己为根的“最短路径树”就画好了。

采用这种思路的代表协议是**开放最短路径优先（OSPF，Open Shortest Path First）**和 **IS-IS（中间系统到中间系统，Intermediate System to Intermediate System）**，它们多用于一家运营商或一家企业内部的网络。好处是每台路由器都“心里有全局”，链路一断，消息迅速泛洪，大家重新计算，收敛较快；代价是每台路由器都要存全图、跑算法，网络越大，内存和计算压力越大。因此大型网络通常会把内部再划分成若干**区域（Area）**，每个区域内部掌握细节，区域之间只交换汇总信息。

## 8.3.3 距离向量：只听邻居说，口口相传

第二类思路叫**距离向量（Distance Vector）**，风格完全不同。路由器不需要全图，只需要知道一件事：**我的每个邻居说，它到各个目的地有多远。**

每台路由器维护一张表，列出“到某目的地的距离，以及该交给哪个邻居”，并定期把这张表告诉邻居。收到邻居的表后，它做一道加法：

> 经邻居 X 到达目的地 D 的代价 = 我到 X 的代价 + X 声称它到 D 的代价

对每个目的地，选总和最小的那个邻居作为下一跳。背后的数学是 **Bellman-Ford（贝尔曼-福特）算法**，以理查德·贝尔曼和小莱斯特·福特的名字命名。这就像在陌生城市问路：你不看地图，只问身边的人“去火车站还有几站”，再加上自己走到他那里的距离，挑最近的一个跟上去。

代表协议是**路由信息协议（RIP，Routing Information Protocol）**，以跳数为代价，规定最大跳数为 15，16 即视为“不可达”，因此只适合小型网络（见 RFC 2453）。

距离向量的优点是简单、每台设备负担轻；缺点是消息一层一层传，坏消息传得慢。经典的毛病叫**无穷计数（Count to Infinity）**：某条链路断了，A 以为 B 还能到达目的地，B 又以为 A 能到，两者互相引用对方的旧信息，距离数字一轮轮地加，迟迟不肯承认“到不了”。RIP 把 16 定为“无穷”，正是为了给这个过程设一个上限；此外还有**水平分割（Split Horizon）**等补救办法：从某个邻居那里学来的路由，就不再反过来告诉这个邻居。

## 8.3.4 两种思路对照，以及 BGP 的位置

| 对比项 | 链路状态 | 距离向量 |
|---|---|---|
| 掌握的信息 | 全网拓扑 | 邻居告知的距离 |
| 核心算法 | Dijkstra | Bellman-Ford |
| 代表协议 | OSPF、IS-IS | RIP |
| 收敛速度 | 较快 | 较慢，可能出现无穷计数 |
| 资源开销 | 存储与计算较多 | 较少 |
| 典型场景 | 运营商或企业内部的大中型网络 | 小型网络 |

那么连接各个自治系统的 **BGP（边界网关协议，Border Gateway Protocol）**属于哪一类？它常被称为**路径向量（Path Vector）**协议，可以看作距离向量的改良版：通告路由时，不只说“有多远”，还附上要经过的自治系统完整列表。路由器一旦在列表里看到自己的编号，就知道出现了环路，直接丢弃，从根本上避开了无穷计数。更重要的是，BGP 选路主要依据商业关系和管理策略，而不是单纯求最短，这一点在 6.3 节已经讲过。这也说明：数学给出“最优”，工程还要服从现实。

## 8.3.5 小结：算法决定了网络怎样“想事情”

同一张图，链路状态让每台路由器做“全知的计算者”，距离向量让它们做“互相传话的邻居”，路径向量则在传话时附上完整的经过记录。互联网之所以能在节点不断增减、链路时断时通的情况下持续找到路，靠的正是这些从图论中长出来的算法：内部网络多用链路状态求快求准，网络之间用路径向量求稳、讲策略。

不过，找到路只解决了“怎么连”的问题。下一节要转向另一个问题：网络连起来以后，节点越多为什么价值越大？那里要讲的是梅特卡夫定律与网络效应。
