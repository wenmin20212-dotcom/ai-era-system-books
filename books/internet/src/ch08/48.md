# 8.5 开放、韧性与安全：互联网设计的取舍

你在咖啡馆连上一个没有密码的 Wi-Fi，几秒钟后就能打开世界另一端的网页。没人审查你的设备是什么牌子，也没人要求你先登记身份。这种“谁都能接进来”的体验看似平常，背后其实是一组有意为之的设计选择。你在同一张网上收到的钓鱼短信、遇到的网站被攻击而打不开，也和这些选择有关。本节把前面几节的原理收拢起来，看互联网怎样在开放、韧性和安全三者之间取舍。

## 8.5.1 开放：不问来者是谁

互联网最初的设计目标之一，是把各种各样已经存在的网络连起来。参与阿帕网和 TCP/IP 设计的工程师在回顾文章里列过一组优先级：首先是在部分网络和网关失效时仍能继续通信，其次是支持多种服务，再次是容纳多种网络。“安全”和“计费”排在后面，有的根本没列进去。

这种取向落到工程上，主要有三点：

- **协议公开**：TCP、IP、DNS、HTTP 等核心协议都写成 RFC（Request for Comments，征求意见稿）公开发布，任何人都能免费阅读、自行实现，不需要向谁申请授权。
- **网络中立地转发**：路由器只看数据包头部的目的地址，不关心里面装的是网页、邮件还是视频。这正是 8.1 节端到端原则的体现，新应用不需要网络“批准”就能上线。
- **自愿互联**：自治系统之间是否互联、怎样结算，由各方协商决定，没有一个总调度中心（见 4.2 节）。

开放带来的好处很直接。万维网、即时通信、视频直播，都是在不改动网络核心的前提下由边缘的人发明出来的。8.4 节讲的网络效应，也需要“接入门槛低”这个前提才能滚起来。

## 8.5.2 韧性：坏掉一部分，整体还能用

韧性指系统在部分损坏时继续工作、并较快恢复的能力。互联网的韧性来自几种机制叠加：

| 机制 | 怎样提供韧性 | 本书相关章节 |
|---|---|---|
| 分组交换 | 数据切成独立的包，不预先占用固定线路，一条路断了，后续的包可以走别的路 | 6.1 |
| 分布式路由 | 每台路由器根据邻居交换的信息自行算路，没有单一控制点 | 3.3、6.3 |
| 多路径与冗余 | 骨干网、海底光缆通常有多条备份路径 | 2.3、2.4 |
| 端系统重传 | 网络丢包时由 TCP 在两端补救，不要求每一跳都可靠 | 6.2 |
| 层级缓存 | DNS 和 CDN 的缓存让部分服务器失效时仍有副本可用 | 6.4、7.3 |

这种韧性有具体例子可看：海底光缆被船锚或地震损坏的事件时有发生，公开报道中常见的结果是相关地区访问变慢，而不是全面断网，因为流量会被路由协议绕到其他电缆上。

韧性也有边界。冗余要花钱，偏远地区可能只有一两条出口线路。韧性也依赖“大家都按规矩办事”，一旦错误信息在分布式系统里扩散，传播速度同样很快。

## 8.5.3 安全：后来补上的那一层

开放的另一面，是早期协议默认参与者彼此信任。举几个典型例子：

- **IP 地址可以被伪造**：IP 包头里的源地址由发送方自己填写，网络本身不验证。这让“伪造来源、放大流量”的拒绝服务攻击有了可乘之机。
- **BGP 默认相信邻居的宣告**：6.3 节提到，一个自治系统错误地宣告了不属于自己的地址段，可能把别人的流量吸走。这类事件在公开资料中被称为路由劫持或路由泄露，多数源于配置失误，也有恶意的。
- **DNS 和早期 HTTP 是明文**：查询和网页内容在途中可以被看到，甚至被篡改。

后来的修补大多采用“在原有结构上加一层”的办法，而不是推倒重来：

| 问题 | 补救技术 | 思路 |
|---|---|---|
| 网页内容被窃听、篡改 | TLS / HTTPS | 两端加密并验证证书 |
| DNS 应答被伪造 | DNSSEC，以及加密的 DNS 传输方式 | 给记录加签名，或给查询通道加密 |
| BGP 路由被冒认 | RPKI（Resource Public Key Infrastructure，资源公钥基础设施） | 用证书证明“这段地址归谁宣告” |
| 伪造源地址 | 源地址过滤（相关最佳实践见 BCP 38 等文档） | 在网络入口丢弃源地址不合理的包 |

这些措施都要靠各方自愿部署，进展参差不齐。写作时 HTTPS 已在主流网站上普及，RPKI 和源地址过滤的部署仍在推进之中，各地区、各运营商的情况差别很大。这正说明了分布式体系的特点：没人能下令所有人同时升级。

## 8.5.4 三者之间的拉扯

开放、韧性和安全并不总是同向的。

- **开放与安全**：门槛越低，滥用越容易；加严身份校验，又会抬高创新和接入的门槛。
- **安全与韧性**：加密和签名让中间设备看不懂流量，排查故障、做缓存都更难；证书过期、签名配置错误本身也可能让网站“自己把自己锁在门外”。
- **韧性与开放**：为了抵御攻击，一些网络会集中到少数大型 CDN 或云平台后面。单个网站更稳了，但大量服务依赖同一家提供商，那家一出故障，许多网站会同时受影响。公开报道中多次出现过这类大面积中断。

所以，互联网的“设计”并不是一份一次性定好的蓝图。它更像一场持续的协商：核心尽量保持简单开放，安全和可靠在两端与各层逐步加固，每一项改进都要在兼容旧设备和应对新威胁之间找平衡。

## 8.5.5 对普通用户意味着什么

理解这组取舍，可以落到几个日常习惯上：认准地址栏里的 HTTPS 和浏览器的证书警告，不要随手点“继续访问”；在公共 Wi-Fi 上不轻易登录重要账户；及时给路由器和光猫更新固件，修改默认管理密码。网络在设计上把很多判断留给了端系统，你的设备和你自己就是这道防线的一部分。

到这里，第八章的几条原理已经齐备：端到端原则决定了“智能放在哪里”，排队论解释了拥塞，图论支撑着路由，网络效应说明了规模从哪来，而开放、韧性与安全的取舍，则说明这张网为什么既生机勃勃又需要不断修补。
