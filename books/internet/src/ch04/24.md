# 4.4 互联网治理：标准组织、地址分配与域名管理

在浏览器地址栏里敲下一个以“.cn”或“.com”结尾的网址，按下回车，你的手机拿到的 IP 地址不会和地球另一边某台服务器的地址重复，名字也会被翻译成唯一正确的地址，两端设备讲的又是同一套协议。这件事看起来理所当然，其实背后要回答三个问题：协议由谁来定？地址由谁来分？名字由谁来管？互联网没有一个“总部”，可这三件事各有一套分工明确的机构和流程。这套安排通常叫作互联网治理（Internet Governance）。本节只讲其中最技术、最贴近日常上网的三根支柱：标准、编号和域名。

## 4.4.1 谁来定规则：IETF 与 RFC

前面几章反复提到 TCP、IP、DNS、HTTP，它们的正式文本大多以 RFC（Request for Comments，征求意见稿）的形式发布。RFC 由 IETF（Internet Engineering Task Force，互联网工程任务组）主导产生。IETF 和一般的国际组织不太一样：

- **没有会员制**。任何人都可以订阅邮件列表、参加讨论，工程师以个人身份发言，不代表所属公司。
- **“粗略共识与运行的代码”**。IETF 有一句流传很广的话，大意是“我们不要国王、总统和投票，我们相信粗略共识和能跑的代码”。决定一个方案，主要看工作组里有没有形成大体一致的意见，以及有没有能互通的实现，而不是简单投票。
- **文档编号只增不改**。一份 RFC 发布后内容不再修改；要更新，就发一份新编号的 RFC，并注明“更新”或“废止”了哪份旧文档。所以查标准时要留意某份 RFC 有没有被后来者取代。

IETF 之外还有几个相关角色。IAB（Internet Architecture Board，互联网架构委员会）关注整体架构；ISOC（Internet Society，互联网协会）为 IETF 提供组织和法律上的依托；网页层面的许多标准，如 HTML、CSS 的规范，则主要由 W3C（万维网联盟）和 WHATWG 等组织推进。另外，光纤、蜂窝等底层通信标准多出自 IEEE、3GPP、ITU 等机构，在本系列相关分册中再展开。

可以这样理解：IETF 像一部“开源的交通法规”，谁都可以参与起草，谁都可以免费下载阅读，设备厂商和软件开发者各自照着实现，彼此就能互通。

## 4.4.2 谁来分号码：IANA 与五大地区注册机构

地址和协议里的各种编号必须全球唯一，这就需要一个“总号码簿”。这项职能叫 IANA（Internet Assigned Numbers Authority，互联网号码分配机构），目前由 ICANN 旗下的机构 PTI 具体运作。IANA 管理三类东西：IP 地址与自治系统号码（AS 号，见 4.2 节）的顶层分配、DNS 根区，以及各种协议参数（比如端口号的登记表）。

IANA 并不直接给你家运营商发地址，而是把大块地址分给五个 RIR（Regional Internet Registry，地区互联网注册机构），形成逐级下放的结构：

| 层级 | 机构 | 覆盖范围或角色 |
|---|---|---|
| 全球 | IANA | 管理整个地址池，按大块分给各地区 |
| 地区 | AFRINIC | 非洲 |
| 地区 | APNIC | 亚太地区（含中国） |
| 地区 | ARIN | 北美 |
| 地区 | LACNIC | 拉丁美洲和加勒比 |
| 地区 | RIPE NCC | 欧洲、中东和中亚部分地区 |
| 国家或本地 | NIR / LIR | 部分国家设有国家级注册机构，例如中国的 CNNIC；运营商作为本地注册机构 |
| 用户 | 运营商分给家庭和企业 | 你家路由器拿到的公网地址 |

地址分配的规则不是哪个机构单方面定的，而是在各 RIR 的社区里公开讨论形成“政策”。IPv4 地址的总量只有约 43 亿个，公开资料普遍记载 IANA 在 2011 年把最后几块 IPv4 地址分给了各 RIR，此后各地区陆续进入只能少量分配或排队等待回收地址的阶段。这正是 NAT 被大量使用、IPv6 必须推开的背景，第七章 7.1 节会细讲。

## 4.4.3 谁来管名字：ICANN、注册局与注册商

域名的管理也是层层授权。ICANN（Internet Corporation for Assigned Names and Numbers，互联网名称与数字地址分配机构）是一家总部设在美国的非营利机构，负责协调顶级域的设立和域名行业的政策。它采用“多利益相关方”模式：政府、企业、技术社区、民间团体都可以通过各自的支持组织或咨询委员会参与讨论，政府咨询委员会就是其中之一。

一个域名从无到有，大致涉及三类角色：

1. **注册局（Registry）**：负责运营某个顶级域的数据库和权威服务器。例如 .com 由一家美国公司运营（写作时为 Verisign），.cn 由 CNNIC 运营。
2. **注册商（Registrar）**：面向用户销售和管理域名的公司，你在域名服务商网站上购买域名时打交道的就是它。
3. **注册人（Registrant）**：也就是买下域名的个人或单位。

顶级域又分两大类：通用顶级域，如 .com、.org 以及近年新增的大量新后缀；国家和地区代码顶级域，如 .cn、.jp、.uk，后者的管理政策通常由当地机构依当地规定制定。

DNS 解析的起点是根区。根区文件的内容变更由 IANA 职能处理；根服务器则由十几家不同的组织运营，对外呈现为从 A 到 M 的 13 个名字，每个名字背后又通过任播技术在全球部署了大量实例，所以实际服务器数量远多于 13 台。这些细节在 6.4 节讲 DNS 机制时还会用到。

## 4.4.4 没有总部的协调：为什么这样分工

把三根支柱放在一起看，会发现一个共同特点：**谁都不是“互联网的主人”**。IETF 写标准，但无权强迫任何人实施；IANA 维护号码簿，但具体分配依赖 RIR 社区制定的政策；ICANN 协调域名，但各国的国家代码顶级域由当地管理。真正让这套体系运转的，是大家自愿遵守同一套规则带来的好处：遵守协议才能互通，用唯一的地址才能被找到。

这种安排也有争议。例如 ICANN 与美国政府的历史关系曾长期受到国际社会关注，2016 年 IANA 职能管理权移交完成后，监督转为由全球多利益相关方社区承担。联合国框架下的互联网治理论坛等场合，也一直在讨论各国政府在网络空间中应扮演什么角色。数据保护、内容监管等议题则更多属于各国法律范畴，超出了本书的技术范围。

回到开头那个网址：你能顺利打开它，是因为协议文本来自公开的 RFC，地址经过 IANA、APNIC 一路分到运营商，名字在注册局的数据库里登记在案。分层模型让协议各司其职，自治系统之间的协商让流量跨网流动，治理体系则让全球数以十亿计的设备共用同一套“号码”和“语言”。下一节，我们把这一章的连接关系收拢成一张骨架图。
