# 4.5 本章骨架小结与实物探索任务

前三章我们一直在回答“有什么”“做什么”：手机、光猫、骨干网、海底光缆、服务器，以及寻址、命名、路由、可靠传输这些功能。第四章换了一个角度，问的是“它们之间是什么关系”。同一个网页请求，在分层模型里被拆成几层分工，在运营商之间被一段段转交，在客户端和服务器之间来回问答，背后还有一整套规则和机构在维持秩序。本节先把这四种关系收拢成一副骨架，再请你动手在自己的设备上把它们找出来。

## 4.5.1 本章骨架回顾：四种“关系”

### 4.5.1.1 纵向关系：分层模型

- TCP/IP 模型把网络通信分成四层：链路层、网络层、传输层、应用层。OSI（开放系统互连，Open Systems Interconnection）模型分成七层，主要用作教学和讨论的参照。
- 每一层只为上一层提供服务，只依赖下一层的接口。数据从上往下逐层“套信封”，叫作封装；到达对端后再逐层“拆信封”，叫作解封装。
- 分层的意义在于各层可以独立替换。把 Wi-Fi 换成网线，或把 IPv4 换成 IPv6，网页本身不需要改动。

### 4.5.1.2 横向关系：自治系统互联

- 互联网由成千上万个自治系统（Autonomous System，AS）组成。每个 AS 由一个或多个运营者管理，对外执行统一的路由策略，并拥有一个全球唯一的 AS 编号。
- AS 之间有两种基本商业关系。“转接”是付费购买通往全网的可达性；“对等”是双方互相交换各自用户的流量，通常不互相付费。互联网交换中心（IXP）是集中进行对等互联的场所。
- 这些关系决定了数据包实际走哪条路。真实路径往往由合同和策略决定，物理距离最短的路线未必被选中。

### 4.5.1.3 角色关系：客户端、服务器、点对点与边缘

- 浏览网页是典型的客户端—服务器模式：浏览器主动发起请求，服务器响应。
- 点对点（P2P）模式中，每个节点既是请求方也是提供方，常见于部分文件分发和实时音视频场景。
- 边缘计算把计算和缓存放到离用户更近的位置，用来缩短往返时间、分担中心节点的压力。三种模式在实际系统里常常混合使用。

### 4.5.1.4 制度关系：互联网治理

- 标准层面：IETF（互联网工程任务组）以 RFC 文档的形式发布协议标准，网页相关标准则主要由 W3C（万维网联盟）和 WHATWG 等组织推进。
- 资源层面：IANA（互联网号码分配机构）职能目前由 ICANN（互联网名称与数字地址分配机构）下属机构履行，统筹分配顶级的 IP 地址块和 AS 号；五个区域互联网注册管理机构（RIR）再向各自地区分配，亚太地区由 APNIC 负责。域名方面，各顶级域由对应的注册管理机构运营。
- 互联网没有一个“总部”，靠多利益相关方协作，以及大家对公开标准的共同遵守来运转。

把四种关系压缩成一句话：**层与层之间是服务关系，网与网之间是商业关系，端与端之间是角色关系，人与网之间是规则关系。**

| 关系类型 | 回答的问题 | 关键词 | 你身边的痕迹 |
|---|---|---|---|
| 分层 | 一次通信分几步完成 | 封装、接口 | 网络设置里分开显示的 IP、DNS、Wi-Fi |
| 自治系统互联 | 数据跨哪些“国界” | AS、对等、转接、IXP | 路由跟踪结果里不同运营商的节点 |
| 客户端/服务器 | 谁请求、谁提供 | 请求、响应、P2P、边缘 | 浏览器开发者工具里的请求列表 |
| 治理 | 规则谁定、资源谁分 | RFC、ICANN、RIR | 域名注册信息、IP 归属查询结果 |

## 4.5.2 实物探索任务

以下任务只需要一台电脑或手机，均为只读的查看操作，不会改动任何设置。

**任务 1：在设置里找出“分层”** 打开手机或电脑的网络详情页，分别找到这几项：Wi-Fi 名称和信号强度（链路层）、本机 IP 地址和网关（网络层）、DNS 服务器（服务于应用层的命名）。把它们写在纸上，标出各自属于哪一层。

**任务 2：查一查你的运营商是哪个 AS** 用搜索引擎找一个公开的“IP 归属/ASN 查询”网站，查看你当前公网出口地址所属的 AS 编号和机构名称。再分别用家庭宽带和手机流量各查一次，比较结果是否相同。

**任务 3：用路由跟踪看“过境”** 在 Windows 命令行里输入 `tracert` 加一个常用网站的域名，macOS 或 Linux 上用 `traceroute`。观察经过的节点地址，再挑几个用任务 2 的方法查归属，标出路径在哪里从一个 AS 进入了另一个 AS。部分节点显示星号属于正常现象，通常是设备设置为不回应探测。

**任务 4：数一数一个网页的“服务器”** 在电脑浏览器中按 F12 打开开发者工具，切到“网络”（Network）面板后刷新页面。统计这些请求来自多少个不同的域名，留意其中哪些看起来像图片、脚本或内容分发网络的节点。你会发现，一个网页背后通常不止一台服务器。

**任务 5：查一个域名的“户口”** 找一个公开的 WHOIS 或 RDAP（注册数据访问协议）查询页，查询你常用网站的域名，看它的注册商、注册日期和域名服务器。注意，出于隐私保护，部分注册人信息会被隐藏。

## 4.5.3 可以直接拿去问 AI 的问题

1. “这是我执行 traceroute 的结果（附上文本），请帮我判断路径大致经过了哪几个运营商或自治系统，哪里可能是跨网互联点？请说明你的判断依据，并标出哪些地方不确定。”
2. “请用寄快递的类比，解释一个 HTTPS 网页请求在 TCP/IP 四层中分别被加上了什么‘信封’，每层的信封上写着什么信息。”
3. “两个运营商之间选择对等互联还是购买转接，主要考虑哪些因素？这种选择对普通用户访问网站的速度有什么影响？”

提问时，请让 AI 区分“公认的标准事实”和“某家运营商或某个地区的具体做法”。拿到回答后，再用任务里的真实结果去核对。
