# 6.3 BGP：互联网的路由协议与它的脆弱点

你在家里打开一个境外视频网站，数据包离开家里的光猫后，要穿过你的运营商，也许再经过一两家国际运营商，才能到达视频网站的机房。这些运营商各自管理自己的网络，彼此之间并没有一个总调度台。那么，你的运营商的路由器怎么知道视频网站的地址“在哪个方向”？答案是一套在运营商之间不停交换消息的协议：边界网关协议（Border Gateway Protocol，BGP）。它很少被普通用户注意到，但当它出错时，一家大型网站可能整个从互联网上“消失”。

## 6.3.1 BGP 在做什么：在自治系统之间交换“我能到哪里”

第四章讲过，互联网由成千上万个自治系统（Autonomous System，AS）组成，每个 AS 有一个编号（ASN），可以是运营商、大学、云服务商或大型网站。AS 内部怎么走路，由它自己用 OSPF 等内部路由协议决定；AS 与 AS 之间怎么走，则由 BGP 负责。目前使用的版本是 BGP-4，规范见 RFC 4271。

BGP 交换的核心信息可以简化成一句话：“某个地址段，经我这里可以到达，路径是这样的。”例如，视频网站所在的 AS 向邻居宣告“地址段 X 在我这里”；邻居收到后，把自己的编号加到路径前面，再告诉它的邻居；层层传递，全球的运营商路由器便都知道了地址段 X 的去向。

几个关键概念：

| 概念 | 含义 | 类比 |
|---|---|---|
| 前缀（prefix） | 一段 IP 地址，如某个 /24 地址块 | 一个片区的门牌范围 |
| 宣告（announcement） | 告诉邻居“这个前缀经我可达” | 在路口立指示牌 |
| 撤销（withdrawal） | 告诉邻居“这个前缀经我不可达了” | 拆掉指示牌 |
| AS_PATH | 到达该前缀要经过的 AS 编号序列 | 沿途经过的城市列表 |
| 对等会话（session） | 两台 BGP 路由器之间的长期连接，基于 TCP 179 端口 | 两个邻居之间的电话专线 |

在 AS 之间运行的叫外部 BGP（eBGP），把这些信息在同一 AS 内部的边界路由器之间同步的叫内部 BGP（iBGP）。

## 6.3.2 路径向量与策略：BGP 不只看“最短”

第八章会讲到距离向量算法。BGP 是它的变体，叫“路径向量”协议：它传递的不是一个距离数字，而是完整的 AS 路径。这样做有两个好处。第一，能防环路：路由器看到路径里已经有自己的编号，就丢弃这条路由。第二，能执行策略：运营商可以根据路径里有谁来决定用不用这条路。

这一点是理解 BGP 的关键：**BGP 选路首先看商业关系和策略，其次才看路径长短。** 第四章介绍的“对等”与“转接”关系在这里落地——一家运营商通常优先走客户的路由（客户付钱），其次走对等伙伴，最后才走需要付费的上游转接。路由器依次比较本地优先级、AS_PATH 长度等一系列属性来选出最佳路径。所以你的数据包走的往往不是地理上最近的路线，而是“商业上合适”的路线。

BGP 的另一个特点是增量更新：会话建立后先交换完整路由表，之后只在变化时发送更新。公开路由观测项目（如 RouteViews、RIPE RIS）的数据显示，写作时全球 IPv4 路由表的规模在百万条前缀的数量级。

## 6.3.3 脆弱点：一个建立在“相信邻居”之上的系统

BGP 诞生于上世纪八十年代末（首个规范 RFC 1105 发布于 1989 年），那时互联网参与者少，彼此熟悉。协议本身默认相信邻居的宣告——它并不验证“你说这个前缀在你那里，是真的吗”。由此带来几类典型问题：

- **路由劫持（hijack）**：某个 AS 宣告了不属于自己的前缀。由于 BGP 倾向于选择更具体（更长）的前缀，这类错误宣告可能吸走大量流量。最著名的案例之一是 2008 年巴基斯坦电信为在国内屏蔽 YouTube 而宣告了其一段更具体的 /24 地址段，该宣告意外传播到全球，导致 YouTube 在全球范围内中断约两小时。
- **路由泄露（route leak）**：某个 AS 把本应只在小范围内使用的路由转告给了不该告诉的邻居，例如把从一个上游学到的路由宣告给另一个上游，使大量流量绕道经过一个承载能力不足的小网络。RFC 7908 对这类问题做了分类。
- **配置失误导致撤销**：2021 年 10 月，Facebook（现 Meta）的服务中断数小时。按该公司公开的事后说明，一次骨干网维护操作出错，进而导致其 DNS 服务器所在前缀的 BGP 宣告被撤销，外界无法再找到这些服务器。

这些事件大多并非恶意，而是人为失误在“默认互信”的体系里被迅速放大。BGP 的脆弱，本质上是开放互联与安全验证之间的取舍，这个话题在 8.5 节还会展开。

## 6.3.4 补强措施：给路由宣告加上“产权证明”

近十多年，业界在不推翻 BGP 的前提下逐步加固：

1. **RPKI（资源公钥基础设施，Resource Public Key Infrastructure）**：地址持有者通过区域互联网注册机构签发路由起源授权（ROA），声明“这个前缀只允许由某个 AS 宣告”。运营商的路由器据此做路由起源验证（ROV），丢弃起源不符的宣告。相关规范见 RFC 6480、RFC 6811。它能有效拦截许多误宣告，但只验证“起点”，不验证整条路径。
2. **过滤与最佳实践**：运营商按客户实际持有的地址设置过滤规则，只接受合理的宣告。行业倡议 MANRS（路由安全相互约定规范）推动成员落实这类做法。
3. **BGPsec（RFC 8205）**：对整条路径逐跳签名，能力更强，但计算和部署成本高，写作时部署范围仍很有限。

作为普通用户，你无法直接干预 BGP；但做网站和运维的读者可以检查自己的地址段是否已登记 ROA，并选择支持路由起源验证的上游运营商。

## 6.3.5 小结

BGP 是把数万个自治系统粘成一个互联网的“外交协议”：它传播路径、执行商业策略、默认信任邻居。这份信任让互联网得以快速扩张，也让一次误宣告能在几分钟内波及全球。路由告诉数据包往哪个方向走，但在出发之前，浏览器还得先把域名变成 IP 地址——下一节我们转向 DNS 的层级、缓存与解析过程。
