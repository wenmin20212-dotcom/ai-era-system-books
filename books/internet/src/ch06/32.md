# 6.1 分组交换与尽力而为：互联网的基本设计

晚上你在家看视频，家人在刷网页，路由器的指示灯一直闪。你们两个人用的是同一根光纤、同一台路由器，却谁也不用排队“占线”。可要是回到几十年前打固定电话，情况就不一样了：家里有人在通话，别人拿起分机只能听到忙音。这两种体验的差别，来自两种不同的网络设计思路，即电路交换和分组交换。互联网选择了后者，还在它上面加了一条朴素的承诺：“尽力而为”。这一节就从这里讲起，看看第六章所有机制共同依靠的那块地基。

## 6.1.1 两种交换：先占路，还是边走边分

**电路交换（Circuit Switching）**是传统电话网的做法。通话开始前，网络先在主叫和被叫之间预留一条端到端的通路，整个通话期间这条通路归你独占，说话也好、沉默也好，资源都一直占着。好处是延迟稳定、音质可预期，坏处是浪费：通话里大量时间是停顿，预留的容量就这样空闲着。

**分组交换（Packet Switching）**则把要发送的数据切成一个个小块，每块加上“信封”（包头，写明源地址和目的地址），叫作**分组**或**数据包（Packet）**。分组各自上路，路由器收到一个就看一眼地址、转发一个，链路不为任何人预留，谁有数据谁就用。

可以用交通来类比：电路交换像为一支车队提前封路，路上没车也不许别人走；分组交换像开放的公路，所有车辆共用车道，各自看路牌前进。

| 对比项 | 电路交换 | 分组交换 |
|---|---|---|
| 建立通路 | 通信前先建立并预留 | 不预留，分组随到随转 |
| 资源使用 | 独占，空闲时也占着 | 共享，按需使用 |
| 延迟 | 稳定、可预期 | 随拥堵程度波动 |
| 拥堵时表现 | 新呼叫被拒绝（忙音） | 分组排队变慢或被丢弃 |
| 典型代表 | 传统固定电话网 | 互联网 |

## 6.1.2 为什么互联网选了分组交换

计算机通信有一个和打电话很不同的特点：**突发性**。你点开一个网页，几百毫秒内要下载大量数据，然后你读上一分钟，几乎什么都不传。如果为这种流量预留固定通路，大部分时间都在空转。分组交换让许多用户的突发流量在同一条链路上“错峰叠加”，这在网络领域叫**统计复用（Statistical Multiplexing）**。正因为大家不太可能同时满速发送，一条链路才能服务远多于其“平均分摊”能力所能支撑的用户。你家人在刷网页时你还能看视频，靠的正是这一点。

第二个原因是**韧性**。分组交换的思想在 20 世纪 60 年代由保罗·巴兰（Paul Baran）和唐纳德·戴维斯（Donald Davies）等人分别提出，阿帕网随后采用了它。网络里没有一条必须保持畅通的固定线路，某段链路或某台路由器坏了，后续分组可以改走别的路径。第一章讲过互联网是“网络的网络”，分组交换让这件事变得可行：不同网络只要都会处理同样格式的数据包，就能互相转交，不需要事先为每对通信方协调一条贯穿多家运营商的专线。

## 6.1.3 “尽力而为”到底承诺了什么

互联网核心的**网际协议（Internet Protocol，IP）**提供的是**尽力而为（Best Effort）**服务。RFC 791 对 IP 的描述很直白：它不保证可靠送达，不提供端到端的确认、流量控制或顺序保证。换成日常语言，网络对每个数据包只承诺“我会尽量把你送到”，不承诺下面这些事：

- **不保证送达**：路由器缓冲区满了，新来的包可能直接被丢弃；
- **不保证顺序**：先发的包可能走了更慢的路，比后发的包晚到；
- **不保证不重复**：某些异常情况下，同一个包可能出现两份；
- **不保证延迟**：拥堵时排队时间可长可短。

这听起来像是一份“很不负责”的服务合同，但它是有意的设计。中间的路由器只需要做一件简单的事：查表、转发，忙不过来就丢。路由器不记住每一条连接的状态，也不负责补救，因此可以做得快、做得便宜，并且容易扩展到全球规模。

## 6.1.4 可靠性去哪儿了：交给两端

网络不管可靠，那你下载的文件为什么不缺字、网页为什么不乱序？答案是可靠性被推到了通信的**两端**，也就是你的手机电脑和远方的服务器。

| 职责 | 由谁承担 |
|---|---|
| 按地址逐跳转发分组 | 网络中间的路由器（IP 层） |
| 发现丢包并重传 | 两端主机（如 TCP） |
| 把乱序的分组排好 | 两端主机（如 TCP） |
| 根据拥堵情况放慢或加快发送 | 两端主机（拥塞控制） |
| 加密与身份确认 | 两端主机（如 TLS） |

在这种分工下，不同应用可以按自己的需要取舍。下载文件要一字不差，就用**传输控制协议（TCP）**来保证可靠有序；视频通话更在乎及时，丢一两个包宁可跳过也不要等待重传，就可以基于**用户数据报协议（UDP）**自己处理。网络本身保持简单，复杂功能由边缘按需添加。这种思路在第八章会以“端到端原则”的名字再次出现，并说明它的理论依据。

当然，“尽力而为”也有代价。网络对谁都一视同仁，所以高峰期的延迟和丢包难以预先保证。工程上有各种补充办法，比如运营商或企业内部网络中的服务质量（QoS）标记与优先级调度，或者用内容分发网络把内容放得离用户更近，但这些都是在尽力而为的基础上做的局部增强，并没有改变公共互联网的基本模型。

## 6.1.5 小结：一块简单的地基

分组交换解决了“怎样高效共享线路”，尽力而为划定了“网络只负责多少”。两者合起来，就是一个中间简单、两端聪明的系统：路由器快速转发、允许丢包，终端负责补救和调节。理解了这块地基，本章后面的几个机制就有了共同的出发点：TCP 要在一个会丢包、会乱序的网络上造出可靠的连接；BGP 要决定这些分组在各自治系统之间往哪儿走；DNS 和 TLS 则在同一个尽力而为的网络上，解决“找到谁”和“怎样安全地说话”。下一节先看 TCP 怎样完成第一项任务。
