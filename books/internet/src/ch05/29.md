# 5.4 内容流：视频与网页怎样从缓存节点到达你

晚上九点，你在手机上点开一集热门剧，几秒内画面就开始播放；拖动进度条跳到后半段，画面很快又接上。同一时间，城市里可能有大量的人在看同一集。如果每个人都要去千里之外的源站服务器取一份完整的视频，跨城、跨国的线路很快会被占满。前面几节讲了数据包、地址和路由信息怎样流动，这一节看另一种流动：**内容本身**怎样被复制、存放、切分，再从离你最近的地方送到屏幕上。

## 5.4.1 一份内容，多处副本：从源站到边缘节点

网站或视频平台存放原始内容的服务器叫作**源站**（Origin Server）。内容如果只放在源站，所有请求都会跨越很长的网络路径。**内容分发网络**（Content Delivery Network，CDN）的做法是把内容的副本缓存到分布在各地、靠近用户的服务器上，这些服务器通常称为**边缘节点**（Edge Node）。

内容流大致按三层流动：

| 层级 | 位置 | 存放什么 |
|---|---|---|
| 源站 | 平台自己的数据中心或云上 | 全部原始内容 |
| 中间层缓存 | 区域性的大型节点 | 较常被请求的内容 |
| 边缘节点 | 城市机房、运营商网络内部、交换中心附近 | 当地当下最热门的内容 |

可以把它比作物流系统：源站是中央仓库，边缘节点是小区门口的前置仓。热门商品提前放进前置仓，你下单后从楼下送达；冷门商品才需要从中央仓库调货。有些大型内容平台还会把缓存服务器直接放进接入运营商的机房，让流量尽量不离开运营商网络。这属于具体平台与运营商之间的合作安排，并非所有网络都如此。

## 5.4.2 命中与未命中：缓存怎样决定“给不给你”

你的请求到达边缘节点后，会出现两种情况：

- **缓存命中**（Cache Hit）：节点上已经有这份内容，直接返回，路径短、速度快。
- **缓存未命中**（Cache Miss）：节点上没有，或者副本已过期，节点向上一层或源站取回内容，一边交给你，一边留一份副本，供后来的人使用。

所以同一集剧，第一个在本地点开的人可能稍慢一点，后来的人就快了。哪些内容值得留、留多久，主要由两方面决定。一是源站在 HTTP 响应里写的缓存指令，例如 `Cache-Control: max-age=3600` 表示这份内容可以缓存一小时；HTTP 的缓存规则在 RFC 9111 中有定义。二是节点自身容量有限，空间满了就要按一定策略淘汰内容，常见思路是优先淘汰最久没人访问的内容。

缓存也不只在 CDN 里。你的浏览器本身就有缓存：第二次打开同一个网站时，网站标志、样式文件、脚本往往直接从本机读取，根本不上网。内容流的第一站，常常就在你自己的设备里。

## 5.4.3 视频为什么被切成小块

网页由很多小文件组成，视频则是一个大文件。主流的在线视频并不是整部下载，而是被切成长度为几秒左右的**分片**（Segment），并且同一段内容会预先编码成多个清晰度版本。播放器先下载一个**清单文件**（Manifest），里面列出各个分片的地址和可选码率，然后一片一片地请求。

目前常见的两种标准做法是苹果公司提出的 **HLS**（HTTP Live Streaming，规范见 RFC 8216）和国际标准 **MPEG-DASH**（基于 HTTP 的动态自适应流）。它们都用普通的 HTTP 传输分片，因此可以直接利用遍布各地的网页缓存和 CDN，不需要另建专门的视频网络。

切片带来三个好处：

1. **好缓存**：小分片是普通的文件，边缘节点很容易存放和命中。
2. **好拖动**：跳到第 40 分钟，播放器只需请求那一段对应的分片。
3. **好调速**：每一片都可以重新选择清晰度。

## 5.4.4 自适应码率：播放器在“看路况”

第三点就是**自适应码率**（Adaptive Bitrate，ABR）。播放器会持续估计最近几个分片下载得有多快，并观察本地缓冲区里还剩几秒可播放的内容。网络顺畅、缓冲充足时，下一片换成更高清的版本；电梯里信号变差、缓冲快要见底时，就降到较低清晰度，宁可画面模糊一些，也尽量不卡住。

你看视频时偶尔发现画面先糊后清，这通常不是故障，而是播放器在开头保守选择低码率，确认网络状况后再逐步提升。这里能看到一个分工：网络只管尽力把分片送到，判断“该送多大的分片”的工作交给了终端上的播放器。这与第八章要讲的端到端原则一脉相承。

## 5.4.5 小结：内容向用户靠近

把这一节串起来，内容流的路径是：源站生产内容，按规则复制到中间层和边缘节点；你的请求被引导到附近的节点，命中就直接返回，未命中再向上取；视频以分片形式流动，由播放器根据实时网络状况挑选清晰度；浏览器缓存则让一部分内容根本不必出门。

数据包流关心“怎么走”，内容流关心“从哪儿取”。互联网能承受晚高峰的海量观看，很大程度上不是靠把每条线路无限加宽，而是靠让内容提前靠近人。至于用户的请求如何被引导到合适的节点、CDN 如何调度和防护，将在 7.3 节展开。下一节，我们把视角拉远，看这些流动汇聚起来后在一天之内形成怎样的高峰与低谷。
