# 5.3 路由信息流：路由协议怎样交换“地图”

打开手机地图导航，屏幕上那条蓝色路线并不是地图软件凭空想出来的。它背后有一张不断更新的路网：哪条路通、哪条路封、哪里在堵车，都要先汇总起来，导航才能算出路线。互联网也是这样。上一节讲的数据包和 DHCP、NAT、DNS，管的是“我是谁”“你在哪”。可一个数据包从你家出发，要经过十几台甚至几十台路由器，每台路由器凭什么知道下一步该往哪个出口送？答案是：在数据包流动之前和流动的同时，网络里一直还有另一股看不见的流，叫做路由信息流。路由器之间靠它互相交换“地图”。

## 5.3.1 两股流：送货的车与传话的人

我们先分清两件经常被混为一谈的事。

| 对照项 | 数据流（转发） | 路由信息流（选路） |
|---|---|---|
| 流动的是什么 | 网页、视频等用户数据包 | 路由器之间的“哪里可达、怎么走”的消息 |
| 谁来处理 | 路由器的转发部分，速度要求极高 | 路由器的控制部分，由软件计算 |
| 产物 | 把每个包从某个接口送出去 | 一张路由表，以及由它生成的转发表 |
| 类比 | 路上跑的货车 | 交通台不停播报的路况 |

工程上把这两部分称为数据平面（Data Plane）和控制平面（Control Plane）。路由协议（Routing Protocol）就是控制平面上的“传话规则”。路由器通过它告诉邻居自己能到达哪些网络，邻居再把听到的消息整理成自己的路由表（Routing Table），表里每一行大致写着：去往某个地址前缀，从哪个接口出去，下一跳交给谁。数据包到达时，路由器只需查表，不必每次重新思考。

你家的家用路由器其实也有一张路由表，只是内容很简单：本地网段在家里，其他所有地址都交给运营商。这条“其余一律往外送”的规则叫默认路由（Default Route）。在家里一条默认路由就够用，但到了运营商网络和互联网核心，就必须靠路由协议持续交换信息了。

## 5.3.2 网络内部：运营商自己画的详细地图

第四章讲过，互联网是由许多自治系统（Autonomous System，AS）拼起来的，每个自治系统通常是一个运营商、一家大公司或一所大学的网络。在一个自治系统的内部，路由信息流用的是内部网关协议（Interior Gateway Protocol，IGP），常见的有两类做法。

**距离向量（Distance Vector）**：每台路由器只告诉邻居“我到某网络有多远”。邻居在这个数字上加上自己到它的距离，再继续往外传。这好比问路时只听人说“往东走，大约三站”，自己并不知道全貌。早期的 RIP（路由信息协议，Routing Information Protocol，最早规范为 RFC 1058，第二版为 RFC 2453）就是这一类，它以“跳数”计算距离，最大只认 15 跳，因此只适合小网络。

**链路状态（Link State）**：每台路由器把“我连着谁、这条链路代价多少”广播给区域内所有路由器，于是人人手里都有一张完整拓扑图，再各自算出最短路径。OSPF（开放最短路径优先，Open Shortest Path First，RFC 2328）和 IS-IS（中间系统到中间系统协议）属于这一类，是大型运营商和企业网内部的主流选择。

这里只记住一个直觉就够了：距离向量是“听邻居转述”，链路状态是“人人手里一张全图”。它们背后的最短路径算法，第八章 8.3 节会从图论角度细讲。

## 5.3.3 网络之间：只交换“可达”，不交换细节

到了自治系统之间，情况就不一样了。运营商不会把自家网络内部的线路、设备和代价告诉竞争对手，而且全世界的网络细节也多到没有任何路由器装得下。于是自治系统之间用的是边界网关协议 BGP（Border Gateway Protocol，现行版本为 BGP-4，RFC 4271）。

BGP 传递的信息更像一句句“宣告”：“地址前缀 X 可以经过我到达，途经的自治系统依次是 A、B、C。”这串自治系统编号叫 AS 路径（AS_PATH）。收到宣告的一方有三个用处：

- 看路径长短，作为选路的一个参考；
- 如果在路径里发现自己的编号，说明出现了环路，就丢弃这条宣告；
- 结合商业关系做取舍。比如在常见的运营商实践中，同样能到达某个目的地时，往往优先走客户的线路，其次是对等伙伴，最后才是要付费的上游转接。

所以，BGP 选路依据的首先是策略，然后才是“近”。这正对应 4.2 节讲过的对等与转接关系。路由信息流在这一层上，承载的其实是商业合同。

全球所有自治系统宣告汇总起来，形成一张常被称为“全球路由表”的清单。按公开测量资料的常见说法，写作时其中 IPv4 前缀在百万条这个数量级，IPv6 前缀也有数十万条，而且还在逐年增长。互联网核心路由器的内存和查表芯片，很大一部分就是为装下这张表准备的。

## 5.3.4 地图会变：收敛与“传错话”

路况会变，网络也会变：光缆被挖断、设备重启、新的网站上线。路由信息流因此从不停止。链路一断，相关路由器会发出更新或撤销消息，消息逐跳扩散，直到所有路由器重新得出一致的结论。这个过程叫收敛（Convergence）。在收敛完成之前，部分数据包可能绕远路、在两台路由器之间来回打转，或者直接丢失。你偶尔遇到网页“卡了几秒又好了”，有时就是某处路由正在收敛。

更值得警惕的是“传错话”。BGP 设计之初默认各方都说真话，假如某个网络误把别人的地址前缀宣告成自己的，邻居可能信以为真并继续转告，结果一大片流量被引到错误的地方。这类事件叫路由泄露或路由劫持，历史上多次造成知名网站在部分地区无法访问。业界的防范办法之一是 RPKI（资源公钥基础设施，Resource Public Key Infrastructure），它用数字证书证明“谁有权宣告哪个前缀”，收到宣告的路由器就能据此做来源验证。具体机制留到 6.3 节展开。

## 5.3.5 小结：先有地图，才有路

把这一节放回整本书的骨架里看：数据包能找到路，前提是路由器手里已经有地图；地图则是靠路由信息流一点点拼起来、不断修补的。在自治系统内部，IGP 追求快速准确地找出最短路；在自治系统之间，BGP 传递可达性和商业策略。两者叠加起来，才让你按下回车时，请求能穿过陌生的网络到达目的地。地图画好了，下一节就来看真正的“货物”：视频和网页内容怎样从离你最近的缓存节点送到眼前。
