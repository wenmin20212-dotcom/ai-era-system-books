# 5.2 地址与名字流：DHCP、NAT 与 DNS 查询

早上打开笔记本电脑，它自动连上家里的 Wi-Fi，几秒后浏览器就能打开网页。整个过程你没有填写过任何地址。可是上一节讲过，每个数据包都要写明“从哪里来、到哪里去”。电脑开机前并没有地址，它也不知道网页服务器在哪。这些信息是在你按下回车之前，靠一组看不见的“地址与名字流”临时取得的。它们主要由三件事完成：DHCP 发地址，NAT 换地址，DNS 查地址。

## 5.2.1 DHCP，给新来的设备“发门牌”

动态主机配置协议（Dynamic Host Configuration Protocol，DHCP，现行 IPv4 版本以 RFC 2131 为基础）的作用，可以比作酒店前台给入住的客人分配房间。设备连上网络时，和前台之间通常要交换四条消息，人们按英文首字母记作“DORA”：

| 步骤 | 消息 | 类比 |
|---|---|---|
| 1 | Discover（发现） | 客人在大堂喊：“有前台吗？” |
| 2 | Offer（提供） | 前台答：“308 号房可以给你。” |
| 3 | Request（请求） | 客人说：“好，我要 308。” |
| 4 | Acknowledge（确认） | 前台登记：“308 归你，住 24 小时。” |

第一条消息是用广播发出的。新设备还没有地址，也不知道前台在哪，只能对整个局域网“喊一声”。在家庭网络里，回答它的前台一般就是无线路由器。

前台发给设备的不只是一个地址。一份典型的 DHCP 回复通常包括四项内容：

- **本机 IP 地址**，例如 192.168.1.23；
- **子网掩码**，用来判断哪些地址算“同一个局域网”；
- **默认网关**，即发往外网的数据包先交给谁，通常就是路由器本身；
- **DNS 服务器地址**，即以后去哪里查名字。

地址还有“租期”（lease）。租期快到时，设备会主动续租。设备离开网络后不再续租，到期的地址就收回给别人用。正因为有租期，咖啡馆里人来人往，地址池也不会被占满。

在电脑的网络设置里，或在手机 Wi-Fi 详情页中，一般能看到这四项信息。它们就是这次“入住登记”的结果。

## 5.2.2 NAT，私有门牌与公共门牌的转换

你会发现，家里各台设备的地址大多以 192.168 或 10 开头。这些属于 RFC 1918 规定的**私有地址**，只在局域网内部有效。全世界无数家庭都在重复使用同一批私有地址，所以它们不能直接出现在公网上。

解决办法是网络地址转换（Network Address Translation，NAT）。这件事通常也由家里的路由器完成。可以把它想成一栋公寓的收发室：

1. 手机（192.168.1.23）发出一个请求，源端口假设为 50000；
2. 路由器把源地址改成运营商分配给它的公网地址，并换一个自己选定的端口，比如 62001；
3. 路由器在“转换表”里记下对应关系：62001 对应 192.168.1.23 的 50000；
4. 服务器的回复到达 62001 端口后，路由器查表，把它改回去，交给手机。

靠着端口来区分，一个公网地址可以同时服务全家几十个连接。这种做法常被称为 NAPT 或 PAT。它在 IPv4 地址紧缺的年代缓解了“门牌不够”的问题，代价是外部主机难以主动连进内网，这给点对点通信带来了麻烦，第 4.3 节已经提到。有些运营商还会在自己的网络里再做一层 NAT，业内称为运营商级 NAT（CGN）。这时你路由器拿到的“公网地址”其实也是运营商内部的地址。具体是否采用 CGN，因运营商和地区而异。第 7.1 节将讲到，IPv6 地址空间足够大，从设计上就不再依赖 NAT。

## 5.2.3 DNS 查询，把名字换成地址

现在设备有了地址，也知道了出口。浏览器拿到的却只是一个名字，比如 www.example.com。于是它要通过域名系统（Domain Name System，DNS）把名字换成 IP 地址。这次查询本身就是一股小小的数据流：

- 浏览器和操作系统先查**本地缓存**，最近查过就直接用；
- 缓存里没有，就把查询发给 DHCP 告知的 DNS 服务器。在家庭网络中，这常常是路由器转交给运营商的**递归解析器**。用户也可以手动改成公共 DNS 服务；
- 递归解析器如果也没有缓存，就去逐级询问根、顶级域和权威服务器。这一层级过程留到第 6.4 节细讲；
- 答案附带“生存时间”（TTL），在规定时间内各级缓存可以直接复用。

传统 DNS 查询多用 UDP 端口 53，以明文传输。近年来出现了 DNS over HTTPS（DoH，RFC 8484）和 DNS over TLS（DoT，RFC 7858）等加密方式，写作时主流浏览器和操作系统都已提供相关选项。加密的目的是防止查询内容在途中被窥视或篡改。

## 5.2.4 把三股流串起来

按时间顺序排列，打开第一个网页之前的“准备流”大致是这样的：

| 阶段 | 流向 | 得到什么 |
|---|---|---|
| DHCP | 设备 ↔ 路由器（局域网内） | 本机地址、网关、DNS 服务器 |
| DNS | 设备 → 路由器 → 解析器 → 各级服务器 | 目标服务器的 IP 地址 |
| NAT | 每个出入家门的包都经过路由器 | 私有地址与公网地址的互换 |

注意它们的范围各不相同。DHCP 只在“一栋楼”里流动。NAT 守在“楼门口”，每个包都要经过它。DNS 则可能一路问到地球另一端。

排查时，这三步也是最常见的断点：

- 设备显示“已连接但无法上网”，地址却是 169.254 开头，多半是 DHCP 没拿到地址；
- 能用 IP 地址访问网页、却打不开域名，往往是 DNS 出了问题；
- 某些联机游戏或视频通话提示“NAT 类型严格”，则与地址转换有关。

地址与名字就位后，数据包才知道要往哪个方向走。至于路由器之间怎样交换“地图”、决定具体走哪条路，是下一节路由信息流要讲的内容。
