# 5.1 数据包流：一个网页请求的完整旅程

在地址栏里敲下一个网址，按回车，不到一秒，页面开始一块块出现。第一章曾用“一秒钟里发生了什么”给出过粗略的轮廓，第三、四章又分别讲了地址、路由、分层和运营商互联。本节换一个视角：不看设备，也不看协议名称，而是把目光盯在“数据包”本身，跟着它从你的手机出发，到达远方的服务器，再带着网页回来。你会发现，所谓“上网”，本质上是一串串数据包在系统中的流动。

## 5.1.1 出发之前：数据包是怎样“打包”出来的

假设你在家里用电脑访问一个使用 HTTPS 的网站。浏览器要发出的第一句“话”，可能只是一行请求：“请把首页给我”。但这句话不能直接扔进网线，它要经过一层层封装（encapsulation），就像寄快递时把物品装进盒子、再贴面单、再装进集装箱：

| 层次 | 加上的“包装” | 主要写了什么 |
|---|---|---|
| 应用层 | HTTP 请求（再经 TLS 加密） | 要哪个页面、浏览器信息等 |
| 传输层 | TCP 头部或 UDP 头部 | 源端口、目的端口、序号等 |
| 网络层 | IP 头部 | 源 IP 地址、目的 IP 地址、生存时间 |
| 链路层 | 以太网或 Wi-Fi 帧头 | 本段链路上下一跳设备的硬件地址 |

一个要点值得记住：**IP 头部里的地址从头到尾基本不变（经过家庭路由器的地址转换除外），而链路层的“面单”每过一跳就要撕掉重贴。** 这就是“端到端”的网络层和“一段一段”的链路层之间的分工。

另外，一次网页请求不会只产生一个包。互联网上常见的以太网链路，单个包承载的数据一般在 1500 字节量级（这是最常见的最大传输单元 MTU，Maximum Transmission Unit，即一个包最多能装多少）。一个普通网页连同图片、脚本，往往有几百 KB 到数 MB，需要成百上千个包才能运完。

## 5.1.2 去程：从家门口到服务器门口

我们按顺序追踪第一个真正携带请求的数据包（假设域名解析已完成，这部分留到 5.2 节细讲）：

1. **电脑 → 家庭路由器**。数据包先经 Wi-Fi 或网线到达路由器。路由器做了一件特别的事：把包里的私有源地址（如 192.168.x.x）换成运营商分给你家的公网地址，并记下对应关系。这就是网络地址转换（NAT，Network Address Translation）。
2. **路由器 → 光猫 → 接入网**。光猫把电信号转换成光信号，送进入户光纤，汇聚到运营商的局端设备，再进入城域网。
3. **城域网 → 骨干网**。运营商的路由器逐跳查转发表，决定下一站。每经过一台路由器，IP 头部里的“生存时间”（TTL，Time To Live）减一，防止包在环路里无限打转。
4. **跨网互联**。如果网站不在你所用运营商的网络里，包要在互联网交换中心或私有互联点交给另一张网络，这一步由第四章讲过的自治系统之间的商业关系与 BGP 路由共同决定。
5. **到达服务器门口**。如今很多网站把内容放在内容分发网络（CDN）上，所以包真正抵达的，常常是离你较近城市里的一台缓存服务器，而不是网站总部的机房。

整个去程可能经过十几到二十多跳，这是公开测量中的常见范围，具体取决于你所在的地区和目标位置。你可以用第七章将介绍的 traceroute 工具亲眼看到这些跳。

## 5.1.3 回程：网页怎样“拆开”送回来

服务器收到请求后，把网页内容切成许多段，每段各自封装成包发回。这里有三个容易被忽视的事实：

- **回程路径不一定等于去程路径。** 各运营商按自己的策略选路，往返走不同的线路是常态，称为路径不对称。
- **包可能乱序、丢失。** 互联网采用“尽力而为”的交付方式，路由器排队满了就会丢包。TCP 用序号和确认机制把乱序的包重新排好，把丢失的包要求重传；在使用 QUIC 的 HTTP/3 中，这部分工作由运行在 UDP 之上的 QUIC 协议完成。
- **回到家门口还要“翻译”一次。** 家庭路由器查找之前记下的 NAT 对应表，把目的地址改回你电脑的私有地址，再送到电脑上。电脑逐层拆包，最终把 HTML 交给浏览器。

## 5.1.4 一个页面，是许多条“流”叠在一起

浏览器拿到首页 HTML 后，会发现里面引用了样式表、脚本、图片、字体，它们可能来自不同域名、不同服务器。于是浏览器同时开出多个请求，形成多条并行的数据包流。按下回车后的一秒里，你的电脑可能和若干台服务器同时保持着连接。

可以用一个类比来理解：首页就像一张菜单，浏览器看完菜单后，同时向几家后厨下单，各家的菜由不同的外卖员沿不同的路送来，最后在你的桌上拼成一桌宴席。哪一家慢了，页面上就会有一块迟迟不出现——这正是“页面加载卡在一半”的常见来源。

| 阶段 | 包的流向 | 典型耗时来源 |
|---|---|---|
| 建立连接 | 电脑 ⇄ 服务器 | 往返时延、握手次数 |
| 请求首页 | 电脑 → 服务器 | 上行链路、排队 |
| 返回内容 | 服务器 → 电脑 | 带宽、丢包与重传 |
| 加载子资源 | 多路并行 | 域名数量、服务器远近 |

## 5.1.5 小结：把“上网”看成流动

沿着一个数据包走一遍，我们看到了本书前几章拼起来的整幅画面：终端负责封装与拆包，家庭路由器负责地址翻译，接入网和骨干网负责一跳跳转发，自治系统之间负责交接，CDN 负责就近供货，TCP 或 QUIC 负责把零散的包重新整理成完整的内容。每个部分只做好自己那一小段，整体却能把千里之外的网页送到你眼前。

不过，数据包能走对路，前提是它“知道”目的地址，路由器“知道”往哪里转。这两种“知道”本身也是在网络中流动的信息。下一节，我们先看地址与名字是怎样流动的：DHCP 怎样给你的设备发地址，NAT 怎样记账，DNS 查询又怎样一路问到答案。
