# 3.6 本章骨架小结与实物探索任务

按下回车之后，浏览器要先知道"去哪里"，再知道"怎么去"，还要保证"送到了、没送错"，最后才是"送来的东西怎么用"。本章五节依次回答了这四个问题：寻址、命名、转发与路由、可靠传输、应用服务。这五项功能落在第二章拆开的各个部件上，网页才得以出现在屏幕上。本节先把这五项功能串成一副骨架，再请你在自己的设备上把它们逐一找出来。

## 3.6.1 本章骨架：五项功能，一条主线

把一次网页访问看成一次寄快递，五项功能大致对应如下：

| 功能 | 回答的问题 | 核心概念 | 快递类比 |
|---|---|---|---|
| 寻址 | 数据送给哪台设备、哪个程序 | IP 地址、端口号 | 收件地址与门牌号 |
| 命名 | 人记得住的名字怎样变成地址 | 域名系统（DNS）、递归解析、缓存 | 查通讯录 |
| 转发与路由 | 每一跳往哪里走 | 路由表、最长前缀匹配、逐跳转发 | 分拣中心按目的地分拣 |
| 可靠传输 | 丢了怎么办、堵了怎么办 | 序号、确认、重传、拥塞控制 | 签收回执、丢件补寄、按路况控制发车 |
| 应用服务 | 收到之后怎样理解和使用 | HTTP、邮件协议、即时通信、视频分片 | 包裹里的内容与说明书 |

这五项功能有几条要点：

- **地址负责定位，名字负责好记。** IP 地址标出网络里的一台设备（准确地说是一个网络接口），端口号再区分这台设备上的不同程序。域名只是给人用的"别名"，真正通信前必须经由 DNS 换成地址。
- **路由器只管下一跳。** 没有哪台路由器掌握完整路径。每台路由器只查自己的路由表，把数据包交给离目的地"更近一步"的邻居。全局路径是由大量局部决定拼出来的。
- **网络本身不保证送达。** IP 层只尽力而为，丢包、乱序、重复都可能发生。传输控制协议（TCP）在两端的主机上用序号、确认和重传补上可靠性，又用拥塞控制让众多发送方在拥堵时主动减速。
- **应用决定体验。** 网页、邮件、即时通信、视频对时延、可靠性和带宽的要求各不相同，所以它们选用不同的协议组合。例如视频会按小段分片传输，并根据网速切换清晰度。
- **功能分工，彼此依赖。** 没有寻址，路由无从谈起；没有命名，人很难使用网络；没有可靠传输，网页就会残缺；没有应用协议，收到的只是一串字节。

这五项功能分别属于哪一"层"，层与层之间怎样衔接，正是第四章"分层模型"要解决的问题。

## 3.6.2 实物探索任务

以下任务只需要一台电脑或手机和家里的网络，只用于观察自己的设备，不涉及他人的系统。

1. **找出你的两种地址。** 在手机的 Wi-Fi 详情页，或电脑的网络设置（Windows 可在命令提示符里输入 `ipconfig`，macOS 可在"系统设置—网络"中查看）里，记下本机 IP 地址和"路由器/网关"地址。再用搜索引擎搜"我的 IP"，看网页显示的地址是否和本机地址一样。想一想两者为什么不同（提示：家庭路由器做了地址转换，第五章会详细讲）。
2. **观察一次域名解析。** 在电脑上运行 `nslookup` 加一个常用网站的域名，看返回了几个地址，是 IPv4 还是 IPv6。隔几分钟再查一次，或换到手机流量网络下再查，对比结果是否变化，并记录下来。
3. **数一数路上有几跳。** Windows 用 `tracert`，macOS 用 `traceroute`，加同一个域名运行一次。数一数经过了多少跳，哪几跳时延明显变大，哪些行显示星号。星号通常表示该路由器不回应探测报文，不一定是故障。
4. **看看网页用了哪些协议。** 用电脑浏览器打开一个网站，按 F12 打开开发者工具，切到"网络（Network）"面板后刷新页面。观察一个页面发出了多少个请求，"协议"一列里出现了哪些版本（如 h2、h3），哪些资源来自其他域名。
5. **感受拥塞控制。** 在家里一台设备上看高清视频，同时让另一台设备下载大文件。留意视频清晰度是否自动降低、缓冲是否增多，停止下载后多久恢复。用本章的"可靠传输"和"应用服务"两节解释你看到的现象。

建议把结果记在同一页纸上，按"地址—名字—路径—传输—应用"五栏排列，这就是你家网络的第一份"功能档案"。

## 3.6.3 可以直接拿去问 AI 的问题

把上面任务的输出结果复制给 AI 时，请先删掉公网 IP 等可能涉及隐私的信息，再提问：

- "这是我电脑上 traceroute 的输出结果，请逐行解释每一跳大概位于哪里（家里、运营商、还是对方网络），哪几跳的时延变化值得注意，星号代表什么。"
- "同一个域名，我在家里宽带和手机流量下用 nslookup 查到的地址不一样，可能有哪些原因？这和内容分发网络有什么关系？"
- "请用一个中学生能听懂的比喻，说明 IP 地址、端口号、域名三者的区别，再指出这个比喻在哪些地方不准确。"

AI 的回答可能会有错误。遇到关键结论时，回头对照本章内容，或查阅对应的 RFC 文档进行核实。

## 3.6.4 承上启下

本章讲的是"每个部分做什么"。下一章转向"各部分怎样连接"：五项功能怎样按层叠放，成千上万个运营商网络怎样通过对等与转接互相连通，谁来分配地址、管理域名。从功能走到关系，你手里的这张骨架图会多出一个维度。
