# 3.3 转发与路由：数据包怎样找到路

在家里打开电脑的命令行，输入一条 traceroute（Windows 上叫 tracert）命令，后面跟上一个常去的网站域名，屏幕上会一行一行地跳出十几个地址：第一行通常是家里路由器的地址，比如 192.168.1.1；接下来是运营商机房里的设备；再往后，地址越来越陌生，有的行还只显示几个星号。每一行就是数据包在路上经过的一台路由器，网络里把这样一步叫作“一跳”（hop）。

一个数据包从你的电脑出发，到达几百甚至几千公里外的服务器，途中要经过十几台这样的设备。没有哪一台路由器知道整条路线，每一台只决定“下一步交给谁”。这一节要讲清楚的，就是这种逐跳接力是怎样运作的。

## 3.3.1 两件事：转发与路由

谈论“数据包怎样找到路”，工程上会把它拆成两件不同的事：

| | 转发（Forwarding） | 路由（Routing） |
|---|---|---|
| 要回答的问题 | 这个包现在从哪个接口送出去？ | 去往各个目的地，整体上该怎么走？ |
| 时间尺度 | 每个包都要做，以纳秒到微秒计 | 网络变化时才更新，以秒到分钟计 |
| 依据 | 查一张已经算好的表 | 与其他路由器交换信息，计算路径 |
| 类比 | 司机在路口看路牌转弯 | 交通部门测绘道路、制作路牌 |

打个比方：转发像路口的司机，看一眼路牌就打方向盘，不用思考全局；路由像幕后测绘和立牌子的人，路修好了、路断了，他们负责改牌子。工程上常把前者称为“数据平面”，后者称为“控制平面”。高端路由器里，转发由专门的芯片完成，路由计算由处理器上的软件完成，两者分开工作，这也是一台路由器能每秒处理海量数据包的原因之一。

## 3.3.2 路由表：路口的那块路牌

每台路由器里都有一张路由表（routing table），每一条记录大致包含三样东西：目的网络、下一跳地址、从哪个接口送出。所谓“目的网络”，不是一个个具体地址，而是一段地址范围，用讲 IP 地址时介绍过的前缀来表示，比如 203.0.113.0/24 代表以 203.0.113 开头的 256 个地址。

一台家用路由器的路由表很简单，大致只有两类记录：

- 目的是家里局域网（例如 192.168.1.0/24）的，直接从内网口送给对应设备；
- 其余一切目的地，都交给运营商那一侧的设备。

第二条叫作默认路由（default route），写作 0.0.0.0/0，意思是“不认识的都往这儿送”。家里的路由器、你的手机和电脑，靠一条默认路由就能把包送进互联网，它们不需要知道世界的样子。

越往网络深处走，路由表越大。处在互联网核心、不依赖默认路由的路由器，要记住全球所有对外公布的地址前缀。根据公开的路由统计资料，写作时 IPv4 的全球路由表已在百万条这一数量级。

## 3.3.3 最长前缀匹配：选最具体的那条

一个目的地址常常同时落在好几条记录的范围里。比如表中有 203.0.0.0/8 和 203.0.113.0/24 两条，而目的地址是 203.0.113.25，两条都匹配。规则是：选前缀最长、也就是范围最小、最具体的那一条，这叫最长前缀匹配（longest prefix match）。

这和寄信的道理相同：信封上写着“某省某市某区某街道”，分拣员会优先按最细的那一级投递，而不是只看省份。默认路由 0.0.0.0/0 前缀长度为零，任何地址都匹配它，但它永远是最后的选择，只在没有更具体的记录时才被使用。

查到记录之后，路由器还要做几件小事：把包头里的“生存时间”（TTL，Time To Live）减一，减到零就丢弃这个包并通知发送方，防止包在网络里无限兜圈；然后按出接口所在链路的要求重新封装，比如换上下一跳设备的硬件地址，把包送出去。开头那条 traceroute 命令，正是巧妙利用了 TTL：依次发出 TTL 为 1、2、3……的探测包，让每一跳路由器在丢包时“报上名来”，于是你看到了一条路径。看到星号也不必紧张，那多半只是某台路由器被设置为不回应这类探测。

## 3.3.4 路由表从哪里来

路牌不会凭空出现。路由表的记录主要有三种来源：

1. **直连路由**：路由器接口上配置了哪个网段，它就自动知道这个网段在哪儿。
2. **静态路由**：由管理员手工写入，家用路由器的默认路由多半就是这样，或者由运营商自动下发。
3. **动态路由**：由路由协议（routing protocol）在路由器之间自动交换信息算出来。

动态路由是互联网能够自我适应的关键。网络规模大到一定程度，人工维护不可能跟上变化；某条光缆被挖断时，相邻路由器通过协议察觉，几秒到几分钟内重新算出绕行路线，用户最多感到一阵卡顿。

路由协议大体分成两类。在一个运营商或一家机构自己管理的网络内部，用内部网关协议，常见的有 OSPF（开放最短路径优先）和 IS-IS，它们追求的是在已知的网络地图上找最短、最快的路。在不同机构的网络之间，用的是边界网关协议 BGP（Border Gateway Protocol），它首先要遵守的不是“最短”，而是各家网络之间的商业协议与管理策略。为什么会有这两种逻辑、BGP 又为何被称为互联网的“脆弱点”，我们会在第四章的自治系统、第五章的路由信息流和第六章的 BGP 机制中逐层展开；最短路径算法背后的图论原理，则留给第八章。

## 3.3.5 小结：没有全局指挥的接力

回头看那十几行 traceroute 输出，可以这样理解：每一行背后都是一台只看包头、只查一张表、只管下一步的路由器；表里的内容，则由路由协议在后台持续维护。整个互联网没有一个总调度中心，全局路径是无数局部决定接力出来的结果。这种设计让网络可以不断扩大、局部故障可以被绕开，代价是路径并不总是最优，也会受到错误路由信息的影响。

数据包找到了路，却不能保证一路平安：路由器会排队，队列满了会丢包，不同的包可能走不同的路而先后错乱。怎样在这样一张“尽力而为”的网上实现可靠传输，是下一节要回答的问题。
