# 2.5 服务器、数据中心与内容分发网络

在视频网站上点开一部电影，几秒钟内画面就开始播放；在购物应用里刷新首页，成百上千张商品图片一齐出现。我们习惯说“数据在云端”，可“云”不是天上的东西。它落在地面上一排排机柜里的服务器中，也落在离你家只有几十公里的缓存节点里。前面几节沿着网线从你的手机一路走到了骨干网和海底光缆，这一节走到旅程的另一头，看看网页和视频最初从哪里出发。

## 2.5.1 服务器：一台“专门回答问题”的计算机

服务器（Server）的含义要从角色上去理解，与长相关系不大。你的手机发出请求，问“请把这个网页给我”；服务器收到请求，找到或生成对应内容，再把它发回来。发出请求的一方叫客户端（Client），负责应答的一方叫服务器。第四章会专门讨论这种客户端与服务器的关系，这里先看它的物理形态。

从原理上说，一台普通笔记本电脑装上网页服务软件，也能当服务器。真正用于提供互联网服务的机器为长期运行做了专门设计：

| 对比项 | 家用电脑 | 典型服务器 |
|---|---|---|
| 外形 | 台式机箱或笔记本 | 扁平的机架式机箱，插在标准机柜里 |
| 运行方式 | 用时开机，用完关机 | 通常全年不间断运行 |
| 显示器与键盘 | 必备 | 一般不接，靠网络远程管理 |
| 电源、硬盘 | 通常各一套 | 常配冗余电源，硬盘做冗余阵列 |
| 网络连接 | 一个网口或 Wi-Fi | 多个高速网口，接入机房交换网络 |

一个大型网站背后很少只有一台服务器。用户发来的请求会先到达负载均衡器（Load Balancer），由它把请求分摊给后面许多台功能相同的服务器。这和银行大厅的叫号机类似：顾客不用自己挑窗口，叫号机把人分到空闲的柜台。哪台服务器出了故障，负载均衡器就不再给它派活，用户一般察觉不到。

## 2.5.2 数据中心：服务器集中居住的“大楼”

成千上万台服务器需要电力、散热和网络，把它们集中放在一起最经济，这样的设施叫数据中心（Data Center）。走进一座数据中心，能看到几样基础要素：

- **机柜与服务器**：一排排标准机柜，每个机柜里叠放着几十台服务器。
- **供电系统**：市电之外配有不间断电源（UPS）和备用发电机，停电时也能维持运行。
- **制冷系统**：服务器发热量大，常见做法是把机柜排成“冷通道”和“热通道”，冷风从正面吸入，热风从背面排出，再由空调或液冷系统带走热量。
- **网络系统**：机柜顶部的交换机把服务器连起来，再逐级汇聚，最后通过多条高速线路接入一家或几家运营商的骨干网，有的还直接接入互联网交换中心。

最后一点与本书主线关系最密切。数据中心本身就是互联网的一个重要节点，它对外连接的线路越多、越靠近骨干网，访问它的速度就越有保障。上一节讲的海底光缆登陆站附近、大城市的交换中心周围，常常聚集着大型数据中心，原因就在这里。

人们常说的“云计算”，可以粗略理解为：云服务商建好数据中心，把计算、存储和网络能力按需出租给企业和开发者。许多网站并不自己盖机房，而是把服务器“租”在云上。数据中心内部的网络架构、云计算的资源调度，在本系列另有专册详细展开，本书只关注它们怎样接入互联网。

## 2.5.3 距离的代价：为什么只有中心还不够

假设一个视频网站只在一个城市建了数据中心，全国乃至全球的用户都到那里取数据，会遇到两个问题。

第一是**时延**。光在光纤中的传播速度大约是每秒二十万公里，即真空光速的三分之二左右。跨越几千公里，单程就要花去几十毫秒；跨洋往返可达一两百毫秒。网页加载往往要来回许多次，这些毫秒会累加起来，变成用户能感受到的等待。

第二是**拥挤**。一部热门剧集上线，同一段视频被千万人同时请求，如果都从同一个出口送出去，数据中心的出口带宽和沿途的骨干链路都会不堪重负。

更合理的办法是把东西放到离用户近的地方，这就是内容分发网络的出发点。

## 2.5.4 内容分发网络：把内容“提前搬到你家门口”

内容分发网络（Content Delivery Network，CDN）是分布在许多城市、许多运营商网络中的一批缓存服务器，它们组成一张覆盖广泛的网。网站把原始内容放在源站（Origin Server），CDN 把其中经常被访问的部分复制到各地的边缘节点（Edge Node）上。你请求一张图片或一段视频时，系统把你引导到离你近、负载又不太重的那个节点，由它就近交付。

这和连锁超市的仓储体系很相似：

| 超市体系 | 内容分发网络 |
|---|---|
| 厂家总仓 | 源站 |
| 各地区域配送中心 | 区域缓存节点 |
| 小区门口的门店 | 边缘节点 |
| 顾客就近购买 | 用户就近获取内容 |
| 门店缺货时向配送中心补货 | 节点未命中时回源站取内容 |

用户怎样被“引导”到最近的节点？常见方法之一是借助域名系统：同一个网址，不同地方的用户查询时可能得到不同节点的地址。另一种方法叫任播（Anycast），许多节点对外宣告同一个 IP 地址，由路由系统把用户的数据包自然送往路径上较近的那一个。这两种机制要等读者学过第三章的寻址、命名与路由之后才更好理解，第七章会专门回到 CDN 的技术细节。

CDN 最适合分发图片、视频、脚本文件这类“很多人要同一份”的静态内容。每个用户各不相同的内容，比如你的购物车、你的私信，通常仍要回到源站或业务服务器去生成。写作时的公开资料普遍显示，视频、软件更新和大型网站的静态资源中，经由 CDN 交付的占了相当大的比重。CDN 既有专门的服务商提供，也有大型互联网公司自建，还有运营商在自己网络内部部署缓存节点，具体做法因公司而异。

## 2.5.5 把三者放回一张图里

现在可以把旅程的终点补完整了：

```
你的手机 → 家庭网络 → 接入网 → 城域网/骨干网
        → (大多数情况) 附近的 CDN 边缘节点
        → (节点没有时) 回到数据中心里的源站服务器
```

服务器是回答请求的个体，数据中心是服务器集中运行的基础设施，内容分发网络则把数据中心的内容分散铺到离用户更近的地方。三者合起来，解决的是同一个问题：在几十亿用户同时上网的情况下，内容既要放得稳，又要送得快。
