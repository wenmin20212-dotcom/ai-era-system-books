# 7.1 IPv6：地址不够用之后

打开手机的“设置”，进入当前 Wi-Fi 或移动网络的详情页，往下翻一翻，很多人会看到两类地址：一类是熟悉的“192.168.1.23”这种四段数字，另一类则长得古怪，像“240e:3a1:xxxx:xxxx::1”，由冒号隔开、夹杂着字母。后者就是 IPv6 地址。它的出现，起因很朴素：原来的地址不够分了。

## 7.1.1 四十多亿为什么不够

第三章讲过，今天最常见的 IP 地址是第四版互联网协议（Internet Protocol version 4，IPv4）定义的，长度 32 位，理论上约有 43 亿个。上世纪七八十年代设计时，这个数字看起来绰绰有余，因为当时联网的主要是大学和研究机构的大型计算机。

后来的事大家都知道了：个人电脑、手机、平板、智能电视、摄像头、手环……每个人身边可能就有好几台联网设备，全球联网设备的数量级早已超过几十亿。更麻烦的是，地址并不能百分之百用满，早期分配又比较宽松，大量地址块分给了少数机构。负责全球地址分配的互联网号码分配机构（IANA）在 2011 年把最后一批 IPv4 大块地址分给了五个区域互联网注册管理机构（RIR），此后各区域陆续进入“只能按严格政策分配少量剩余地址”的阶段。

面对枯竭，工程界有两条路：

| 思路 | 做法 | 代价 |
|---|---|---|
| 省着用 | 网络地址转换（NAT），让一屋子、甚至一个小区的设备共用一个公网地址 | 外部难以主动连进来，点对点应用变复杂，运营商级 NAT 增加设备和排障负担 |
| 扩容量 | 换用地址更长的新协议 IPv6 | 需要终端、路由器、服务器、应用全链条升级 |

第五章介绍的 NAT 属于第一条路，它确实帮互联网撑过了很多年，但本质是“打补丁”。IPv6 走的是第二条路。

## 7.1.2 IPv6 地址长什么样

第六版互联网协议（IPv6）的核心规范是 RFC 8200，地址结构见 RFC 4291。最直观的变化是地址长度从 32 位变成 128 位，可用数量约为 3.4×10³⁸，这是一个大到难以想象的数，“给地球上每粒沙子分一个地址都用不完”是科普中常见的形容。

128 位如果写成十进制太长，所以 IPv6 用十六进制，每 16 位一组，共 8 组，用冒号分隔，例如：

`2001:0db8:0000:0000:0000:0000:0000:0001`

为了好写，有两条省略规则：每组开头的 0 可以省略；连续若干组全 0 可以用一个“::”代替，但一个地址里只能用一次。于是上面的地址可以简写为 `2001:db8::1`。（以 2001:db8 开头的地址段是标准专门留给文档和示例用的，不应在真实网络中使用。）

一个 IPv6 地址通常分为两半：前 64 位是“网络前缀”，由运营商分配，相当于小区和楼栋号；后 64 位是“接口标识”，标出这台具体设备，相当于门牌号。家里的光猫或路由器往往会从运营商拿到一整段前缀，再分给屋里每台设备，每台都能有自己的公网地址。

## 7.1.3 不只是加长：设计上的几处改进

如果 IPv6 只是把地址写长，就不值得花这么大力气升级。设计者借这次机会，还做了几处结构性调整：

- **首部更简洁、长度固定。** IPv4 首部长度可变，字段较多；IPv6 基本首部固定 40 字节，可选功能放进“扩展首部”，路由器处理起来更规整。
- **路由器不再分片。** IPv4 中，包太大时途中路由器可以把它切开；IPv6 把这件事交给发送端，路由器发现包太大就丢弃并回一条消息，由发送端调整大小。这体现了第八章将讨论的“把复杂留在端点”的思路。
- **地址可以自己配。** 无状态地址自动配置（SLAAC，RFC 4862）让设备听到路由器广播的前缀后，自己拼出完整地址，不一定需要 DHCP 服务器。出于隐私考虑，现在的主流操作系统通常会生成随机、定期更换的临时地址（RFC 8981），避免用固定的后半段在网上被长期追踪。
- **用邻居发现代替 ARP。** 在同一个局域网里找邻居的硬件地址，IPv6 改用基于 ICMPv6 的邻居发现协议（NDP）。

需要说清楚的是：IPv6 并没有让网络“天然更安全”或“天然更快”。加密靠的仍是第六章讲的 TLS；速度取决于路径、拥塞和服务器位置。有了公网地址，反而更要依靠路由器上的防火墙，默认拦住外部主动发起的连接——主流家用路由器大多已这样设置，读者可以在管理页面里确认一下。

## 7.1.4 新旧怎样共存

IPv4 和 IPv6 的首部格式互不兼容，一台只懂 IPv4 的设备无法直接和只懂 IPv6 的设备说话。整个互联网不可能某天统一停机切换，所以过渡期会很长，常见做法有三类：

1. **双栈**：设备同时拥有 IPv4 和 IPv6 地址，两套并行。今天大多数手机和电脑就是这样。浏览器查 DNS 时会同时请求 A 记录（IPv4 地址）和 AAAA 记录（IPv6 地址），并用“快乐眼球”（Happy Eyeballs，RFC 8305）机制让两种连接竞速，谁先通用谁，避免用户因某一边故障而干等。
2. **隧道**：把 IPv6 包装进 IPv4 包里，穿过只支持 IPv4 的一段网络，像把小箱子装进大箱子运输。
3. **翻译**：例如 NAT64 配合 DNS64，让只有 IPv6 的终端也能访问只有 IPv4 的网站。一些移动运营商在其网络中采用了这类方案。

至于部署进度，各国、各运营商差别很大。按公开的测量统计（例如大型网站或研究机构发布的 IPv6 访问比例），写作时全球已有相当一部分用户流量经由 IPv6，部分国家的比例已超过一半；中国近年也在政策推动下大规模部署，移动网络和家庭宽带普遍已支持。具体比例变化很快，读者可以搜索相关机构发布的最新统计。

## 7.1.5 回到你的手机

现在再看设置页面里那串带冒号的地址，就能读懂它了：前半段来自你的运营商，后半段可能是系统随机生成、过一阵就会换的临时标识。你访问一个同时支持两种协议的网站时，手机很可能已经悄悄走了 IPv6，而你毫无察觉——这正是一场成功过渡该有的样子。

IPv6 解决的是“地址够不够”的问题，属于网络层的升级。而在它之上，传输层也在发生变化：TCP 握手太慢、队头阻塞拖累网页加载，于是有了 QUIC 和 HTTP/3。下一节我们就沿着协议栈往上走一层。
