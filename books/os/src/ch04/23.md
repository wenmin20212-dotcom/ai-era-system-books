# 4.3 操作系统与网络：网络协议栈

打开手机浏览器，输入一个网址，按下回车，一两秒后网页出现在屏幕上。这一两秒里，你的手机和远方一台从未谋面的服务器完成了一次“对话”：数据被切成小块，贴上层层地址标签，经过家里的路由器、运营商的线路，可能还穿越了海底光缆，再被对方一层层拆开、拼好。浏览器本身并不懂得怎样驱动无线网卡，也不知道数据包丢了该怎么办，这些活儿主要由操作系统里的一套软件完成，它叫**网络协议栈**（network protocol stack）。本节就来看看，操作系统怎样把一块网卡变成应用随手可用的“上网能力”。

## 4.3.1 一封信的层层信封：协议分层

“协议”就是通信双方事先约定好的规矩，比如数据怎样编号、出错了怎样重发。网络通信要解决的问题很多，工程师把它们分成若干层，每层只管一件事，上层把数据交给下层，下层在外面再套一层“信封”。这种层层叠起的结构，就是“栈”这个名字的由来。

今天互联网实际使用的是 **TCP/IP 模型**，通常按四层来讲（教科书里还有一个七层的 OSI 参考模型，主要用于教学和概念划分）：

| 层次 | 主要协议举例 | 负责什么 | 类比 | 通常在哪里实现 |
|---|---|---|---|---|
| 应用层 | HTTP、DNS | 网页、域名查询等具体业务 | 信的内容 | 应用程序或系统库 |
| 传输层 | TCP、UDP | 把数据送到对方的哪个程序，是否保证可靠 | 收件人姓名 | 操作系统内核 |
| 网络层 | IP | 给数据包定地址，决定往哪条路走 | 街道门牌 | 操作系统内核 |
| 链路层 | 以太网、Wi-Fi | 在一段线路或一个无线网络内送达 | 小区里的投递 | 内核驱动加网卡硬件 |

几个术语说明如下：**IP**（Internet Protocol，网际协议）为每台联网设备分配地址，并负责把数据包一跳一跳地转发出去，但它不保证一定送到。**TCP**（Transmission Control Protocol，传输控制协议）在 IP 之上提供“可靠、有序”的连接：丢了会重发，乱序会重排，网络拥堵时还会主动放慢速度。**UDP**（User Datagram Protocol，用户数据报协议）则轻便得多，发出去就不管，适合视频通话、在线游戏这类宁可丢一点也不想等待的场景。

表格最后一列值得留意：在 Windows、Linux、macOS、Android、iOS 这些主流系统中，传输层和网络层通常都实现在内核里。所以说，网络协议栈是操作系统的一部分，而不是浏览器的一部分。

## 4.3.2 应用的那一端：套接字

应用程序怎样使用协议栈？操作系统提供了一个统一的入口，叫**套接字**（socket）。可以把它想成墙上的一个插座：应用只需“插上”，说清楚要连哪个地址、哪个端口，用 TCP 还是 UDP，剩下的事交给系统。

**端口**（port）是一个 0 到 65535 之间的编号，用来区分同一台机器上的不同程序。IP 地址找到楼，端口找到房间。网页服务常用 443 端口（加密的 HTTPS），这是公认的约定。

套接字接口最早流行于 20 世纪 80 年代的 BSD Unix，后来被各大系统广泛借鉴，所以在 Linux、macOS 和 Windows 上，应用调用网络的方式大体相似（Windows 的版本叫 Winsock）。应用每次“发送”或“接收”，本质上都是上一节讲过的**系统调用**：程序从用户态请求进入内核，由内核里的协议栈完成真正的工作。

## 4.3.3 一个数据包的往返旅程

以浏览器请求网页为例，把各层串起来：

1. **查地址**：浏览器先要把网址里的域名换成 IP 地址，这一步叫 **DNS**（Domain Name System，域名系统）解析。操作系统通常会缓存近期查过的结果，所以第二次访问往往更快。
2. **建连接**：浏览器通过套接字请求建立 TCP 连接，内核里的 TCP 模块与对方完成俗称“三次握手”的确认过程。
3. **层层封装**：浏览器写入的请求内容，被 TCP 加上端口号和序号，被 IP 加上源地址和目标地址，再由网卡驱动交给硬件，加上链路层的头部，变成电信号或无线电波发出去。
4. **接收与拆封**：回应的数据到达网卡后，网卡通过**中断**通知处理器（这正是 4.2 节讲过的机制），驱动把数据交给内核，内核一层层剥去信封、检查顺序和完整性，最后把干净的网页内容放进对应套接字的缓冲区，唤醒正在等待的浏览器。

整个过程中，浏览器只看到“写进去一段请求，读出来一段回应”，中间的重发、排序、路由选择都被操作系统挡在了幕后。这正是操作系统一贯的做法：把复杂留给自己，把简单交给应用。

## 4.3.4 系统在网络上的其他职责

除了收发数据，操作系统在网络方面还承担几项日常工作，它们常常出现在你看到的提示里：

- **配置网络**：连上 Wi-Fi 后，系统通常通过 DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）自动向路由器索要 IP 地址，你不必手动填写。
- **选择路线**：系统维护一张**路由表**，决定数据从哪块网卡出去。手机在 Wi-Fi 和移动数据之间切换，就涉及这类决策。
- **防火墙**：系统内置的防火墙按规则放行或拦截连接。Windows 第一次运行某些程序时弹出“是否允许访问网络”的提示，就是它在工作。
- **网络权限**：在 Android、iOS 等手机系统中，应用访问网络、访问局域网设备往往需要相应权限，这把网络和第三章讲的安全机制连在了一起。

还有一个工程上的趋势：网速越来越快以后，内核协议栈本身可能成为瓶颈。部分高性能服务器场景会把一部分工作“卸载”给智能网卡，或让应用绕过内核直接收发数据。这类做法主要见于数据中心，普通电脑和手机仍以内核协议栈为主。

## 4.3.5 小结

网络协议栈把“上网”拆成分工明确的几层：链路层负责近距离送达，IP 负责找路，TCP 和 UDP 负责送到具体程序，应用层负责具体业务。操作系统在中间承上启下，向下驱动网卡、响应中断，向上通过套接字为每个应用提供统一的通信入口。理解了这一点，再看到“网络连接已断开”“防火墙已阻止此应用”这类提示，就能大致判断问题出在哪一层。网络让一台机器连上了另一台，下一节我们再往前走一步：当成千上万台机器连在一起，操作系统怎样在“云”里运转。
