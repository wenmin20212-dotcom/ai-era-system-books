# 2.4 系统服务与后台进程

打开电脑上的任务管理器（Windows 按 Ctrl+Shift+Esc），或者 Mac 上的“活动监视器”，你会看到一个现象：自己只开了浏览器和一个文档，列表里却有几十甚至上百个条目。很多名字很陌生，比如 Windows 里的“服务主机”（svchost.exe），macOS 里的 launchd、mds，Linux 里的 systemd、sshd。没有人去点开它们，它们却一直在运行。

这些程序就是**系统服务**（System Service）和**后台进程**（Background Process）。上一节讲的驱动负责让内核能操作硬件，系统服务则负责让整台机器持续处在“可用”的状态。

## 2.4.1 看不见的值班人员

可以把操作系统比作一栋办公楼。内核像大楼的结构、电路和电梯控制，前台的应用像各个办公室里的员工。楼里还有一批不坐在办公室、却一直在值班的人：保安、网管、清洁工、收发室。它们平时不出现在你面前，一旦停工，大楼很快就会出问题。

系统服务承担的就是这类工作。常见的有：

| 服务类型 | 做什么 | 停掉后你会发现 |
|---|---|---|
| 网络配置服务 | 获取 IP 地址、管理 Wi‑Fi 连接 | 能连上 Wi‑Fi 却打不开网页 |
| 打印服务 | 排队管理打印任务 | 点了打印，打印机没有反应 |
| 音频服务 | 混合多个程序的声音并送到声卡 | 所有程序都没有声音 |
| 时间同步服务 | 通过网络校准系统时钟 | 时间慢慢变得不准，部分网站证书校验失败 |
| 索引与搜索服务 | 为文件建立索引 | 搜索文件变得很慢或搜不到 |
| 更新服务 | 检查、下载系统补丁 | 不再收到安全更新 |
| 日志服务 | 记录系统事件 | 出了故障却找不到线索 |

这些工作有两个共同点：**需要长期在线**，而且**为所有程序共同服务**。如果每个应用都自己管网络、自己混音，就会互相冲突，也会重复浪费资源。把它们集中成独立的服务，是操作系统常用的分工方式。

## 2.4.2 服务与普通程序的区别

从技术上说，服务本身也是进程，也就是“正在运行的程序”（第三章会详细讲）。它和你双击打开的应用有几处不同：

- **启动时机不同**：许多服务在开机过程中自动启动，往往早于你登录；应用要你手动打开。
- **没有界面**：服务一般不显示窗口，靠日志或配置文件与人交流。
- **生命周期长**：服务通常一直运行到关机，崩溃了还可能被自动重启。
- **身份和权限不同**：服务常以专门的系统账户运行，权限可能比普通用户高，也可能被特意限制得很低。

在 Unix 和 Linux 传统里，这类程序叫**守护进程**（Daemon），名字末尾常带一个 d，比如 sshd（远程登录服务）、crond（定时任务服务）。Windows 把它们称为“服务”（Windows Service），可以在“服务”管理工具（services.msc）里查看每个服务的状态和启动类型。

## 2.4.3 谁来管理这些服务：服务管理器

几十个服务谁先启动、谁后启动、谁依赖谁，需要一个总调度。各主流系统都有自己的**服务管理器**，而且做法不同：

| 系统 | 服务管理器（写作时的主流做法） | 特点 |
|---|---|---|
| 多数 Linux 发行版 | systemd | 开机后第一个用户态进程，按依赖关系并行启动服务 |
| macOS | launchd | 同样是第一个用户态进程，可按需启动服务 |
| Windows | 服务控制管理器（SCM） | 管理服务的启动、停止和启动类型 |
| Android | init 进程配合系统服务框架 | 启动底层守护进程，再拉起 Java 层的系统服务 |

这些管理器解决的问题大体一致：

1. **依赖顺序**：网络服务要等网卡驱动就绪，时间同步服务要等网络可用。管理器根据依赖关系排出启动顺序，没有依赖关系的服务可以同时启动，以缩短开机时间。
2. **按需启动**：有些服务平时不必常驻。例如 macOS 的 launchd 和 Linux 的 systemd 都支持“有请求到来时再启动服务”，以节省内存。
3. **故障恢复**：服务意外退出时，管理器可以按配置把它重新拉起来，所以很多问题用户根本察觉不到。

在 Linux 上，可以在终端输入 `systemctl status` 查看服务树；Mac 上可以在活动监视器里按“进程名称”找到 launchd，它的进程号通常是 1，说明它是开机后最先运行的用户态进程。

## 2.4.4 为什么要把它们放在内核之外

一个自然的问题是：网络、音频这么重要，为什么不直接写进内核？

答案与安全和稳定有关。内核运行在最高权限下，内核里的一个错误可能让整台机器蓝屏或死机。服务运行在**用户态**（权限受限的运行模式，第六章会展开），即使某个服务崩溃，通常也只是这一项功能暂时失效，系统其余部分照常运行，管理器还能把它重启。另外，服务可以单独更新，不必每次都改动内核。

因此常见的分工是：**内核只保留必须由它完成的底层机制，具体策略和日常业务交给用户态的服务**。不同系统在这条界线上取舍不同，第八章讲“抽象与分层”时还会回到这个话题。

## 2.4.5 后台进程与你的电池、隐私

系统服务之外，许多应用也会留下后台进程：云盘同步、聊天软件的消息接收、各种“更新助手”。它们和系统服务一样不露面，但不一定都必要。

这正是手机系统对后台管得很严的原因。Android 和 iOS 都会限制应用在后台运行的时间和频率，并提供系统级推送服务，鼓励应用把消息推送交给它集中处理，而不是各自一直联网等待，以减少耗电。电脑上则可以在 Windows 的“任务管理器—启动应用”或 macOS 的“系统设置—通用—登录项与扩展”（较早版本为“登录项”）里，查看并关闭不需要开机自启的程序。

需要提醒的是：**不认识的进程不等于病毒，也不等于可以随手结束**。结束 svchost.exe 或 launchd 这类核心进程，可能导致系统不稳定甚至立即重启。遇到陌生名字，先查清它的来源和作用，再决定怎么处理。

## 2.4.6 小结

系统服务和后台进程是操作系统中长期在线的部分：内核提供机制，服务把网络、声音、时间、搜索、更新等公共功能持续维持住，服务管理器负责它们的启动顺序、按需运行和故障恢复。它们大多在你登录之前就已经就位。下一节转向你每天直接面对的那一层：外壳与图形界面，看看人是怎样向这套系统下达指令的。
