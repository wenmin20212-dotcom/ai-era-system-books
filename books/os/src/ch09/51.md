# 9.2 动手实验：在自己的电脑上观察进程、内存与文件

读到这里，你已经在纸面上见过进程、虚拟内存、文件系统和缓存。但这些概念真正落地，是在你亲眼看到它们的那一刻。好消息是，操作系统本身就提供了观察自己的“窗口”：Windows 的任务管理器和资源监视器、macOS 的“活动监视器”、Linux 的终端命令，甚至手机设置里的“电池”和“存储”页面，都是内核统计数据的展示台。本节设计几组不需要编程、几乎没有风险的小实验，并示范怎样把观察结果交给 AI，让它陪你把现象推回到原理。

先约定一条安全规则：**只看不改，只结束自己打开的程序**。不要结束名称陌生的系统进程，不要删除系统目录里的文件，也不要随意修改启动项和服务设置。下面的实验都可以随时停止，不会损坏系统。

## 9.2.1 实验一：数一数你的电脑里有多少个进程

打开观察窗口：

| 系统 | 打开方式（写作时的常见做法） | 重点查看的页面 |
|---|---|---|
| Windows | 按 Ctrl+Shift+Esc 打开任务管理器 | “进程”“详细信息”“性能” |
| macOS | 在“应用程序—实用工具”中打开“活动监视器” | “CPU”“内存”“磁盘” |
| Linux | 在终端输入 `top`，或安装 `htop` | 进程列表与顶部的汇总行 |

### 9.2.1.1 步骤：

1. 记下当前的进程总数。Windows 的“性能”页显示“进程”“线程”“句柄”三个数字；在 Linux 的 `top` 中，“Tasks”一行给出进程数。
2. 打开一个浏览器，再开五个标签页，观察总数变化。
3. 关闭浏览器，再看一次。

**你可能看到的现象：** 即使桌面上只开着一两个窗口，进程也常有一百到数百个，线程更多，通常是进程数的十倍左右甚至更多。这正好印证了第二章讲的系统服务与后台进程：屏幕上看不见的“后勤人员”远多于前台应用。打开浏览器后，进程数可能一下子增加好几个。这是因为许多现代浏览器采用**多进程架构**，把界面、渲染、插件分进不同进程，一个标签页崩溃时不会拖垮整个浏览器。这是浏览器的设计选择，并不是所有程序都这样做。

## 9.2.2 实验二：看内存怎样被“借用”与“归还”

切换到内存相关页面。Windows 任务管理器“性能—内存”会显示“正在使用”“已缓存”“可用”等项；macOS 活动监视器底部有“内存压力”曲线和“已缓存文件”等项；Linux 可在终端输入 `free -h`。

### 9.2.2.1 步骤：

1. 记下“已用”和“缓存”的数值。
2. 连续打开几个大型程序，例如办公软件、图片编辑器和多个浏览器标签页，观察数值上升。
3. 关闭这些程序，等待几十秒再看。

### 9.2.2.2 观察要点：

- 关闭程序后，“已用”内存会回落，但“缓存”往往不降反升，或者保持高位。这不是浪费。操作系统把刚读过的文件内容留在空闲内存里，下次再用就不必访问磁盘。这正是第八章讲的局部性原理。在系统看来，空着的内存才是浪费。
- 如果 macOS 的“内存压力”变黄或变红，或者 Windows 的“已提交”接近上限，说明内存已经吃紧，系统会更多地依赖内存压缩和交换空间。这时你可能感到切换程序变慢，这就是第六章讲的换页在“出力”。

**一个常见误区：** 很多人看到内存占用高就想“清理内存”。对现代操作系统来说，内存占用高本身不说明问题；内存压力持续偏高、频繁换页，才说明真的不够用。

## 9.2.3 实验三：跟踪一个文件的读写

### 9.2.3.1 步骤：

1. 在 Windows 打开“资源监视器”（在任务管理器“性能”页右上角的“…”菜单中，或按 Win+R 输入 resmon）的“磁盘”页，在 macOS 打开活动监视器的“磁盘”页，或在 Linux 终端运行 `iostat` 或 `iotop`（可能需要先安装）。
2. 复制一个几百 MB 到几 GB 的文件，比如一段视频，观察读写速率曲线。
3. 复制完成后立刻再复制一次同一个文件，对比两次的速度。

**你可能看到的现象：** 第二次复制时，读取速率往往明显更低，甚至几乎没有读取，而复制速度却更快。原因是文件内容已经在页缓存里，读操作直接由内存满足。这条路径可以对照第五章“一次读写文件的完整旅程”：应用发出请求，经过系统调用、文件系统、缓存，最后才可能到达磁盘驱动。

你还可以右键查看文件“属性”或“简介”，比较“大小”和“占用空间”。两者常常不一样，因为文件系统按固定大小的“块”分配空间，最后一块即使只用了一部分，也要整块占用。

## 9.2.4 实验四：把观察结果交给 AI

实验的价值在于“看到现象之后问为什么”。下面是一种推荐的提问方式，把你的**系统环境、观察数据和疑问**三样东西一起交给 AI：

> 我用的是 Windows 11（24H2 版），任务管理器显示进程 280 个、线程 3500 个，内存 16GB 中“正在使用”9GB、“已缓存”5GB。我只开了浏览器和聊天软件。请解释：1. 这么多进程大致属于哪几类？2. “已缓存”是否需要清理？3. 我该怎样判断内存是否真的不够？

使用 AI 时注意三点：

- **截图前隐去敏感信息**，例如文件路径中的用户名、窗口标题里的文件名。
- **要求 AI 给出验证方法**，不要只听结论。可以追问：“我在哪里能看到证据证明这一点？”
- **对“一键优化”类建议保持警惕**。如果 AI 建议结束陌生系统进程、修改注册表或关闭安全服务，先让它解释风险，必要时再查官方文档核实。

## 9.2.5 从“看见”到“看懂”

这四个实验分别对应本书的几条主线：进程表现了“让很多程序同时运行”，内存与缓存体现了虚拟内存和局部性原理，文件复制展示了 I/O 数据流与缓存层次。你会发现，任务管理器里的每一个数字背后，都是内核在默默记账；书中的骨架告诉你这些账目分几类，你的电脑提供真实数据，AI 帮你把数据和原理连起来。下一节将把这种提问方式整理成由浅入深的阶梯，让不同基础的读者都能找到适合自己的追问路径。
