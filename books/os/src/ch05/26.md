# 5.1 启动流：从固件到登录界面

早上打开笔记本，按下电源键，风扇轻响，屏幕先亮出厂商标志，接着出现一个转动的圆圈，十几秒后停在登录界面。手机也一样：长按电源键，品牌标志亮起，片刻后出现锁屏。这段时间在我们看来只是“等一会儿”，系统内部却在完成一次接力：控制权从一小段固化在芯片里的代码出发，交给引导程序，再交给内核，最后交给成百上千个系统服务和登录界面。第二章已经拆开了固件、引导程序、内核和服务这几个部件。本节换一个角度，把它们放在时间线上，看一条“启动流”怎样从通电一路流到登录界面。

## 5.1.1 一场接力赛：启动流的总体形状

可以把启动过程想象成一场接力赛。每一棒的选手能力有限，只负责把下一棒选手找出来、准备好，然后把接力棒交出去。之所以要分棒，是因为刚通电时机器几乎什么都没准备好：内存还没初始化，硬盘里的文件系统也读不懂，能直接运行的只有芯片里那一小段固定代码。每跑一棒，系统能做的事就多一些。

| 棒次 | 执行者 | 主要任务 | 交出控制权给 |
|---|---|---|---|
| 第一棒 | 固件（UEFI 或传统 BIOS） | 自检、初始化内存和基本设备、找到启动设备 | 引导程序 |
| 第二棒 | 引导程序（Boot Loader） | 找到并载入内核及其所需的初始文件 | 内核 |
| 第三棒 | 内核（Kernel） | 接管硬件、建立内存管理和进程管理、加载驱动 | 第一个用户进程 |
| 第四棒 | 初始化进程与系统服务 | 按依赖顺序启动后台服务 | 登录界面 |
| 终点 | 登录管理器与图形界面 | 等待用户身份验证 | 用户的桌面会话 |

## 5.1.2 第一棒和第二棒：从芯片里的代码到内核载入

通电后，处理器会从一个预先约定的位置开始执行指令，这里存放的就是固件。现代个人电脑大多使用统一可扩展固件接口（Unified Extensible Firmware Interface，UEFI），老机器使用基本输入输出系统（Basic Input/Output System，BIOS）。固件先做开机自检（Power-On Self-Test，POST），检查处理器、内存等关键部件是否可用，再初始化内存控制器和基本的输入输出设备。

接下来要决定从哪里启动。UEFI 会读取自己保存的启动顺序，在硬盘上一个专门的分区（EFI 系统分区，ESP）里找到对应的引导程序文件并运行。在开启“安全启动”（Secure Boot）的电脑上，固件会先检查这个文件的数字签名，签名不被信任就拒绝运行。这一步是整条启动链安全的起点。

引导程序的任务很专一：找到内核，把它连同必要的初始数据装进内存，然后跳过去执行。Linux 常见的引导程序是 GRUB，它还能显示菜单让用户选择系统；Windows 使用自己的启动管理器（Windows Boot Manager）。手机的过程类似，只是细节由芯片厂商和系统厂商定制。以安卓手机为例，常见做法是芯片内固化的启动代码先校验并加载下一级引导程序，逐级验证，最后加载内核。

## 5.1.3 第三棒：内核醒来，接管整台机器

内核被载入后，启动流进入关键阶段。内核要做的事大致按以下顺序进行：

1. **建立自己的运行环境**：设置处理器进入合适的工作模式，建立页表，启用第三章讲过的虚拟内存。
2. **识别硬件**：读取固件提供的硬件描述信息，弄清楚机器上有几个处理器核心、多少内存、哪些设备。
3. **初始化核心子系统**：中断处理、进程调度、内存分配器、文件系统框架依次就位。
4. **加载驱动**：内核必须读得懂存放系统文件的磁盘，才能继续往下走。Linux 常借助一个“初始内存盘”（initramfs），先在内存里放一套临时文件和必要驱动，用它找到并挂载真正的根文件系统。
5. **启动第一个用户进程**：内核在用户态创建第一个进程，把后续工作交给它。

第五步是一条分界线。在此之前，所有工作都在内核态完成；从这里开始，系统的“人员规模”迅速扩大，后面所有进程都是这个初始进程直接或间接派生出来的。

## 5.1.4 第四棒：服务成群启动，直到登录界面

第一个用户进程的名字因系统而异。如今大多数 Linux 发行版使用 systemd，macOS 使用 launchd，Windows 则由会话管理器等系统进程接手，再由服务控制管理器启动各项服务。它们的职责相似：读取配置，按依赖关系启动服务。网络服务要在网卡驱动就绪后启动，登录界面要等显示服务和账户服务就绪后才能出现。

这里体现了现代系统提速的一个重要思路：**并行启动**。早期的一些系统按清单逐个启动服务，前一个不完成，后一个就要等。现在的初始化系统会分析依赖关系，互不依赖的服务同时启动，有的服务等到第一次被用到时才真正运行（按需启动）。这和第六章将要讲的调度、同步问题直接相关：同时启动的服务越多，越要处理好“谁等谁”的问题。

最后，登录管理器启动图形环境，屏幕上出现输入密码或识别指纹的界面。用户通过身份验证后，系统为这位用户创建会话，加载个人设置，启动桌面和自动运行的程序，启动流到这里结束。

## 5.1.5 为什么开机有时快、有时慢

理解了启动流，许多日常现象就有了解释：

- **“快速启动”和休眠**：Windows 的“快速启动”功能在关机时把内核状态保存到硬盘，下次开机直接恢复，跳过了部分初始化工作。所以它在一些场合表现得不像真正的“全新启动”，这是 Windows 的特定做法。
- **开机后仍然卡一阵**：登录界面出现，不代表所有服务都已启动完毕。按需启动和延迟启动的服务、开机自启的应用会在登录后继续运行，抢占磁盘和处理器。
- **更新后首次开机较慢**：系统可能需要完成更新的收尾工作，或重建缓存，这部分会在 5.5 节展开。
- **卡在厂商标志处**：问题多半出在前两棒，例如固件设置、启动设备或引导文件出错。如果系统画面已经出现后才卡住，就更可能是驱动或服务的问题。

启动流是一条单向、逐级交权的流动：每一级只做好自己那一段，验证并唤醒下一级。把这条时间线记住，后面讲到的中断、调度和数据读写，都可以看作在这条流动铺好的路面上运行的日常交通。下一节，我们就进入系统运行起来以后最频繁的流动：处理器时间怎样在指令流与中断流之间被分配。
