# 1.3 操作系统的边界：内核、系统程序与应用

打开电脑上的“任务管理器”（Windows）或“活动监视器”（macOS），你会看到一长串正在运行的名字：浏览器、聊天软件，还有大量看不懂的条目，比如 Windows 里的“服务主机”、macOS 里的 `WindowServer`、`launchd`。手机的“设置—应用”里也有类似情况：除了你自己装的 App，还有一堆“系统应用”。于是一个看似简单的问题出现了：这些东西里，哪些算操作系统，哪些不算？

这个问题没有一句话的标准答案。工程界和普通用户对“操作系统”的划界本来就不同。本节把这条边界画清楚，并说明它为什么会有争议。

## 1.3.1 三圈同心圆：从内核到应用

可以把一台运行中的设备想象成三圈同心圆。

- **最里圈是内核（Kernel）**。它直接管理处理器、内存和各种设备，在处理器的最高权限下运行。进程切换、内存分配、读写磁盘这些最基础的工作由它完成。
- **中间一圈是系统程序**，也叫系统软件或系统工具，包括开机后自动运行的系统服务、命令行外壳（Shell，用户输入命令的程序）、图形界面、文件管理器、设置程序、软件包管理器等。它们不在内核里，却是系统“出厂自带”、维持日常运转的部分。
- **最外圈是应用程序（Application）**。浏览器、办公软件、游戏、你装的各种 App，都是为了完成用户自己的任务而存在。

用一家酒店来类比：内核像酒店的配电、供水和门禁总控室，客人看不见，却决定一切能否运转；系统程序像前台、保洁和保安，是酒店“自带”的服务；应用程序则是入住的客人，各自办自己的事。

## 1.3.2 两种定义：狭义与广义

围绕这三圈，存在两种常见的说法：

| 定义 | 包含范围 | 常见使用场合 |
|---|---|---|
| 狭义：操作系统就是内核 | 只算最里圈 | 操作系统教材、内核开发者的讨论 |
| 广义：操作系统是“开机后自带的整套软件” | 内核 + 系统程序，有时还包括预装应用 | 日常用语、产品发布、软件授权 |

最典型的例子是 Linux。严格说，Linux 指的是一个内核；我们平时装的 Ubuntu、Debian、Fedora 等，被称为“Linux 发行版”（Distribution），是在 Linux 内核之外配上了大量系统工具、图形界面和软件仓库。正因如此，自由软件基金会一方长期主张把这类系统称为“GNU/Linux”，以强调其中大量工具来自 GNU 项目。这场命名之争本身就说明：内核和“完整系统”不是一回事。

Android 也类似。它使用经过修改的 Linux 内核，但手机上看到的界面、应用框架、权限管理等，绝大部分是 Android 自己的系统层。所以说“Android 是 Linux”，在内核层面说得通，在用户体验层面并不准确。

## 1.3.3 真正的分界线：特权级

既然名称有争议，工程上靠什么划界？最可靠的标准是**运行权限**。

现代处理器在硬件上提供不同的特权级。粗略地说，可以分为两种状态：

- **内核态（Kernel Mode）**：可以执行所有指令，直接访问任何内存和设备。
- **用户态（User Mode）**：受限状态，不能直接操作硬件，也不能随意读写别人的内存。

内核运行在内核态；系统服务、外壳、图形界面以及所有应用，通常都运行在用户态。也就是说，从硬件角度看，你的浏览器和系统自带的“设置”程序，处在同一个受限的层次。它们想读文件、发网络数据，都必须“敲门”请内核代办——这个敲门的动作叫系统调用（System Call），第四章和第六章会详细展开。

这条线解释了一个常见现象：一个应用崩溃了，通常只是它自己的窗口消失，系统照常运行；而内核或运行在内核里的驱动出错，就可能导致整机死机——Windows 上的“蓝屏”、macOS 上的内核崩溃重启，往往与此有关。权限越高，出错的代价越大。

需要说明的是，内核里究竟放多少东西，各系统做法不同。有的设计把驱动、文件系统都放进内核（常称宏内核），Linux 属于这一类；有的设计让内核尽量小，把许多功能移到用户态的服务里（常称微内核）。Windows 和 macOS 的内核则常被描述为混合结构。所以“系统程序”这一圈的厚薄，因系统而异，第二章会进一步拆解。

## 1.3.4 边界为什么会模糊

日常生活中，人们对边界的争论往往不是技术问题，而是商业和使用问题。

一个经常被引用的案例是 20 世纪 90 年代末美国政府诉微软一案，争议焦点之一就是浏览器是否属于操作系统的一部分。类似地，手机厂商预装的应用能否卸载、系统自带的应用商店算不算系统，也常引发讨论。这些问题之所以难有定论，正是因为广义的“操作系统”边界本身随产品形态在变。

对普通用户来说，一个实用的判断方法是问三个问题：

1. 它运行在内核态还是用户态？（决定出错的严重程度）
2. 删掉它，设备还能开机并完成基本操作吗？（决定是否属于必需的系统程序）
3. 它是为系统服务，还是为你的具体任务服务？（区分系统程序与应用）

拿这三个问题去对照任务管理器里的条目，许多“看不懂的名字”就有了归属：多数是用户态的系统服务，少数与内核或驱动相关，其余才是你自己的应用。

## 1.3.5 小结

操作系统的边界可以用“内核—系统程序—应用”三圈来描述：狭义上它只指内核，广义上还包括随系统提供的各种系统程序。真正可靠的技术分界线是处理器的特权级——内核在内核态，其余大多在用户态。理解了这条线，再看操作系统的各个家族就有了统一的坐标：下一节我们将看到，从大型机到手机和物联网设备，不同系统正是在这三圈的厚薄与组合上走出了各自的路。
