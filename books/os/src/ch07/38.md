# 7.1 Linux 与开源生态

你也许从没在自己的电脑上装过 Linux，但几乎每天都在用它。打开手机刷短视频，视频从远端服务器传来，而大量互联网服务器运行的正是某种 Linux 系统；手里的 Android 手机，底层内核也是 Linux；家里的路由器、智能电视、车载屏幕，很多同样如此。这一节就从“它到底在哪里”出发，看清 Linux 是什么、怎样组织起来，以及“开源”这种协作方式为什么能撑起一个这么大的系统。

## 7.1.1 一个内核，一大家子：Linux 到底指什么

严格地说，Linux 只是一个**内核**（Kernel），也就是第二章讲过的那位“核心管家”：负责进程调度、内存管理、文件系统、驱动和网络协议栈。它由芬兰学生林纳斯·托瓦兹（Linus Torvalds）在 1991 年发起，起初只是个人项目，后来通过互联网吸引了全世界的开发者参与。

光有内核还不能用。人们平时说的“装一个 Linux”，其实是装一个**发行版**（Distribution），它把 Linux 内核和大量其他软件打包在一起：

| 组成部分 | 作用 | 常见例子 |
|---|---|---|
| Linux 内核 | 管理硬件与资源 | 各发行版通用，版本不同 |
| 系统库与基础工具 | 给程序提供标准接口与命令 | GNU C 库、GNU 核心工具 |
| 初始化与服务管理 | 开机后拉起各种后台服务 | systemd（许多发行版采用） |
| 软件包管理器 | 安装、升级、卸载软件 | apt、dnf 等 |
| 图形界面（可选） | 桌面、窗口、文件管理器 | GNOME、KDE Plasma |

其中很多基础工具来自更早的 GNU 计划，所以有人主张称之为“GNU/Linux”。常见的发行版有 Debian、Ubuntu、Fedora、红帽企业版（RHEL）、Arch 等，它们共用同一个内核家族，但在软件选择、更新节奏和面向人群上各有侧重：有的追求稳定、适合服务器多年不动；有的追新、适合开发者尝鲜。

需要注意，Android 虽然用 Linux 内核，上层却是谷歌设计的另一套运行环境和应用框架，与桌面发行版差别很大。“用了 Linux 内核”和“是一个常见的 Linux 发行版”是两回事。

## 7.1.2 宏内核加可加载模块：Linux 的结构选择

第二章提到内核有宏内核和微内核等不同设计。Linux 属于**宏内核**（Monolithic Kernel）：调度、内存、文件系统、驱动、网络协议栈都运行在同一个内核空间里，彼此直接调用，速度快，但一处驱动出错可能拖垮整个系统。

为了弥补“大而僵”的缺点，Linux 支持**可加载内核模块**（Loadable Kernel Module，LKM）。插上一个新的 USB 网卡，系统可以在运行中把对应驱动模块装进内核，不需要重新编译整个内核。在 Linux 终端里输入 `lsmod`，就能看到当前已加载的模块清单，往往有几十到上百个。

Linux 还继承了 Unix 的一条重要思想：**“一切皆文件”**。硬盘、终端、甚至进程信息都以文件的形式出现在目录树里。比如 `/proc` 目录下，每个正在运行的进程都有一个以编号命名的文件夹，读取其中的文件就能看到它占用的内存和状态。第九章做实验时，你会发现这个设计让“观察系统”变得格外方便。

## 7.1.3 开源怎样运转：许可证与协作流程

**开源**（Open Source）指源代码公开，任何人都可以阅读、修改和再发布，但要遵守许可证。Linux 内核采用 **GPL**（GNU 通用公共许可证）第 2 版，它的核心要求可以概括为“你可以自由用，但如果你把修改过的版本分发出去，也得公开源代码”。这条规则让各家公司的改进最终回流到公共代码里，而不是各自封闭。

内核的协作并不是“谁都能随手改”。它有一套层级清晰的流程：

1. 开发者把修改做成**补丁**（Patch），通过邮件列表提交；
2. 负责某个子系统（如网络、文件系统、某类驱动）的**维护者**审阅、提意见、合并；
3. 各子系统的修改汇总到托瓦兹维护的主线，大约每两三个月发布一个新版本；
4. 部分版本被选为**长期支持**（Long Term Support，LTS）版本，持续多年只修漏洞，供手机厂商和服务器使用。

为了管理这种规模的协作，托瓦兹在 2005 年写出了版本控制工具 Git，如今它已成为整个软件行业最常用的代码管理工具之一。贡献者里既有个人爱好者，也有大量来自芯片厂商、云服务商和硬件公司的工程师——他们需要让自家硬件在 Linux 上跑得好，于是把驱动和优化贡献进来。

## 7.1.4 为什么是 Linux：开源生态的优势与代价

Linux 能遍布服务器、手机和嵌入式设备，原因不只是“免费”：

- **可裁剪**：路由器可以只保留几个必要模块，超级计算机可以把调度和网络调到极致；
- **可审计**：代码公开，安全研究者能直接检查，漏洞被发现和修补的路径更透明；
- **硬件覆盖广**：厂商主动贡献驱动，新芯片往往很快获得支持；
- **生态复利**：容器、云平台等技术大量建立在 Linux 的功能之上，第 7.3 节会看到容器正是依靠 Linux 内核的命名空间和控制组机制实现的。

代价也存在。发行版众多，软件打包方式不统一；桌面端的商业软件和游戏支持长期不如 Windows 完善；开源项目依赖维护者的投入，一些基础组件曾因人手不足而出现安全隐患。开源不等于自动安全，它只是让“更多眼睛检查”成为可能。

## 7.1.5 小结：一套代码，多种形态

回到开头那部手机和那台看不见的服务器：它们共享同一个内核家族，却因发行版、裁剪和上层框架的不同而形态迥异。Linux 的意义在于，它证明了一个上千万行代码量级的操作系统可以由全球协作持续维护。理解了这个开源样本，下一节再看 Windows、macOS、Android 和 iOS 这些商业系统时，就能更清楚地对照：哪些设计是操作系统的共同规律，哪些只是某家公司的选择。
