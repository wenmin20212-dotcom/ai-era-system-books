# 7.4 实时操作系统与嵌入式系统

早上出门前，你按下微波炉的“启动”键，转盘开始旋转；开车时轻踩刹车，防抱死系统在车轮即将抱死的瞬间松开又夹紧刹车片；手腕上的运动手环在你睡着后仍然每隔一段时间测一次心率。这些设备里也运行着程序，也需要有人管理处理器、内存和外设，但你从来没在它们身上见过“开始菜单”或“设置”应用。它们背后的管家，常常是一类专门的系统，叫作实时操作系统。这类系统运行在嵌入式设备里，是我们身边数量最多的计算机，却最少被人注意。

## 7.4.1 嵌入式系统：藏在设备里的计算机

嵌入式系统（Embedded System）是指被“嵌”进某个更大设备、只为特定功能服务的计算机。它通常没有键盘和显示器，或者只有几个按钮和一块小屏幕。它的核心往往是一颗微控制器（Microcontroller Unit，MCU），也就是把处理器、少量内存、存储和输入输出接口集成在一块芯片上的“单片机”。

与读者手边的电脑和手机相比，嵌入式设备的条件差别很大：

| 对比项 | 笔记本电脑 / 智能手机 | 典型嵌入式设备（如手环、电机控制器） |
|---|---|---|
| 内存 | 通常以 GB（十亿字节）计 | 常见为 KB 到 MB 量级 |
| 功能 | 通用，可随时安装新应用 | 专用，出厂时功能基本固定 |
| 用户交互 | 丰富的图形界面 | 少量按键、指示灯，甚至没有 |
| 核心诉求 | 体验流畅、功能丰富 | 稳定、省电、按时响应 |

资源这样紧张，Windows 或完整的 Linux 这类庞大的系统根本装不进去，嵌入式系统需要更小、更专注的“管家”。不过嵌入式系统的范围很宽：家用路由器、智能电视等资源较充足的设备，常常就运行裁剪过的 Linux。真正对时间要求严苛的场合，才需要实时操作系统。

## 7.4.2 “实时”的含义：不是快，而是准时

实时操作系统（Real-Time Operating System，RTOS）里的“实时”，常被误解为“速度快”。准确地说，它强调的是**可预测**，也就是一件事必须在规定的截止时间（Deadline）之前完成，而且每一次都要做到。

打个比方：普通操作系统像一家生意兴隆的餐馆，大多数时候上菜很快，但高峰期偶尔让客人多等十分钟，也不算大事；实时操作系统像医院的急救调度，平均速度未必最快，但必须保证危急病人在规定时间内得到处理，一次都不能误。

工程上通常把实时要求分为两类：

- **硬实时**（Hard Real-Time）：错过截止时间就意味着失败，可能造成事故。例如汽车安全气囊的触发、飞行控制、工业机械臂的急停。
- **软实时**（Soft Real-Time）：偶尔超时会降低质量，但不至于酿成灾难。例如视频通话中某一帧晚到，画面卡顿一下。

你的电脑在播放视频时偶尔掉一帧，属于软实时问题；如果刹车控制器“掉一帧”，后果就完全不同了。

## 7.4.3 实时操作系统怎样做到准时

第六章讲过，桌面系统的调度器追求“公平”和“整体吞吐量”，让每个程序都分到处理器时间。实时操作系统的设计取舍不同，它的几个核心机制都围绕“确定性”展开：

1. **基于优先级的抢占式调度**：每个任务有固定优先级，一旦更紧急的任务就绪，系统立即打断正在运行的低优先级任务。刹车控制任务的优先级远高于仪表盘刷新任务。
2. **中断响应时间有上限**：从硬件发出中断到相应处理程序开始运行，这段延迟必须有确定的最坏情况上限，而不只是“平均很短”。
3. **避免不可预测的操作**：许多实时系统尽量不用或少用虚拟内存换页、动态内存分配这类耗时不固定的机制，内存常常在启动时就分配好。
4. **处理优先级反转**：当高优先级任务等待一个被低优先级任务占用的资源时，中优先级任务可能插进来，导致高优先级任务被无限拖延。常见对策是“优先级继承”，即暂时把占用资源的低优先级任务提升到高优先级，让它尽快用完并释放资源。公开资料中常被引用的案例是 1997 年美国“火星探路者”号探测器，它在火星上出现反复重启，原因正是优先级反转，地面工程师远程开启优先级继承后问题得到解决。

由此可见，实时系统在“平均性能”上做出了让步，以换取“最坏情况可控”。这正是 8.4 节将讨论的调度理论在工程上的直接应用。

## 7.4.4 常见的实时与嵌入式系统

写作时，公开资料中常被提到的实时与嵌入式系统包括：

- **FreeRTOS**：开源、体积很小的实时内核，广泛用于各类微控制器，现由亚马逊公司维护。
- **Zephyr**：Linux 基金会托管的开源实时系统，面向物联网设备。
- **VxWorks**：风河公司（Wind River）的商业实时系统，常见于航空航天和工业控制领域。
- **QNX**：采用微内核设计的商用实时系统，在汽车电子领域应用较多，现属黑莓公司。
- **RT-Thread**：源自中国的开源实时系统，社区活跃。
- **嵌入式 Linux 与实时补丁**：Linux 社区长期开发的 PREEMPT_RT 补丁，可以提升 Linux 的实时性能，已于 2024 年随 Linux 6.12 正式并入主线内核。

很多实时内核小到只有几千字节到几十千字节。它们往往不区分用户态和内核态，也没有文件系统和图形界面，只提供任务调度、定时器、任务间通信和同步这几样最核心的功能。这体现了 2.2 节所说的思路：内核可以按需要裁剪到极简。

## 7.4.5 一台设备，多个系统

一辆现代汽车里可能有数十个甚至上百个电子控制单元，分别运行着不同的系统：发动机和制动控制用硬实时系统，中控大屏可能运行 Android 或 Linux。你手里的智能手机也是如此，主处理器上跑着 Android 或 iOS，而负责通信的基带芯片、负责电源管理和传感器的小芯片里，常常各自运行着独立的小型实时系统。

所以，“一台设备只有一个操作系统”的印象并不准确。在现代设备中，通用系统负责与人打交道，实时系统负责按时控制硬件，两者分工协作。理解了这一点，再看下一节将要讨论的安全机制就更容易明白：系统越分散，每一层的防护越重要。
