# 7.2 桌面与手机操作系统：Windows、macOS、Android 与 iOS

把笔记本电脑和手机并排放在桌上，你会发现它们的“脾气”很不一样：电脑上可以随手从网上下载一个安装包双击运行，手机上安装应用通常要经过应用商店；电脑上可以同时开十几个窗口互相拖拽文件，手机上切到后台的应用过一会儿可能被“冻住”，回来时重新加载。这些差异不是偶然的界面风格，而是背后四个主流系统在内核结构、安全模型和资源策略上做出的不同选择。本节把 Windows、macOS、Android 和 iOS 放在一起对照，看清它们各自从哪里来、核心长什么样、为什么这样设计。

## 7.2.1 两条血脉：NT 系与 Unix 系

从“家谱”上看，四个系统大致分属两条血脉。

- **Windows**：今天的桌面 Windows 建立在 **Windows NT**（New Technology，新技术）内核之上。NT 在 20 世纪 90 年代初问世，最初面向服务器和工作站，后来逐步取代了建立在 DOS 之上的早期 Windows，成为家用版本的基础。
- **macOS 与 iOS**：它们共享一个名为 **XNU** 的内核（公开资料中常解释为“X is Not Unix”的缩写）。XNU 把卡内基梅隆大学的 Mach 微内核与来自 BSD（伯克利软件发行版，一种 Unix 分支）的组件组合在一起，属于第二章提到的“混合内核”。macOS 通过了 The Open Group 的 UNIX 03 认证，在本节对照的四个系统中只有它如此。
- **Android**：底层使用 **Linux 内核**，在其上叠加了谷歌主导开发的运行时和应用框架。它与上一节讲到的 Linux 生态同根，但用户看到的是一套完全不同的上层世界。

所以，iPhone 和 Mac 在底层是“亲兄弟”，Android 手机与服务器上的 Linux 是“表亲”，而 Windows 自成一系。

## 7.2.2 四个系统的结构对照

| 对照项 | Windows | macOS | Android | iOS |
|---|---|---|---|---|
| 内核 | Windows NT 内核（混合式） | XNU（Mach + BSD，混合式） | Linux 内核（宏内核，模块化） | XNU |
| 主要硬件 | 多厂商 PC，x86 为主，也支持 ARM | 苹果自家 Mac，写作时以苹果自研 ARM 芯片为主 | 多厂商手机，ARM 为主 | 苹果自家 iPhone |
| 应用来源 | 商店与自由安装并存 | 商店与自由安装并存，未签名软件会受到提示和限制 | 以应用商店为主，允许“侧载” | 原则上通过 App Store，部分地区按当地法规有例外 |
| 源代码 | 闭源 | 内核部分开源，整体闭源 | 基础部分开源（AOSP），厂商定制版多含闭源组件 | 闭源 |

表里有一个容易忽略的维度：**谁造硬件**。苹果同时掌控 Mac、iPhone 的硬件和系统，驱动和硬件型号都可控，系统可以针对少量机型深度优化。Windows 和 Android 要面对成千上万种不同厂商的硬件组合，必须依靠第二章讲过的驱动模型和硬件抽象层来消化差异。这也是 Windows 电脑偶尔因某个驱动出问题而蓝屏、Android 手机“同一版本系统在不同品牌上表现不同”的根源之一。

## 7.2.3 Android 的分层：内核之上还有很多层

Android 值得多看一眼，因为它清楚地展示了“同一个 Linux 内核，可以撑起完全不同的系统”。按谷歌公开文档的描述，自下而上大致是：

1. **Linux 内核**：负责进程、内存、驱动和电源管理等基础工作。
2. **硬件抽象层**（HAL，Hardware Abstraction Layer）：把摄像头、传感器等硬件包装成统一接口，让上层不必关心具体芯片。
3. **Android 运行时**（ART，Android Runtime）：执行应用代码的环境，应用通常用 Java 或 Kotlin 编写，编译成中间格式后由 ART 运行。
4. **应用框架**：提供活动管理、通知、位置服务等应用编程接口。
5. **应用**：包括系统自带应用和用户安装的应用。

Android 还利用了 Linux 的用户机制做隔离：每个应用安装时被分配一个独立的用户编号，彼此的文件默认互不可见。这是把 Linux 原本为“多个人共用一台电脑”设计的权限体系，改造成“多个应用共用一部手机”的隔离墙。

## 7.2.4 手机与电脑：三处根本差异

为什么手机系统比桌面系统“管得严”？可以归结为三点。

**第一，电池是硬约束。** 电脑插着电源，后台程序多跑一会儿问题不大；手机电池容量有限，后台每多一次唤醒都在耗电。因此 iOS 和 Android 都严格限制后台活动：应用切到后台后会被暂停或受到严格限制，内存紧张时系统会直接结束它们，只留下推送通知、音乐播放等少数经过许可的后台任务。这就是“切回应用要重新加载”的原因。

**第二，内存回收更激进。** 第六章讲过，桌面系统在内存不足时常把页面换到硬盘上。手机闪存的写入寿命和速度不同于电脑，手机系统通常更倾向于直接终止后台应用来回收内存，而不是大量换页。Android 和 iOS 的具体策略不同，并随版本调整，但“优先保前台”的思路一致。

**第三，默认不信任应用。** 桌面系统诞生于“用户安装的程序就是用户自己想运行的”年代，传统程序往往能读取用户名下的所有文件。手机系统很早就采用**沙箱**（Sandbox，把每个应用关在独立空间里的隔离机制）：应用只能访问自己的目录；经过多年演进，如今读取相册、通讯录、定位、麦克风都要弹窗请求授权。近年来桌面系统也在向这个方向靠拢，例如 macOS 会在应用首次访问“文稿”文件夹或摄像头时弹出授权提示，Windows 也对通过应用商店分发的部分打包应用（如 UWP 应用）施加类似隔离。

## 7.2.5 趋同中的不同

写作时，四个系统正在互相借鉴：桌面系统加强沙箱和签名，手机系统支持多窗口和外接显示器；Mac 与 iPhone 使用同一架构的芯片，部分 iPhone 应用可以直接在 Mac 上运行。但底层血脉和设计约束没有消失：Windows 背负着数十年的软件兼容责任，苹果依靠软硬一体换取可控性，Android 依靠开源内核换取多厂商生态。

看懂这些差异，再看到“该应用想要访问你的位置”或“此软件来自未知开发者”这样的提示，就能明白它们是系统安全模型的正常体现，而不是故障。下一节，我们把视角从一台设备移到一台设备里同时运行多个“系统”的技术——虚拟化与容器。
