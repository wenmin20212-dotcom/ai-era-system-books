# 6.6 本章骨架小结与实物探索任务

打开任务管理器（Windows）或活动监视器（macOS），你会看到几百个进程在“同时”运行，内存占用可能超过物理内存条的容量。拔掉电源再开机，刚才保存的文件依然完好。一个程序崩溃了，其他程序照常工作。这些现象背后，是第六章讲的五套机制在协同工作。本节先把这五套机制串成一副骨架，再请你回到自己的设备上，亲眼验证它们。

## 6.6.1 本章骨架回顾：五套机制回答五个“怎么办”

第三章讲操作系统“做什么”，本章讲它“怎么做到”。五节内容对应五个具体难题：

| 节次 | 要解决的难题 | 核心机制 | 一句话记忆 |
|---|---|---|---|
| 6.1 调度 | 处理器核心少、任务多，谁先用、用多久？ | 时间片、优先级、抢占、多核负载均衡 | 轮流坐庄，急事优先 |
| 6.2 虚拟内存 | 每个程序都想要一大块完整而独立的内存 | 分页、页表、地址转换、换页 | 每人一本“假账”，系统对真账 |
| 6.3 文件系统 | 数据怎样长期保存、快速找到、断电不乱？ | 目录树、索引结构、日志（Journaling） | 先记账，再动手 |
| 6.4 同步与死锁 | 多个程序抢同一样东西时怎样不出错？ | 锁、信号量、死锁的四个必要条件 | 排好队，别互相卡住 |
| 6.5 特权级 | 应用怎样安全地请求硬件服务？ | 用户态与内核态、系统调用、陷入 | 窗口办事，不进后台 |

把它们连起来看，可以得到三条贯穿全章的线索：

- **“虚拟化”的线索**：调度把一个处理器“变成”很多个，虚拟内存把一块物理内存“变成”很多份独立空间。每个程序都以为自己独占机器，这是操作系统最重要的一种“假象”。
- **“隔离与受控交互”的线索**：特权级保证应用不能直接动硬件，虚拟内存保证程序不能随意读写别人的内存；需要交互时，必须走系统调用这扇“正门”，或通过锁等同步手段协调。
- **“为意外做准备”的线索**：日志让文件系统在断电后能恢复一致，死锁预防与检测让程序不至于永远互相等待，抢占式调度让一个“赖着不走”的程序拖垮不了整台机器。

这些机制都是“取舍”的产物：时间片太短，切换开销大；太长，交互卡顿。换页让内存“看起来更大”，但频繁换页会让电脑明显变慢。理解取舍，比记住名词更重要。第八章会进一步追问这些取舍背后的原理，例如局部性原理、排队论和并发理论。

## 6.6.2 实物探索任务：在自己的设备上看见机制

以下任务只需查看，不需修改系统设置。

1. **观察调度与多核**：打开任务管理器的“性能”页（Windows）、活动监视器的“CPU”页（macOS），或在 Linux 终端运行 `top`。同时播放一段视频并打开几个网页，观察各个核心的占用曲线怎样变化。思考：为什么几百个进程只用到少量处理器时间？

2. **观察虚拟内存与换页**：在 Windows 任务管理器“性能—内存”中查看“已提交”与物理内存总量的对比；在 macOS 活动监视器“内存”页查看“已使用的交换”和“内存压力”图。连续打开大量浏览器标签页，看这些数字是否上升，电脑是否开始变慢。

3. **观察特权级的分界**：在 Windows 任务管理器“性能—CPU”页的曲线上右键，选择“显示内核时间”，曲线中会出现区分内核态时间的部分。复制一个大文件时再看，内核时间是否明显增加？这对应着大量系统调用和 I/O 处理。

4. **查看文件系统类型**：在 Windows 中右键某个磁盘，选择“属性”，查看文件系统（常见为 NTFS）；在 macOS 的“磁盘工具”中查看格式（写作时新设备常见为 APFS）；在 Linux 中运行 `df -T`（常见为 ext4 等）。查一查：你的文件系统用什么方式保证断电后的一致性？

5. **体会“卡住”**：回忆一次程序“未响应”的经历。它是整个系统卡死，还是只有这个窗口卡住？结合抢占式调度与进程隔离，解释为什么通常只是单个程序出问题。

## 6.6.3 可以直接拿去问 AI 的问题

- “我的电脑有 16GB 内存，任务管理器显示‘已提交’超过了 16GB，这说明什么？请用分页和换页的原理，按中学生能听懂的方式解释。”
- “请用生活中的例子，分别说明死锁的四个必要条件，并告诉我操作系统通常打破其中哪一个来预防死锁。”
- “日志文件系统在写文件时先写日志，断电后怎样恢复？请对比 NTFS、ext4 和 APFS 的做法，并标明哪些说法需要我去官方资料核实。”

向 AI 提问时，记得追问一句“这是哪个系统的做法”，并对照本章骨架判断回答是否混淆了不同系统的机制。
