# 6.1 调度：谁先用处理器、用多久

打开电脑的任务管理器（Windows）或活动监视器（macOS），往往能看到几百个进程，而处理器只有几个到十几个核心。你一边听音乐、一边打字、浏览器还在后台下载，音乐没有卡顿，键盘也及时响应。几百个程序轮流使用几个核心，却让你觉得它们在同时运行，这件事由操作系统里的调度器（scheduler）负责。它每时每刻都在回答两个问题：下一个让谁上处理器？让它用多久？

## 6.1.1 一个核心，一条队伍：调度要解决什么

可以把处理器核心想象成银行里的一个窗口，进程和线程是排队办事的顾客。第三章讲过，一个程序运行起来是进程，进程里可以有多个线程；现代系统真正调度的单位通常是线程。

在任一时刻，一个线程大致处于三种状态之一：

| 状态 | 含义 | 银行类比 |
|---|---|---|
| 运行（running） | 正在某个核心上执行 | 正在窗口办理 |
| 就绪（ready） | 万事俱备，只差处理器 | 在大厅排队等叫号 |
| 阻塞（blocked） | 在等硬盘、网络或键盘输入等事件 | 回家取材料，暂时不排队 |

大多数线程其实在阻塞。你的聊天软件绝大部分时间在等新消息，并不占用处理器。调度器只在“就绪队列”里挑人。所以任务管理器显示几百个进程时，处理器占用率仍可能只有百分之几。

调度器追求的目标往往互相冲突：

- **响应快**：点一下鼠标，界面要立刻有反应；
- **吞吐高**：单位时间内完成的工作尽可能多；
- **公平**：任何线程都不该被无限期晾在一边，这种情况叫“饥饿”（starvation）；
- **省电**：在手机和笔记本上，让核心尽量休眠，有时比跑得快更重要。

没有哪种算法能同时把这几项做到最好，调度的设计就是在它们之间取舍。

## 6.1.2 经典策略：从先来先服务到时间片轮转

教科书里有几种基本策略，它们是理解所有现代调度器的起点。

**先来先服务（First-Come First-Served，FCFS）**：按到达顺序办理，前一个不办完，后一个不能上。规则简单，问题也明显：一个要算十分钟的任务排在前面，后面只需一眨眼的任务也得干等。这叫“护航效应”，就像一辆慢卡车后面堵了一串小轿车。

**短作业优先（Shortest Job First，SJF）**：先办最快的。在理论上它能让平均等待时间最短，但系统事先并不知道一个任务要算多久，只能根据它过去的表现去估计。另外，长任务可能一直被插队，导致饥饿。

**时间片轮转（Round Robin，RR）**：每人只能连续办一小段时间，这段时间叫时间片（time slice）；时间到了就回到队尾，换下一个人。交互式系统的“同时运行”感主要就靠它实现。时间片的长短需要权衡：太长，界面反应变迟钝；太短，频繁换人的开销又会吃掉大量时间。常见的时间片在毫秒量级，具体数值因系统和负载而异。

**优先级调度（priority scheduling）**：给每个线程一个优先级，高的先上。为防止低优先级线程饿死，常配合“老化”（aging）机制，等得越久，优先级逐渐抬高。

## 6.1.3 时间片到了怎么办：抢占与上下文切换

线程不会主动交出处理器，怎么在时间片用完时把它请下来？这要靠第五章讲过的时钟中断。硬件定时器周期性地或按需发出中断，处理器暂停当前线程，转入内核，调度器借机检查是否该换人。这种由系统强行收回处理器的做法叫抢占（preemption）。早期一些个人电脑系统采用“协作式”多任务，依赖程序自觉让出处理器，一个程序陷入死循环，整台机器就可能失去响应。现代主流桌面和手机系统都采用抢占式调度。

换人时，内核要把旧线程的寄存器、程序计数器等“工作现场”保存起来，再把新线程的现场恢复，这个过程叫上下文切换（context switch）。它好比窗口职员把上一位顾客的材料收进文件夹，再摊开下一位的。每次切换通常只需微秒量级，但还会让处理器缓存里的数据“凉掉”，新线程起步会慢一些。所以调度器不会无节制地频繁切换。

## 6.1.4 真实系统怎么做：多级队列与公平分配

真实系统通常把上述思路组合使用，下面举两个有代表性的做法。

**多级反馈队列（Multilevel Feedback Queue，MLFQ）**：设几条优先级不同的队列，新线程先进高优先级队列，时间片短；如果它用满时间片还没停，说明是“计算型”任务，就降到低一级队列，时间片变长。经常很快让出处理器去等输入的交互型任务则留在高处。系统不需要预先知道谁是什么类型，靠观察行为来区分。Windows 的调度器采用基于优先级的抢占式调度，并会临时提升前台窗口和刚等到输入的线程的优先级，思路与此相近。

**完全公平调度（Completely Fair Scheduler，CFS）**：这是 Linux 内核长期使用的默认调度器。它为每个线程记录“已经用了多少处理器时间”，并按优先级加权，每次挑累计时间最少的线程运行，力求长期看每个线程都拿到应得的份额。自 Linux 6.6（2023 年）起，内核已用 EEVDF（最早合格虚拟截止时间优先）调度器替代 CFS，目标仍是按权重公平分配，同时改善对延迟敏感任务的照顾。

还有两个现代因素让调度更复杂：

- **多核与负载均衡**：调度器要决定线程在哪个核心上跑。尽量留在原核心可以利用热缓存，但某个核心太忙时又要把线程迁走。
- **大小核架构**：很多手机芯片和部分新款电脑处理器同时有高性能核心和高能效核心。系统要判断哪些任务值得放到大核，哪些放在小核上慢慢跑更省电。例如手机上，前台动画通常获得更高的服务质量等级，后台同步则被安排得更“节俭”。

你在 Linux 或 macOS 终端里用 `nice` 命令调低一个程序的优先级，或在 Windows 任务管理器里右键“设置优先级”，就是在给调度器提供参考意见。最终怎么排，仍由调度器决定。

## 6.1.5 小结：调度是一门取舍的手艺

调度器决定谁先用处理器、用多久，它依靠线程状态区分谁需要服务，用时钟中断实现抢占，用上下文切换完成交接，并在响应、吞吐、公平与能耗之间寻找平衡。为什么这些策略有效、排队等待时间怎样估算，第八章会从排队论的角度回答。调度分配的是“时间”，下一节将转向操作系统分配的另一种核心资源，也就是“空间”：虚拟内存怎样让每个程序以为自己独占了整块内存。
