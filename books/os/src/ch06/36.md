# 6.5 特权级与系统调用：用户态与内核态

打开电脑上的任务管理器（Windows）或活动监视器（macOS），有时会看到 CPU 占用被分成两种颜色，或者分成“用户”和“系统”两栏。手机上，一个应用想读取通讯录或打开摄像头，系统会先弹窗询问你同不同意。这两件事背后有同一套安排：处理器在两种“身份”之间来回切换。一种是普通应用运行时的受限身份，另一种是操作系统内核运行时的完全身份。本节说明这两种身份怎样划分，应用又怎样在不越界的前提下请内核帮忙。

## 6.5.1 一栋大楼里的两种门禁卡

可以把计算机想成一栋办公楼。访客拿普通门禁卡，只能进自己租用的办公室，用公共走廊。物业人员拿万能卡，配电房、监控室、电梯机房都能进。访客要是想调空调温度或开通一条网线，不能自己撬门进机房，只能到前台填单子，由物业代办。

处理器里的“门禁卡”叫**特权级**（Privilege Level），由硬件实现。处理器里有一个状态位或状态字段，记录当前代码以什么级别运行。

- **用户态**（User Mode）：应用程序运行在这里。它不能直接执行操控硬件的指令，比如关中断、改页表、直接读写磁盘控制器；也只能访问分配给自己的内存。
- **内核态**（Kernel Mode）：操作系统内核运行在这里，可以执行全部指令，访问全部内存和设备。

不同处理器对级别的命名不同。x86 架构有 0 到 3 共四个“环”（Ring），主流操作系统一般只用 Ring 0（内核）和 Ring 3（应用）。ARM 架构用“异常级别”（Exception Level，EL），常见划分是 EL0 跑应用、EL1 跑内核、EL2 跑虚拟机管理程序、EL3 跑安全固件。RISC-V 架构有用户模式、监管者模式和机器模式。名字各不相同，思路是一致的：硬件强制分级，低级别的代码碰不到高级别的资源。

## 6.5.2 为什么必须由硬件来把守

假如分级只靠软件“约定”，任何一个程序都可以无视约定，直接改写别人的内存或格式化磁盘。一个有缺陷的游戏就可能让整台机器崩溃，一个恶意程序就能窃取所有数据。

硬件把守的效果是：用户态程序如果执行了特权指令，或者访问了不属于自己的地址，处理器会立刻停下，产生一个**异常**（Exception），把控制权交给内核。内核通常的处理办法是结束这个程序。Windows 上的“程序已停止工作”，Linux 上的“段错误”（Segmentation Fault），多数就是这样来的。出错的程序退出了，系统和其他程序照常运行。6.2 节讲的虚拟内存隔离，要依靠特权级才能成立：页表只能在内核态修改，应用没法给自己“扩大地盘”。

## 6.5.3 系统调用：从前台递单子

应用总得读文件、发网络包、在屏幕上画图，这些都要碰硬件。办法就是 4.1 节提过的**系统调用**（System Call，简称 syscall）：应用不自己动手，而是通过一个固定入口请内核代办。

一次系统调用大致经过这几步，以“读取一个文件”为例：

| 步骤 | 发生了什么 | 所处状态 |
|---|---|---|
| 1. 准备 | 应用把“要读哪个文件、读多少、放到哪里”放进约定的寄存器，并放入系统调用编号 | 用户态 |
| 2. 陷入 | 执行一条专门指令（x86-64 上常用 `syscall`，ARM 上常用 `svc`），处理器切换到内核态，跳到内核预先登记好的入口地址 | 切换中 |
| 3. 检查 | 内核核对编号是否合法、参数指向的内存是否属于该应用、当前用户有没有权限读这个文件 | 内核态 |
| 4. 执行 | 内核调用文件系统和驱动完成读取，把数据复制到应用指定的位置 | 内核态 |
| 5. 返回 | 内核把结果或错误码放回寄存器，执行返回指令，处理器回到用户态，接着运行应用的下一条指令 | 用户态 |

这里有两个关键设计。第一，入口地址由内核在启动时设好，应用只能“敲门”，不能指定跳到内核的哪一行代码，因此没法绕过检查。第二，第 3 步的检查是安全的最后关口，前面讲的文件权限（3.5 节）就是在这一步执行的。手机上的权限弹窗属于更上层的系统服务，最终访问摄像头、通讯录也要经过内核和系统服务的层层核验。

程序员平时很少直接写系统调用，用的是 C 语言库、Windows API 等封装好的函数，这些函数在内部发起系统调用。不同系统的调用编号和数量差别很大，Linux 提供的系统调用有数百个。

## 6.5.4 切换是有代价的

身份切换不是免费的。处理器要保存和恢复寄存器，内核要做检查，有时还要清理缓存或相关硬件状态，以防敏感数据泄露。单次开销通常在几十纳秒到微秒的数量级，具体取决于硬件和系统，但调用次数一多就会累积起来。

因此系统设计里有不少节省切换次数的做法：

- **缓冲**：C 库先把小块写入攒在用户态缓冲区里，攒够了再发起一次系统调用。
- **批量提交**：Linux 的 io_uring 机制让应用把一批 I/O 请求放进与内核共享的队列，减少反复进出内核的次数。
- **免陷入的快速路径**：Linux 的 vDSO 机制把“读取当前时间”这类只读、无害的操作映射到用户空间直接完成。

回到开头的 CPU 占用图。“用户”部分是应用自己在算，“系统”或“内核”部分是内核在替应用办事或处理中断。如果内核时间比例长期偏高，往往说明有程序在频繁读写磁盘、收发网络，或者某个驱动在忙。

## 6.5.5 小结：一道墙，一扇门

特权级是一道由硬件砌起的墙，把应用和内核隔开，使一个程序出错不至于拖垮整个系统。系统调用是墙上唯一一扇有人看守的门，应用的所有正当请求都从这里进出，内核在门口完成核验。保护与服务就靠这两样东西同时实现。第五章讲的中断流、本章讲的调度和虚拟内存，都建立在这道墙之上。下一节将把本章的几种机制串起来，整理成完整的骨架。
