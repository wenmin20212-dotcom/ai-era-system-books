# 2.1 用户与物品：推荐系统的两类主角

打开手机上的短视频应用，屏幕上其实只发生了一件事：一个“人”遇到了一条“内容”。你点开个人主页，能看到自己的头像、关注列表、点赞记录；你长按一条视频，能看到作者、标题、话题标签、发布时间。前者是系统眼中的你，后者是系统眼中的一条内容。推荐系统无论多复杂，归根结底都在处理这两类对象之间的关系。工程上习惯把它们叫作**用户**（User）和**物品**（Item）。本节先把这两位主角认清楚，后面讲埋点、特征、漏斗时，就都有了落脚点。

## 2.1.1 “物品”是个借来的词

“物品”这个说法来自早期电商和电影推荐的研究传统。那时推荐的对象确实多是一件商品、一部电影。后来推荐系统进入短视频、音乐、新闻、社交等领域，这个词被保留下来，成了一个统称：**凡是可以被推荐给用户的东西，都叫物品**。

| 应用类型 | 典型的“物品” | 一次“消费”通常是什么 |
|---|---|---|
| 短视频 | 一条视频 | 观看、看完、点赞、转发 |
| 电商 | 一件商品（有时细到某个规格） | 点击、加购、下单 |
| 音乐 | 一首歌、一张歌单 | 播放、收藏、跳过 |
| 新闻资讯 | 一篇文章 | 点击、阅读时长、评论 |
| 社交 | 一条动态、一个“可能认识的人” | 点赞、关注、发起私信 |

从表中可以看出，“物品”并不一定是实物，甚至不一定是内容。社交应用里的“推荐好友”，物品就是另一个用户。这说明用户与物品的划分是**按角色**而不是按身份来的：同一个人，在刷视频时是用户，在被推荐给别人关注时就成了物品。

## 2.1.2 系统眼中的用户：一个不断更新的“档案”

对推荐系统来说，“用户”不是你这个活生生的人，而是一份由数据拼成的档案。这份档案大致有三层来源：

1. **注册与设置信息**：账号、注册时填写或授权的年龄段、地区、语言，以及你主动勾选的兴趣标签。
2. **环境信息**：当前使用的设备型号、网络类型、所在城市级别的位置、时间段。同一个人，早高峰在地铁上和周末晚上躺在沙发上，想看的东西往往不同。
3. **行为信息**：看过什么、看了多久、点了什么赞、搜索过什么词、对什么点了“不感兴趣”。这是档案里最大、变化最快、也最有价值的一层。

需要注意一个容易混淆的点：系统识别的往往不是“人”，而是**账号或设备**。全家共用一台平板，系统看到的是一个兴趣混杂的“用户”；一个人有两个账号，系统看到的则是两个用户。很多“为什么推给我这个”的困惑，源头就在这里。

还有一类特殊用户——没有登录、刚安装应用的人。系统对他们几乎一无所知，只能依靠设备、时间等少量环境信息，这就是第三章要讲的“用户冷启动”问题。

## 2.1.3 系统眼中的物品：内容本身加上它的“经历”

一条视频在系统里同样是一份档案，可以分成两部分：

- **静态属性**：作者是谁、标题和文案、话题标签、时长、分类、发布时间；电商商品则有品牌、价格、规格、产地等。如今许多平台在公开资料中提到，会用图像、语音和文本分析技术自动理解内容，例如识别画面里有没有猫、字幕在讲什么，从而补充人工标签之外的信息。
- **动态统计**：发布后被多少人看过、平均看完比例、点赞率、被举报次数等。这部分随时间不断变化，一条视频刚发布时几乎为空，几小时后可能就积累了大量数据。

物品还有一个用户不太容易察觉的特点：**生命周期差别很大**。新闻热点可能一天后就无人问津，一首经典老歌可以被反复推荐许多年，电商商品会下架、缺货、调价。推荐系统必须知道一个物品“现在还能不能推、值不值得推”，这让物品档案也需要持续维护。

## 2.1.4 两类主角的不对称

把用户和物品放在一起对比，能看出推荐系统面临的几个基本难题：

| 对比维度 | 用户 | 物品 |
|---|---|---|
| 数量级 | 大型平台常说的是亿级 | 内容平台常见百万到亿级，并持续新增 |
| 信息来源 | 主要靠行为积累 | 既有内容本身，也有被消费的统计 |
| 变化速度 | 兴趣随时间、场景漂移 | 热度快速升降，有上架下架 |
| 表达能力 | 很少主动说明自己想要什么 | 不会说话，只能被分析和被观察 |

其中最关键的一点是：**用户很少直接告诉系统自己的偏好**。你不会每刷一条都打分，系统只能从“停留了几秒”“有没有滑走”这类间接信号里推断。研究中把打分、点“不感兴趣”这类明确表达称为**显式反馈**（Explicit Feedback），把观看、点击、停留这类行为称为**隐式反馈**（Implicit Feedback）。在今天的信息流应用里，隐式反馈的数量远多于显式反馈，但它也更含糊：多看了几秒，可能是喜欢，也可能只是手机放在一边忘了划。

另一个难题是**稀疏性**：用户数和物品数都很大，但每个人一辈子能接触的物品只是极小一部分。如果画一张“用户×物品”的大表格，绝大多数格子都是空的。推荐系统的核心任务，可以理解为根据少数已填的格子，去猜那些空格里的值。第六章讲协同过滤和矩阵分解时，我们会回到这张表。

## 2.1.5 小结：关系才是真正的对象

用户和物品是推荐系统的两类主角，但系统真正关心的是两者之间的**交互**——谁在什么时候、什么场景下，对哪个物品做了什么。用户档案、物品档案和交互记录，构成了推荐系统最底层的三块数据。那么，你的每一次滑动、停留和点赞，究竟是怎样被记录下来、变成交互记录的？这就是下一节“数据采集与埋点”要回答的问题。
