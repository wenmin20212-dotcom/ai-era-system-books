# 2.5 上下文窗口与系统提示词

和 AI 聊得久了，很多人都遇到过这样的情形：一段长对话进行到后半程，模型忽然“忘了”你开头交代过的要求；或者你把一份很长的合同整个贴进去，界面提示“内容过长”。还有一种情形不太容易察觉：你明明只打了一句“你好”，模型却用一种固定的语气、带着某些自我介绍回答你，好像有人事先嘱咐过它。

这两种现象对应本节要讲的两个部件：**上下文窗口**和**系统提示词**。前者是模型一次能“看见”的文字范围，后者是在这个范围里预先放好、你通常看不到的那段说明。

## 2.5.1 上下文窗口：模型的“工作台面”

**上下文窗口**（Context Window）指模型在一次计算中能够同时处理的令牌（token）数量上限。前几节讲过，文字先被分词器切成令牌，再变成向量，送进一层层 Transformer。上下文窗口就是这条流水线一次能容纳的令牌总数。

可以把它想成一张固定大小的工作台。模型生成每一个新令牌时，都要把台面上已有的全部内容重新“看一遍”，再决定下一个令牌是什么。台面上没有的东西，模型就无从参考。

这里有三点容易误解：

1. **窗口里装的不只是你这一句话。** 系统提示词、之前所有轮次的提问和回答、你上传的文档、模型正在生成的回答，全部计入同一个窗口。
2. **窗口按令牌计算，不按字数计算。** 同样一段话，中文、英文、代码切出来的令牌数各不相同，具体比例取决于所用的分词器。
3. **窗口不是记忆。** 模型的权重在对话过程中不会改变。它之所以“记得”你五分钟前说的话，是因为对话程序把那段历史又放回了窗口里。一旦超出窗口，被挤出去的内容对模型来说就等于从未出现过。

至于窗口有多大，各家模型差别很大，而且变化很快。在写作时的公开资料中，常见的说法是早期模型的窗口在数千令牌量级，后来普遍扩展到数万乃至数十万令牌，也有厂商宣称支持百万令牌量级。具体数字应以各模型官方说明或模型卡为准。

## 2.5.2 窗口为什么不能无限大

窗口变大是有代价的，这正是它成为一个独立“部件”的原因。

| 限制因素 | 原因 | 读者能感受到的现象 |
|---|---|---|
| 计算量 | 标准自注意力要让每个令牌和其他所有令牌两两比较，计算量大致随长度的平方增长 | 文本越长，响应越慢、费用越高 |
| 显存占用 | 推理时要为已处理的令牌缓存中间结果（即 KV 缓存，第七章详述） | 本地运行时，开大窗口容易显存不足 |
| 训练分布 | 模型若很少在超长文本上训练，长位置的表现往往变差 | 长文档中间部分的信息容易被忽略 |
| 位置编码 | 位置编码有其设计适用的长度范围 | 强行超出训练长度可能导致输出混乱 |

研究者把第三种现象形象地称为“中间迷失”（Lost in the Middle）：许多模型对窗口开头和结尾的内容利用得较好，对夹在中间的内容利用得较差。所以“窗口能装下”不等于“模型能用好”。怎样把窗口做长、做得可用，是第七章 7.3 节的主题。

你下载开源模型文件时，可以在配置文件里找到类似 `max_position_embeddings` 的字段，它通常标示模型设计或训练时支持的最大位置数。用本地推理工具运行时，往往还有一个“上下文长度”参数，可以设得比上限小，以节省显存。

## 2.5.3 系统提示词：放在台面最前面的说明书

**系统提示词**（System Prompt）是对话开始前就放进上下文窗口的一段文字，用来规定模型的身份、语气、规则和可用工具。它和你输入的内容一样都是令牌，并没有什么特殊的“指令通道”。

那么模型怎么分得清哪段是系统说的、哪段是用户说的？靠的是**对话模板**（Chat Template）。模型在指令微调阶段（第三章 3.2 节）见过大量用特殊标记分隔角色的对话，于是学会了不同角色的文字应当区别对待。不同模型家族的标记写法各不相同，大致形如：

```
<系统开始>你是一个耐心的数学助教，回答要分步骤。<系统结束>
<用户开始>三角形内角和为什么是180度？<用户结束>
<助手开始>
```

真正送进模型的，是这样一整串拼接好的令牌。模型要做的仍然是第 2.4 节讲的那件事：预测“助手开始”之后的下一个令牌。系统提示词之所以起作用，是因为它改变了模型做预测时所依据的上下文。很多开源模型会把对话模板写在分词器配置文件里，读者打开就能看到这些特殊标记的真实写法。

## 2.5.4 系统提示词能做什么，不能做什么

把系统提示词理解为“写在台面最前面的说明书”，就容易把握它的边界：

- **能做的：** 设定角色和语气；限定回答格式（比如只输出表格）；告诉模型当前日期等外部信息；列出可调用的工具及其用法（第四章 4.4 节）；补充业务规则。
- **做不到的：** 不能给模型增加训练中没有学到的能力；不能保证模型百分之百遵守；它本身也占用窗口，写得越长，留给对话的空间越少。

正因为它只是文字，也就可能被其他文字干扰。用户或网页内容里夹带“忽略之前的所有指令”之类的话，试图改写模型行为，这类攻击被称为**提示词注入**（Prompt Injection）。厂商会通过训练让模型更重视系统层级的指令，但在写作时，这仍是一个没有被彻底解决的问题。

还要区分一点：你在对话产品里看到的“记忆”“自定义指令”等功能，通常是产品层把你保存的信息在每次对话时自动写进系统提示词或上下文，模型本体并没有被修改。这正是第一章 1.3 节所说的模型本体与对话产品的分界。

## 2.5.5 小结

到这里，第二章拆出的零件已经齐全：分词器把文字变成令牌，嵌入层和位置编码把令牌变成向量，Transformer 层反复加工这些向量，输出层给出下一个令牌的概率分布；而上下文窗口规定了这一切一次能处理多少内容，系统提示词则决定窗口里最先放进去的是什么。理解了窗口，就理解了模型“记性”的真实来源；理解了系统提示词，就明白同一个模型文件为什么能在不同产品里表现出不同的样子。下一节，我们把这些零件拼回一张完整的结构图。
