# 1.1 从一次对话开始：模型“说话”的样子

打开手机或电脑上的任意一款 AI 对话工具，输入一句：“帮我给周五请假写一段简短的说明，理由是孩子发烧。”按下回车，屏幕上的回答通常不是一下子整段出现，而是一个词一个词、甚至半个词半个词地“吐”出来，像有人在另一头边想边打字。几秒钟后，一段语气得体、格式工整的请假说明就出现了。

这个再普通不过的场景，是我们认识大语言模型（Large Language Model，LLM）的第一个入口。本节不急于讲内部结构，先像观察一只动物那样，仔细看看它“说话”时有哪些外在特征。每一个特征背后都对应着后面章节要拆解的一个部件或机制。

## 1.1.1 特征一：一个字一个字地“吐”出来

逐字出现的效果并不只是界面上的动画装饰，它基本如实反映了模型的工作方式。大语言模型每一步只做一件事：根据前面已有的全部文字，预测下一个最可能出现的文字片段，把它接到末尾，再用加长后的文本去预测下一个片段，如此循环，直到它判断“该结束了”。这种“写一点、接一点、再写一点”的方式，称为自回归生成（Autoregressive Generation）。

这里所说的“文字片段”，在技术上叫令牌（Token）。它既可能是一个完整的汉字或英文单词，也可能是单词的一部分，或一个标点。所以你看到的“吐字”节奏有时快有时慢、有时蹦出半个英文单词，就是令牌在逐个产出。对话产品把这种逐步产出的结果实时推送到屏幕上，叫作流式输出（Streaming）。至于令牌怎样切分，第二章 2.1 节会专门讲。

## 1.1.2 特征二：同一个问题，每次回答都不完全一样

试着把同一个请求点一次“重新生成”。你大概率会得到意思相近、但措辞不同的另一段文字：上一次说“因孩子突发高烧”，这一次可能写成“由于孩子发烧需要照顾”。

原因在于，模型在每一步给出的并不是一个确定的答案，而是一张“候选清单”：下一个令牌可能是“因”，可能是“由”，可能是“孩”，每个候选都附带一个概率。系统再按一定规则从清单里“抽签”选出一个。抽签的随机程度可以调节，调低时回答更稳定、更保守，调高时更多样、也更容易跑偏。这套规则叫采样策略，第六章 6.3 节会讲温度、Top-p 等具体参数。

理解这一点很有用：模型的回答本质上是概率选择的结果，而不是从某个数据库里“查”出来的固定答案。

## 1.1.3 特征三：它“记得”刚才说过的话，但记忆有边界

接着上面的对话，你再输入一句“改得更正式一点”。模型没有问你“改什么”，而是直接把刚才的请假说明改写成更正式的版本。看起来它记住了前面的对话。

实际上，模型本身并不会在两次回答之间保存什么。对话产品在每一轮都会把之前的对话内容连同你的新问题一起重新交给模型，模型读的是一整段拼起来的文本。这段模型一次能读入的文本，有一个长度上限，叫上下文窗口（Context Window）。对话足够长、超出上限之后，最早的内容就会被截掉或压缩，模型也就“忘了”你一开始说过的话。不同模型的窗口大小差别很大，公开资料中常见的说法从几千个令牌到上百万个令牌不等，而且这个数字在写作时仍在快速变化。2.5 节和 4.2 节会分别从结构和连接的角度讨论它。

## 1.1.4 特征四：说得流畅，不等于说得正确

再换一个问题：请它介绍一本冷门的地方志，或者列出某个小众领域的几篇参考文献。你可能会得到一份格式标准、作者和年份齐全的清单，但仔细核对就会发现，其中一些书名或论文根本不存在。

这种“一本正经地说错”的现象，业内称为幻觉（Hallucination）。它和特征一、特征二其实是同一枚硬币的两面：模型擅长生成“在语言上看起来合理”的下一个令牌，但“合理”不等于“真实”。当它掌握的相关信息不足时，依然会按照语言的惯常模式把句子补全。第六章 6.5 节会解释这一机制，第四章 4.3 节则介绍用检索外部资料来缓解它的办法。

## 1.1.5 把观察整理成一张对照表

| 你看到的现象 | 背后的概念 | 本书展开位置 |
|---|---|---|
| 回答逐字出现 | 令牌、自回归生成 | 2.1、5.1 |
| 重新生成结果不同 | 概率分布与采样 | 2.4、6.3 |
| 能接着上文聊 | 上下文窗口、对话历史 | 2.5、4.2 |
| 长对话后遗忘开头 | 上下文长度限制 | 2.5、7.3 |
| 语气得体、听从要求 | 指令微调、偏好对齐 | 3.2、3.3 |
| 流畅但可能编造 | 幻觉 | 6.5 |

表中“语气得体、听从要求”一行值得补充一句：一个只经过大规模文本训练的原始模型，并不天然会以“助手”的口吻回答问题，它更像一台续写机器。今天我们用到的对话模型之所以有问必答、格式整齐、会礼貌拒绝不当请求，是经过额外训练“调教”出来的，第三章会讲这一过程。

## 1.1.6 从外在表现走向内部

到这里可以先得出一个朴素而重要的结论：屏幕上那段看似“思考后写出”的回答，是一台机器在反复执行“读入全部上文—给出下一个令牌的概率—选出一个—接到末尾”这一循环的结果。流畅、多变、记忆有限、偶尔编造，这些表现都能从这个循环中找到来源。

不过，对话界面只是我们看到的“外表”。真正执行这个循环的，是一个可以单独下载、保存在硬盘上的模型文件。下一节，我们就把这个文件打开，看看里面到底装着什么。
