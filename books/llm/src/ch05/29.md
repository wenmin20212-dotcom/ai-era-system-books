# 5.4 数据流：从网页语料到训练数据集

打开你下载的开源模型所附的模型卡（Model Card），常能看到一句话：“本模型在若干万亿令牌的数据上进行了预训练。”（“万亿令牌”是公开资料中常见的数量级说法，具体数字因模型而异。）这句话很短，背后却是一条很长的流水线。网页、书籍、代码和论文最初杂乱地散落在互联网上，要先经过抓取、清洗、去重、筛选和配比，最后才变成模型训练时一批批读入的令牌序列。上一节讲误差怎样从输出端倒流回每个参数，这一节往上游追：参数学到的一切，源头都在这股数据流里。

## 5.4.1 从“原矿”开始：数据从哪里来

预训练数据的来源，大致可以归为几类：

| 来源类型 | 典型例子 | 主要贡献 |
|---|---|---|
| 公开网页 | 非营利组织 Common Crawl 定期抓取并公开的网页快照 | 规模最大，覆盖话题最广 |
| 书籍与百科 | 公有领域图书、维基百科 | 长篇连贯的文本，事实密度高 |
| 代码 | 公开代码仓库 | 结构化思维、编程能力 |
| 学术与专业文本 | 论文预印本、技术文档 | 专业术语与推理过程 |
| 对话与问答 | 公开论坛、问答社区 | 口语表达、一问一答的格式 |

可以把公开网页看作“原矿”。它体量巨大，但里面混着导航栏、广告、乱码、重复转载和低质量内容，真正有用的“矿石”只占一部分。一些公开的研究报告和数据集说明提到，原始网页经过层层过滤后，最终保留的比例常常只有百分之几到百分之十几。具体数字因团队和标准而不同，但“绝大部分会被丢掉”这一点基本是共识。

需要说明的是，许多闭源模型并不公开训练数据的具体构成，开源模型的公开程度也各不相同。本节讲的是业界公开资料和开源数据集（例如 FineWeb、RedPajama、The Pile 等）中常见的做法，不代表某一家公司的具体流程。

## 5.4.2 清洗流水线：从网页到干净文本

一张网页要变成训练数据，通常依次经过下面几道工序：

1. **正文提取**：去掉网页代码（HTML 标签）、菜单、页脚和广告，只保留正文。
2. **语言识别**：用一个小分类器判断文本是哪种语言，再按语言分桶。中文、英文、代码的处理规则各不相同。
3. **启发式过滤**：用简单规则剔除明显的劣质文本，比如太短的页面、符号比例异常的页面、大量重复同一句话的页面，或者满是“点击这里”的页面。
4. **去重（Deduplication）**：网上大量内容被反复转载。完全相同的文档可以用哈希值比对后剔除；“几乎相同”的文档则要用 MinHash 一类的近似算法找出来。去重不只是为了省算力，重复太多的文本会让模型倾向于死记硬背。
5. **质量打分**：训练一个小模型，给文本打“像不像高质量文章”的分数。参照标准可以是百科、教科书风格的文本，也可以是更大的模型给出的评分。分数低的文本被丢弃或降低权重。
6. **安全与隐私处理**：过滤有害内容，并尽量去除电话号码、邮箱等个人可识别信息（PII）。

这像自来水厂：粗格栅拦掉大块杂物，沉淀池去掉泥沙，滤池和消毒再处理细小的杂质。每一道工序都会扔掉一部分数据，留下来的才流向下一步。

## 5.4.3 配比与课程：不是越多越好，而是怎样搭配

清洗之后还要回答一个问题：各类数据各放多少？这叫**数据配比**（Data Mixture）。代码多一些，编程能力往往更强；百科和书籍多一些，知识问答更扎实；各语言的比例则直接影响模型对不同语言的掌握程度。英文在网页中占绝对多数，所以如果一个模型的中文语料比例偏低，它说中文时就可能不如说英文自然。

配比不必从头到尾不变。一些公开的技术报告提到，训练后期会提高高质量数据（如数学、代码、精选文本）的比例，有的团队称之为“退火”阶段。这有点像学生先广泛阅读，考前再集中做精选题。不同团队的配方差别很大，而且常被视为核心经验，不一定公开。

最后，所有文本都要用 2.1 节讲过的分词器切成令牌，拼接或截断成固定长度的序列，打乱顺序，再分成一批批（batch）送进训练。到这一步，“数据流”才和上一节的“梯度流”接上：每一批令牌产生一次预测误差，误差再推动参数更新。

## 5.4.4 数据流决定了模型的边界

理解数据流，有助于看清模型的几个特点：

- **知识截止日期**：数据抓取停在某个时间点，模型就不“知道”此后发生的事，除非借助 4.3 节讲的检索增强。
- **偏差的来源**：网页上哪些观点多、哪些语言多，模型就更容易学到它们。过滤规则本身也带有设计者的取舍。
- **版权与授权争议**：用网页和书籍训练模型是否需要授权，写作时在多个国家和地区仍有法律讨论和诉讼，尚无统一定论。
- **数据枯竭的担忧**：一些研究者估计，公开的高质量人类文本总量有限，未来可能不够用，于是出现了用模型生成“合成数据”来补充训练的做法。它的效果和风险仍在研究中。

预训练之后的指令微调和偏好对齐（第三章）也有自己的数据流，规模小得多，但更依赖人工撰写、标注和比较，单条数据的成本也高得多。

## 5.4.5 小结

从 Common Crawl 的原始快照，到训练时的一批批令牌，数据流经历了“采集—提取—过滤—去重—打分—配比—分词—打包”这条流水线。模型的能力、知识范围和偏差，很大程度上在这条流水线上就已经确定了。人们常说“数据是燃料”，更准确的说法是：数据经过怎样的提炼，决定了模型能烧出怎样的火。下一节我们沿着同一条主线算账，看看训练和推理的花费到底落在哪里。
