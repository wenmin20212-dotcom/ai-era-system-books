# 3.2 指令微调：学会听懂要求

如果你在开源模型平台上搜索同一个模型系列，常会看到两个名字相近的文件，一个带“Base”（基座）字样，另一个带“Instruct”或“Chat”字样。两个文件大小几乎一样，分词表相同，配置文件里的层数、维度也基本一致。把它们分别加载到本地推理工具里，输入同一句“请用三句话介绍长城”，结果却很不一样。

基座模型可能接着写出“请用三句话介绍故宫。请用三句话介绍兵马俑……”，像在续写一份练习题清单。指令模型则会老老实实交出三句话的介绍。两份结构相同的文件，表现却差别很大，这个差别来自本节要讲的环节：指令微调。

## 3.2.1 从“续写者”到“应答者”

上一节讲过，预训练让模型学会了一件事：给定前文，预测下一个令牌。互联网语料里，“请用三句话介绍长城”后面跟着一份题目列表、一段论坛讨论或者一篇作文，都很常见。基座模型并没有出错，它是在忠实地续写最常见的文本形态。

问题在于，用户需要的是回答，不是续写。指令微调（Instruction Tuning）也叫监督微调（Supervised Fine-Tuning，SFT），做法是在预训练好的模型基础上，用大量“指令—回应”配对的样本继续训练，让模型把“看到一个要求”和“给出满足要求的回答”这两件事稳定地连在一起。

打个比方，预训练像一个人读完了一座图书馆，见多识广，但没人教过他怎样当客服。指令微调相当于岗前培训：给他看成千上万份“客户这样问、优秀员工这样答”的范例，让他熟悉这份工作的套路。培训不会再塞给他多少新知识，主要改变的是他使用已有知识的方式。

## 3.2.2 训练数据长什么样

指令微调的数据通常是一条条对话样本。下面是一个简化的示意：

| 部分 | 内容示例 |
|---|---|
| 系统提示 | 你是一个乐于助人的助手。 |
| 用户指令 | 把下面这句话翻译成英文：今天天气很好。 |
| 期望回应 | The weather is nice today. |

真实的数据集覆盖的任务类型很宽，常见的有：

- **问答**：事实问题、解释概念；
- **改写与翻译**：润色、缩写、换语气、跨语言转换；
- **结构化输出**：按表格、列表、JSON 等格式作答；
- **多轮对话**：在上下文里记住前面说过的话；
- **拒绝与澄清**：遇到信息不足或不当请求时，说明原因或追问。

数据来源大致有三类：人工专门编写；把已有的学术任务数据集改写成指令形式；用较强的模型生成，再经人工或自动筛选。公开研究中常见的说法是，指令微调用到的样本量通常在数万到数百万条之间，比预训练的语料小好几个数量级。不少研究还发现，质量和多样性往往比数量更要紧，几千到几万条精心挑选的样本，就能让基座模型明显学会“好好回答”。

## 3.2.3 对话模板：让模型分清谁在说话

这里有一个容易被忽略的工程细节。模型本身只认识一长串令牌，它怎么知道哪一段是用户说的、哪一段该由自己说？

答案是对话模板（Chat Template）。训练时，每条样本都会被特殊标记包起来，示意如下：

```
<|system|>你是一个乐于助人的助手。
<|user|>把下面这句话翻译成英文：今天天气很好。
<|assistant|>The weather is nice today.<|end|>
```

这些尖括号标记在分词表里通常是专门的特殊令牌。不同公司、不同模型系列的模板写法各不相同，写作时并没有统一标准。你下载的模型文件夹里，分词器配置文件中常有一段 `chat_template` 字段，记录的就是这个模型训练时用的格式。

这件事有很实际的后果。如果在本地运行指令模型时套错了模板，模型往往会答非所问、不停续写，甚至自己扮演用户接着提问。它学到的是“在 `<|assistant|>` 之后给出回应，并在适当时候输出结束标记”。格式一乱，学到的行为就对不上了。

训练时还有一个常见做法：只对“助手回应”部分计算损失。也就是说，模型不用学习怎样预测用户会说什么，只学习轮到自己时该怎样说。训练的目标仍然是预测下一个令牌，只是把要求收窄到了“作为助手的那一段”。

## 3.2.4 指令微调改变了什么，没改变什么

把能力和行为分开看，更容易理解这一步的作用：

| 方面 | 指令微调的影响 |
|---|---|
| 知识储备 | 基本来自预训练，微调很难大量注入新知识 |
| 回答格式 | 明显改变：会按要求分点、控制长度、遵守格式 |
| 任务理解 | 显著提升：能识别“翻译”“总结”“改写”等意图 |
| 对话轮次 | 学会在合适位置停下，交还发言权 |
| 泛化能力 | 能处理训练中没见过的新指令组合 |

最后一条值得多说一句。早期研究观察到，用足够多样的任务做指令微调后，模型对从未训练过的新类型指令也能给出合理回应。它学到的不只是一道道具体的题，更是“读懂要求并照做”这种通用的行为模式。

同时也要看清局限。指令微调学的是模仿范例，范例里有什么风格，模型就学什么风格。如果样本中有自信满满却内容错误的回答，模型也会学会自信地说错。如果试图借微调教给它大量预训练中没见过的新事实，研究中常见的观察是，模型更容易学会编造看起来像样的答案，而不是真正记住这些事实。这和第六章要讲的幻觉机制有直接关系。

还有一个问题，指令微调本身解决不了：两个回答都满足了要求，哪一个更好？哪一个更有帮助、更诚实、更安全？“照着范例模仿”很难表达“这个比那个好”这样的比较。要让模型在多个可行答案中倾向人类更认可的那一个，就需要下一节讲的偏好对齐。

## 3.2.5 小结

基座模型和指令模型共享同一副骨架，差别在于后者多经历了一轮“听懂要求”的训练。指令微调用高质量的指令—回应样本和对话模板，把一个只会续写的模型变成一个会应答的助手。它改变的主要是行为方式，知识储备基本没有变化。弄清这一点，你就能理解为什么本地部署时模板很重要，为什么换个说法提问结果会不同，也能理解为什么后面还需要偏好对齐这一步。
