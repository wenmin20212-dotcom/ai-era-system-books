# 9.2 动手实验：观察分词、调采样参数、跑本地模型

读到这里，你已经在纸面上走完了大语言模型的九层阶梯。但纸上的“令牌”“温度”“量化”，和亲眼看到一句话被切成碎片、亲手把温度从 0 调到 1.5、亲自在笔记本电脑上让一个模型文件开口说话，是两种不同的理解。本节设计三组实验，从“只用浏览器”到“下载一个模型文件”，难度逐级上升。每组实验都配一个 AI 助手的用法：遇到看不懂的现象，就把现象原样描述给它，让它帮你对照本书的骨架解释。

## 9.2.1 实验一：观察分词——看见模型眼中的文字

**需要什么**：一台能上网的电脑或手机。

写作时，一些模型提供方和开源社区都提供了在线分词可视化工具（英文常称 tokenizer playground）。在搜索引擎中输入“tokenizer 在线 可视化”，或请 AI 助手推荐几个当前可用的页面即可。这类页面通常会把输入的文字切成一块块带颜色的片段，并显示每块对应的编号。

建议依次输入下面几组文字，并记录令牌数：

| 输入内容 | 观察重点 |
|---|---|
| `Hello, world!` 与 `你好，世界！` | 中英文同样意思，令牌数差多少 |
| `unbelievable` 与 `unbelievablyyyyy` | 常见词与生造词的切法有何不同 |
| `2026` 与 `20261026` | 数字是整块还是被切开 |
| 一段文言文与一段网络流行语 | 训练语料中少见的文本是否被切得更碎 |
| 同一句话前面加不加空格 | 空格是否会改变切分结果 |

你很可能会发现：常见词往往是一个令牌，罕见词会被拆成好几块；不同模型的分词器对同一句中文给出的令牌数可能明显不同。这正对应第二章讲的子词分词（如字节对编码，Byte Pair Encoding，BPE）：词表是从语料统计中学来的，见得多的组合才会被合并成整块。

这个实验还有两个现实意义。第一，许多服务按令牌计费，令牌数直接对应第五章讲的成本流。第二，模型“数不清单词里有几个字母”这类常见现象，部分原因在于它看到的是令牌而不是字母。可以把截图发给 AI 助手，问它：“为什么这个词被切成了这三块？这会影响模型做拼写类任务吗？”

## 9.2.2 实验二：调采样参数——同一个模型的不同“性格”

**需要什么**：一个允许调节参数的环境。写作时，不少模型提供方的开发者控制台（常称 playground）提供温度、Top-p 等滑块；也可以在下面实验三的本地工具中调节。日常聊天界面通常不开放这些参数。

固定一个提示词，例如“用一句话描述秋天的早晨”，然后按下表改变参数，每种设置各生成三到五次：

| 设置 | 预期现象 |
|---|---|
| 温度 0（或接近 0） | 多次输出几乎一样，用词稳妥 |
| 温度约 0.7 | 有变化，但大体通顺 |
| 温度 1.5 以上 | 用词更跳跃，可能出现不通顺甚至乱码 |
| 温度不变，Top-p 从 1.0 降到 0.3 | 候选范围收窄，输出趋于保守 |
| 调高重复惩罚 | 长文本中的重复词句减少，但过高时可能刻意回避必要的词 |

把结果并排贴在一张表里，你会直观看到第六章的结论：模型每一步输出的是一张概率分布，温度改变分布的“陡峭程度”，Top-p 决定从多大范围里抽签，模型的“知识”本身并没有变，变的是抽签方式。

再做一个对照：换成一道有唯一答案的算术题，用高温度多问几次。如果答案开始出错，你就亲手验证了一条实用经验：事实性、计算性任务适合低温度，创意写作可以适当调高。不同产品的参数名称和取值范围可能不同，以其当前文档为准。

## 9.2.3 实验三：跑本地模型——让模型文件在你的电脑上说话

**需要什么**：一台内存较充裕的电脑（公开资料中常见的说法是，运行数十亿参数量级、经过 4 比特量化的模型，8 至 16GB 内存的普通电脑即可尝试），以及一个本地推理工具。

写作时，常见的本地推理工具有 Ollama、LM Studio，以及以命令行为主的 llama.cpp 等。它们大多支持 GGUF 等量化模型文件格式，也提供图形界面或一行命令即可下载运行的方式。具体安装步骤变化较快，请以工具官网的当前说明为准，或直接请 AI 助手按你的操作系统一步步指导。

建议按以下顺序观察：

1. **看文件**：下载后找到模型文件，记下它的大小。用“参数量 × 每个参数占的字节数”估算一下，看是否接近，这就是第七章量化的直接体现。同一模型的不同量化版本（如 4 比特与 8 比特）文件大小差异明显。
2. **看速度**：许多工具会显示每秒生成的令牌数。对比短提示与长提示、小模型与大一点的模型，你会感受到推理成本与模型规模、上下文长度的关系。
3. **看边界**：断开网络后提问“今天的新闻是什么”。本地模型无法联网，只能依据训练数据作答，可能会坦言不知道，也可能编出看似合理的内容。这是观察第六章幻觉机制和第一章“模型本体与产品”边界的好机会。
4. **看系统提示词**：在工具中设置不同的系统提示词，例如“你是一位只用三句话回答的老师”，比较回答风格变化。
5. **看模型卡**：回到模型下载页，读一读它的许可证、训练数据说明和已知局限。

本地运行时，电脑风扇可能转得很响，这说明矩阵运算正在消耗算力。至于更大规模的模型需要怎样的芯片和集群，可以参阅本丛书第十七册《人工智能系统》。

## 9.2.4 安全与记录：让实验真正变成知识

动手实验有几条底线：只从工具官方渠道或可信的模型托管平台下载文件；留意模型许可证是否允许你的用途；不要把个人隐私或工作机密输入在线服务。本地模型的好处之一，正是数据不离开你的电脑。

更重要的是做记录。建议准备一张“实验日志”，每次写下三栏：我做了什么、我看到了什么、这对应本书哪一节。看不懂的现象，就原样交给 AI 助手解释，再回到书中对照。纸面骨架负责告诉你“该看哪里”，实物负责给出“真实的样子”，AI 负责解答“为什么”。三者咬合起来，你对大语言模型的理解才会从“听说过”变成“亲眼见过”。
