# 2.2 文档处理：解析、去重与分词

打开任意一个网页，在空白处点右键，选择“查看网页源代码”（手机上不方便，可以用电脑浏览器试试）。你会看到一大屏尖括号、英文标签、脚本代码和样式说明。你在页面上读到的那几段正文，往往只占其中一小部分。

爬虫搬回来的就是这样的原始文件。它还不能直接用来检索：里面混着导航栏、广告、版权声明，同一篇文章可能在几十个网址下重复出现，中文句子之间也没有空格可以断开。**文档处理**（Document Processing）要把这堆原料整理成干净、不重复、切分好的文本单元，交给下一步的索引系统。这道工序大致分三步：解析、去重、分词。

## 2.2.1 解析：从源代码里取出“正文”

网页的骨架是超文本标记语言（HTML，HyperText Markup Language）。它用标签说明每段内容的身份，比如 `<title>` 是标题，`<h1>` 是大标题，`<a>` 是链接。解析（Parsing）先要读懂这些标签，再把有用的信息分门别类取出来：

| 取出的内容 | 来源示例 | 后续用途 |
|---|---|---|
| 页面标题 | `<title>` 标签 | 结果页上显示的蓝色标题，也是重要的相关性线索 |
| 正文文本 | 段落、标题等标签内的文字 | 建立索引、生成摘要 |
| 链接及锚文本 | `<a href="…">点击文字</a>` | 交给爬虫继续抓取，也用于链接分析 |
| 元信息 | `<meta>` 标签、语言声明、发布时间 | 判断语言、时效和页面属性 |

解析时有几个常见的麻烦：

- **字符编码**。同样是“搜索”两个字，用 UTF-8 和 GBK 存储的字节完全不同。编码判断错了，就会出现“锟斤拷”这类乱码，整页内容都检索不到。
- **残缺的网页**。现实中很多网页标签没有闭合、嵌套混乱，解析器只能尽量容错，猜出作者原本的意思。
- **脚本生成的内容**。不少现代网页的正文要等浏览器运行脚本之后才会出现。谷歌在官方文档中说明，它会对网页进行渲染（Rendering），也就是像浏览器一样把页面“跑”一遍，再读取结果。这样做比直接读源代码费资源得多。
- **模板噪声**。同一网站的每个页面都带着相同的导航、侧栏和页脚。识别并降低这些“样板内容”（Boilerplate）的权重，可以避免用户搜“联系我们”时冒出成千上万个无关页面。

## 2.2.2 去重：同一篇文章，别收一百遍

转载、镜像站、打印版页面、带不同跟踪参数的网址，都会制造大量重复内容。如果不处理，存储被浪费，结果页上前十条也可能是同一篇文章。去重一般分两个层次。

**完全重复**比较好办。系统给每篇文档的内容算一个“指纹”，也叫哈希值（Hash），它像一串定长编号。内容一字不差，编号就相同，比较编号就能判断是否重复，不必逐字核对两篇长文。

**近似重复**更常见，也更难处理。两篇文章只差一个广告位或一行日期，哈希值就完全不同。为此，研究者设计了一类特殊指纹：内容越相似，指纹也越接近。其中常被提到的是 SimHash，最早由计算机科学家查里卡尔（Moses Charikar）提出。谷歌工程师在 2007 年发表的一篇论文中，介绍了用 SimHash 在网页规模上检测近似重复的做法。这个方法的思路可以这样理解：把每篇文章压缩成一串由 0 和 1 组成的短码，比较两串短码有几位不同，不同的位数很少，就认为两篇文章“基本一样”。

找到重复之后，还要决定留哪一份作为代表，这个代表叫“规范网页”（Canonical Page）。网站可以用 `rel="canonical"` 标签主动声明哪个网址是正本，谷歌、必应等搜索引擎都在官方文档中支持这一标签。不过公开文档也写明，它只是一个“提示”，搜索引擎会结合其他信号自行判断。

## 2.2.3 分词：把句子切成可以查找的“词”

索引要按词来建，所以文本必须先切成一个个词元（Token）。这一步叫分词（Tokenization）。

英文有空格，切分相对容易，但仍要做一些归并：大小写统一；把 running、runs 还原成 run，这叫词干提取（Stemming）；对 the、of 这类出现极多、几乎不区分文档的“停用词”（Stop Words）做特殊处理。

中文没有天然的分隔符，难度就上来了。看这个经典例句：

> 南京市长江大桥

它可以切成“南京市 / 长江大桥”，也可能被误切成“南京 / 市长 / 江大桥”。切错了，用户搜“长江大桥”时就可能漏掉这页。中文分词常见的做法有三类：

1. **词典匹配**：拿一本大词典，从句子里找最长的已知词。速度快，但遇到新词就容易出错，比如新出现的网络用语、人名。
2. **统计与机器学习方法**：从大量语料中学习哪些字经常连在一起，遇到歧义时选择概率更高的切法。
3. **多粒度切分**：同一段文字同时保留粗、细两种切法，例如既存“长江大桥”，也存“长江”“大桥”，兼顾查得准和查得全。

各家中文搜索引擎具体用哪种组合，大多没有公开。开源工具里能看到的通常是词典与统计方法的结合，后文介绍开源搜索技术时还会提到。需要注意的是，同一套切分规则既要用于网页，也要用于用户的查询，两边切法一致，才能对得上。

## 2.2.4 小结：从“原料”到“标准件”

经过解析、去重和分词，一个杂乱的网页变成了一份结构清楚的记录：标题是什么，正文有哪些词，每个词出现在什么位置，链向哪里，是不是某篇文章的副本。可以把这道工序想成工厂里的备料车间：原材料运进来，先拆包装，再剔除重复件，最后切成标准规格的零件。

这些“标准件”接下来要按词编进一本巨大的目录，让系统在毫秒级时间内查到任何一个词出现在哪些网页里。这本目录就是下一节的主角：倒排索引。
