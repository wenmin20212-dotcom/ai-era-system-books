# 5.1 抓取流：爬虫怎样在网页之间穿行

打开你常用的一个新闻网站，首页上有几十条标题，每条都是一个链接；点进去一篇报道，文末又有“相关阅读”，再点进去，又是新的链接。你只要愿意一直点下去，几乎可以从一个网页走到互联网的任何角落。网络爬虫（Web Crawler，也叫蜘蛛 Spider）做的就是这件事，只不过它不睡觉、不看内容是否有趣，而且同时在成千上万条路上走。第二章我们把爬虫当作一个“部件”拆开看过，本节换一个角度：把目光放在“流”上，看网址和网页怎样在爬虫系统里源源不断地进出、排队、分流和回流。

## 5.1.1 一条抓取流的起点：种子与待抓队列

任何流都要有源头。爬虫的源头叫“种子网址”（Seed URL），通常是一批公认重要、链接丰富的网站首页，或者网站主动提交的站点地图（Sitemap）里列出的网址。

种子并不直接被抓，而是先放进一个“待抓队列”，工程上常称为抓取边界（Crawl Frontier）。可以把它想成快递分拣中心门口的待处理货架：所有“已经知道存在、但还没去取”的网址都堆在这里。爬虫的一次基本循环是：

1. 从待抓队列里取出一个网址；
2. 通过域名解析（DNS）找到对应服务器，发出 HTTP 请求下载页面；
3. 把下载到的网页内容交给后续的文档处理与索引环节；
4. 从页面里抽取出所有链接，规范化后检查是否见过；
5. 没见过的新网址放回待抓队列。

第 4、5 步让这个循环自我“续命”：每抓一个页面，往往会带回几十个新网址。抓取流因此不是一条直线，而是一张不断向外扩张的网。

## 5.1.2 分流：先抓谁、后抓谁

互联网上可被发现的网址数量极其庞大，公开资料中常见的说法是以万亿乃至更高数量级计（其中大量是重复、低质或动态生成的地址）。任何爬虫都不可能“全部抓完”，于是待抓队列不是先来先走，而是一个带优先级的调度系统。

| 调度考虑 | 通俗理解 | 常见依据 |
|---|---|---|
| 重要性 | 先取“热门货” | 链接数量、站点权威性等 |
| 新鲜度 | 常变的页面勤去看 | 历史更新频率、是否新闻类 |
| 礼貌性 | 别把一家店挤垮 | 同一站点的请求间隔 |
| 成本 | 别在死胡同里打转 | 抓取失败率、重复率 |

学术界早期研究（如斯坦福大学关于抓取顺序的论文）表明，按链接重要性估计来安排顺序，比单纯的广度优先或随机顺序能更早抓到高价值页面。不过，各家商业搜索引擎具体怎样打分、权重如何，大多没有公开，这里只能说明公开的思路，不能当作某家的真实配方。

“礼貌性”值得多说一句。爬虫通常把待抓队列按主机（域名）拆成许多小队列，每个站点在一段时间内只放行有限的请求，并遵守网站根目录下 robots.txt 文件里的规则（第四章已介绍）。这好比分拣中心给每家小店单独排班，不让一辆车同时冲进同一条小巷。

## 5.1.3 去重与回流：别把同一件货取两次

抓取流里最容易“淤积”的地方，是重复。同一个页面可能挂着不同的网址：带不带“www”、结尾有没有斜杠、后面跟着追踪参数……爬虫因此要先做网址规范化（URL Normalization），把这些写法统一成一种，再拿去和“已见网址集合”比对。

这个集合大到无法简单地逐条查，工程上常用布隆过滤器（Bloom Filter）一类的结构：用很小的空间快速判断“这个网址大概率见过”，代价是偶尔误判，把少数新网址当成见过而漏掉。这是一个典型的“用一点准确换大量速度和空间”的取舍。

内容层面的重复——比如转载文章、镜像站点——则要等页面下载后，用指纹或近似重复检测来识别，这部分在第二章文档处理中讲过。

还有一种特殊的“淤积”叫爬虫陷阱（Crawler Trap）：例如一个日历页面，每点“下一月”就生成一个新网址，可以无限点下去。爬虫一般会限制单站抓取深度、识别规律性无限网址，及时止损。

## 5.1.4 并行与分布：一条流变成千万条支流

单台机器每秒能下载的页面有限，大型搜索引擎的爬虫必然是分布式的。常见做法是按主机名做哈希，把不同网站分配给不同的抓取节点：同一个网站总是落在同一个节点上，既方便执行礼貌性限制，也避免多个节点重复抓取。节点之间只交换“这个网址属于你”的消息。

于是，从宏观看，抓取流像一张水系图：种子是源头，待抓队列是水库，调度器是闸门，各抓取节点是并行的支流，下载的网页流向索引系统，抽出的新链接又回流进水库。

## 5.1.5 小结：抓取流决定了你“能搜到什么”

你在搜索框里永远搜不到一个从未被抓取的页面。抓取流的覆盖范围、先后顺序和回访频率，决定了索引里有什么、有多新。它的核心矛盾也很清楚：网页无限，资源有限，所以每一步都在做取舍——先抓谁、多久再来、哪些是重复、哪里该止步。

网页被抓回来之后，还只是一堆原始的 HTML 文本。下一节，我们跟着这些“原材料”进入索引流，看它们怎样被一步步加工成能在毫秒间检索的倒排索引。
