# 3.1 计算：处理请求与运行程序

你在相册里点开“同步到云端”，几秒钟后照片旁边出现一个小小的对勾。这几秒里，远方机房里有不止一台服务器在为你“干活”：有的检查你的账号和登录状态，有的接收照片数据并决定存到哪里，有的生成缩略图，有的识别照片里有没有人脸、是不是海边。第二章我们拆开了服务器这台“机器”，这一节换个角度看：服务器到底在做什么？答案可以概括为两个字：计算。

## 3.1.1 一次上传，被拆成许多小任务

在数据中心里，“计算”不是指做数学题，而是指运行程序、处理请求（Request）。所谓请求，就是从你的手机发出的一句“话”，例如“这是我的照片，请保存”“把我 2023 年的照片列出来”。一次看似简单的上传，在服务端往往会被拆成一串小任务：

| 步骤 | 服务器在做什么 | 计算特点 |
|---|---|---|
| 身份验证 | 核对登录凭证，确认是你本人 | 量小、要求快 |
| 接收数据 | 收下照片文件，计算校验值防止传错 | 读写多、算得少 |
| 生成缩略图 | 把几兆字节的大图缩成小图 | 消耗处理器算力 |
| 内容识别 | 用模型判断画面内容，方便日后搜索 | 计算量大，常用加速芯片 |
| 写入索引 | 记录“这张照片属于谁、存在哪里” | 要求准确、不能出错 |

这些任务不一定在同一台机器上完成。大型服务通常把系统拆成许多相对独立的小程序，各自负责一件事，常被称为“微服务”（Microservice）。好处是哪一环忙不过来就单独给哪一环加机器，像餐馆里洗菜、切配、炒菜分开安排人手。

## 3.1.2 处理器怎样“干活”：取指令、算、写回

无论任务多复杂，落到硬件上都是中央处理器（CPU，Central Processing Unit）在一条条执行指令：从内存取出指令和数据，进行运算，再把结果写回去。手机里的处理器也是这样工作的，区别主要在规模和侧重点：

- **核心更多**：手机芯片常见 8 个左右核心；写作时主流服务器处理器单颗常有几十个核心，高端型号可达上百个，一台服务器还常装两颗。
- **内存更大**：手机内存一般是几 GB 到十几 GB，服务器常见几百 GB，高配机型达到 TB 级。
- **长期满负荷**：手机大部分时间在“打盹”，服务器则被设计成 7×24 小时连续工作。

为什么要这么多核心？因为数据中心面对的是海量用户的同时请求。一个核心一次专注一件事，几十个核心就能同时处理几十个请求，再加上操作系统在毫秒级快速切换，一台服务器每秒可以应付成百上千个简单请求。这叫并发（Concurrency），是服务器计算最核心的特征之一。

## 3.1.3 通用计算与加速计算

CPU 像一位样样都会的全能工匠，适合逻辑复杂、分支多的工作，比如校验账号、处理订单。但有些任务的特点是“同样的简单运算重复亿万次”，比如处理图像像素、运行神经网络模型。这时更适合交给加速器：

| 类型 | 中文解释 | 擅长的事 |
|---|---|---|
| CPU | 中央处理器 | 通用逻辑、操作系统、各类业务程序 |
| GPU（Graphics Processing Unit） | 图形处理器，拥有成千上万个简单计算单元 | 大规模并行运算，如 AI 训练与推理 |
| 专用加速芯片（如 ASIC，专用集成电路） | 为特定任务定制的芯片 | 特定场景效率高，例如谷歌为机器学习自研的 TPU |
| DPU / SmartNIC | 数据处理器 / 智能网卡 | 分担网络、存储、安全等“杂务”，让 CPU 专心算业务 |

识别你照片里的“猫”或“海滩”，以及你向 AI 助手提问，背后多半就是 GPU 或专用芯片在工作。它们功耗高、发热大，正是第七章要讲的 AI 算力中心和液冷技术出现的原因。

## 3.1.4 计算是“按需取用”的资源

在你家电脑上，一个程序独占一台机器很正常；在数据中心，这样太浪费。公开资料中常提到，传统企业服务器的平均利用率长期偏低，很多时间处理器是闲着的。于是数据中心把计算当作一种可以切分、调配的资源：一台物理服务器可以被分成多台虚拟机或许多个容器，分给不同的程序使用；白天相册上传多，就多分点资源给上传服务，深夜做批量整理、备份时再把资源挪过去。

衡量计算能力，工程师常看几类指标：

- **吞吐量**：每秒能处理多少请求；
- **延迟**：单个请求从进来到返回要多久，通常以毫秒计；
- **利用率**：处理器有多大比例的时间在干活。

这三者常常相互牵制：利用率压得太满，排队变长，延迟就会上升。好的数据中心不是让每台机器都跑到 100%，而是在“不浪费”和“不卡顿”之间找平衡。具体怎样切分、怎样分派请求，会在第六章“虚拟化与容器”“负载均衡与调度”中展开。

## 3.1.5 小结：计算是数据中心的“发动机”

回到那个小对勾：它意味着验证、接收、处理、识别、记录这一串计算全部完成。计算是数据中心存在的直接目的，其余部分都在为它服务：存储为它保存原料和成品，网络为它传递请求，供电给它能量，制冷带走它产生的热。但计算的成果如果没有被可靠地保存下来，一切就会随断电而消失。下一节，我们就跟着你的照片，看它怎样被“存好、不丢”。
