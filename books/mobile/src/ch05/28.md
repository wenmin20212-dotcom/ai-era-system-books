# 5.3 用户数据流：一个视频分组的完整旅程

你在地铁站台上滑开短视频应用，手指一划，下一个视频几乎立刻开始播放。屏幕右上角的“5G”或“4G”图标纹丝不动，好像什么都没发生。其实这一刻，成百上千个数据分组正从千里之外的服务器出发，穿过互联网、运营商核心网、传输光纤和基站，最后经由几十米到几百米的空中电波落进你的手机。上一节讲的信令流是“打招呼、办手续”，这一节要追踪的是真正的“货物”，也就是用户数据。我们选一个视频分组作样本，看它从服务器到屏幕走了哪几段路、每一段换了什么“包装”。

## 5.3.1 出发之前：通道已经铺好

视频分组上路之前，有一件事已经办完：手机开机登记、建立数据连接时，网络为它准备了一条逻辑通道。在 4G LTE 里，这条通道叫 **EPS 承载（EPS Bearer，演进分组系统承载）**；在 5G 里叫 **PDU 会话（PDU Session，协议数据单元会话）**，会话内部再按业务要求分成若干 **QoS 流（QoS Flow，服务质量流）**。手机也在这时拿到一个 IP 地址，好比给收件人分配了门牌号。

可以把它想象成快递公司事先为你开通的一条专线：起点是运营商网络通往互联网的“出入口”，终点是你的手机，沿途每个站点都知道这条专线的编号。之后的视频分组不需要逐站问路，只要贴上专线编号，就能沿既定路线传递。这正是第二章所说“控制面”和“用户面”分离的意义：手续由控制面一次办好，货物由用户面高速搬运。

## 5.3.2 第一段：从互联网进入运营商的大门

视频平台的服务器（通常位于内容分发网络 CDN 的某个节点上，详见本系列第二十五册）把一小段视频切成 IP 分组，目的地址就是你手机的 IP 地址。分组在互联网上一路转发，到达运营商网络的出入口：

- 4G 中是 **PGW（PDN Gateway，分组数据网网关）**；
- 5G 中是 **UPF（User Plane Function，用户面功能）**。

这个网关做三件关键的事：一是根据目的地址认出“这是某某用户的分组”；二是按规则把它归入相应的承载或 QoS 流，例如普通视频走“尽力而为”的等级；三是为计费、合规统计记录流量。随后，网关给分组“套一个信封”，这就是 **GTP-U 隧道（GPRS 隧道协议用户面）**。信封上写着隧道编号（TEID，隧道端点标识），外层再加一个新的 IP 头，目的地是你此刻所在的基站。

为什么要套信封？因为你的手机会移动。原始分组的地址始终是手机的 IP 地址，而外层信封的地址可以随你换基站而改写。这样，互联网上的服务器完全不必知道你在哪座基站下，“边走边连”的复杂性被关进了运营商网络内部。

## 5.3.3 第二段：穿过传输网到达基站

套好信封的分组进入传输网和承载网，经过汇聚路由器、光纤，有时还有微波链路，到达基站。4G 里这段接口叫 S1-U，5G 里叫 N3。对传输网来说，它只看外层地址和优先级标记，按普通 IP 分组转发，并不关心里面装的是视频还是网页。

基站收到后拆掉 GTP-U 信封，根据隧道编号判断：这个分组属于哪个用户、哪个承载或 QoS 流。接下来，分组就要从“有线世界”进入“无线世界”了。

## 5.3.4 第三段：在基站里换上空中包装

空口资源稀缺、信道多变，所以基站要在分组外面再层层加工。用第四章介绍的用户面协议栈看，自上而下依次是：

| 层次 | 中文名 | 对视频分组做什么 |
|---|---|---|
| SDAP（仅 5G） | 业务数据适配协议 | 把 QoS 流映射到无线承载 |
| PDCP | 分组数据汇聚协议 | 压缩 IP 头、加密、编序号 |
| RLC | 无线链路控制 | 切分或拼接成适合发送的块，必要时重传 |
| MAC | 媒体接入控制 | 由调度器决定何时、用哪些资源块发送，HARQ 快速重传 |
| PHY | 物理层 | 信道编码、调制、多天线发射 |

几处细节值得留意。PDCP 还可以做头压缩，把几十字节的 IP 和 UDP 头压到很小，这一功能主要用于语音等小分组业务，能省下宝贵的空口资源；加密也在这里完成，密钥正是 3.4 节鉴权时推导出来的，所以空中截获的电波无法直接还原内容。MAC 层的调度器每隔很短时间（LTE 典型为 1 毫秒，5G 可更短）就重新决定“这一刻把资源给谁”，信号好的用户可能分到更高阶调制、更多比特，机制细节留到第六章。

到了物理层，比特变成调制符号，再变成电磁波，从天线发出，穿过车厢玻璃、人群和墙壁，被手机天线接收。

## 5.3.5 最后一段：手机里拆包，屏幕上成像

手机的处理方向正好相反：物理层解调译码，MAC 和 RLC 把碎块按序拼回，必要时请求重传；PDCP 解密、恢复 IP 头、按序号排好；最后还原出与服务器发出时内容一致的 IP 分组，交给操作系统和视频应用。应用把收到的视频片段放进**缓冲区**，解码后显示在屏幕上。

缓冲区是你“感觉不到卡顿”的秘密之一：播放器总是提前多下载几秒内容，偶尔某个分组晚到或需要重传，只要缓冲还没耗尽，画面就不受影响。很多视频应用还会根据实测速率自动调整清晰度，这属于应用层的做法，不同平台策略各不相同。

如果你在途中换了基站怎么办？核心网会把网关到基站这段隧道的终点改到新基站，旧基站还可把尚未发完的分组转交给新基站。视频分组本身毫不知情，它的“门牌号”从未改变，这就是 3.3 节切换在用户面上的体现。

## 5.3.6 小结：一次旅程，三层包装

回头看，一个视频分组的旅程可以概括为“一个不变、两层可变”：内层 IP 地址指向你的手机，始终不变；核心网与基站之间用 GTP-U 隧道应对移动；空口用 PDCP、RLC、MAC、PHY 应对稀缺而多变的无线信道。上行方向，比如你上传评论或直播画面，走的正是同一条路的反向。理解了这条路，就能明白测速结果里的“时延”和“速率”分别卡在哪里。下一节我们换一种货物，看看对时延最敏感的语音，是怎样从电路交换一路走到 VoLTE 和 VoNR 的。
