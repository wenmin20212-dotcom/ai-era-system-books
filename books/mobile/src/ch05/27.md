# 5.2 信令流：开机、待机与来电时的“对话”

把手机从飞行模式切回正常模式，右上角先是“无服务”，几秒钟后出现运营商名称和信号格，再过一会儿冒出“5G”或“4G”字样。这几秒钟里，你什么都没做，手机却已经和网络说了几十句“话”。这些不承载你的声音和视频、专门用来协商“怎么连、连到哪、用什么参数”的消息，叫作信令（Signaling）。如果说上一节的无线信号流是道路，下一节的用户数据是货车，那么信令就是调度电话：货还没上路，调度先要把路线、通行证和装卸时间谈妥。

本节沿着手机生活中最常见的三个时刻，开机、待机、来电，听一听这段“对话”的内容。为便于叙述，以下以 4G LTE 和 5G 的标准流程为主，名称依据 3GPP 规范；不同网络在细节上有取舍，但骨架相同。

## 5.2.1 信令和数据：两条并行的“车道”

在移动网络里，控制和承载是分开设计的。3GPP 把它们称为控制面（Control Plane）和用户面（User Plane）：

| 对照项 | 信令（控制面） | 用户数据（用户面） |
|---|---|---|
| 内容 | 登记、鉴权、建立连接、切换、寻呼等消息 | 网页、视频、语音分组 |
| 数据量 | 小，单条常为几十到几百字节 | 大，可达每秒数百兆比特量级 |
| 主要对端 | 基站、核心网中的移动性管理实体（4G 的 MME，5G 的 AMF） | 核心网中的网关（4G 的 S-GW/P-GW，5G 的 UPF） |
| 关键要求 | 可靠、有序、不能丢 | 速度快、时延低 |

空口上，信令主要由两层协议承载：一是无线资源控制（Radio Resource Control，RRC），手机和基站之间“谈无线资源”；二是非接入层（Non-Access Stratum，NAS），手机越过基站直接和核心网“谈身份与业务”，基站只负责转交，看不懂也不改动其中内容。记住这两个名字，下面的对话就容易听懂了。

## 5.2.2 开机：从“找网”到“报到”

开机后的信令过程可以分成四步，像一个新员工第一天进大楼。

1. **找门牌（小区搜索）。** 手机扫描所支持的频段，捕捉基站周期性发出的同步信号，对齐时间和频率，再读取广播的系统信息，得知这是哪个运营商、哪个小区、允许怎样接入。这一步只听不说。
2. **敲门（随机接入）。** 手机在指定的时频位置发出一段前导序列，相当于举手示意。基站回复时间提前量和临时编号，双方再交换一两条消息，避免多台手机“撞车”。
3. **建立 RRC 连接。** 手机与基站建起专用的信令通道，从此可以“说完整的句子”。
4. **向核心网报到（注册）。** 手机通过 NAS 发出注册请求（4G 称附着 Attach，5G 称注册 Registration）。核心网随即发起鉴权：根据 SIM 卡中的密钥出一道“题”，手机算出答案并回传，同时双方各自推导出后续加密用的密钥（原理见第三章 3.4 节）。鉴权通过后，启动加密和完整性保护，核心网为手机分配临时身份标识，并通常建立默认的数据会话，分配 IP 地址。

到这一步，信号格亮起、网络制式图标出现，手机才算正式“上岗”。整个过程通常在一两秒到数秒之间完成，取决于信号质量和网络负荷。

## 5.2.3 待机：省电的“轻声细语”

手机大部分时间处于待机，屏幕黑着，口袋里安静。但信令并没有停，只是换成了最省电的方式。

没有数据要传时，基站会把手机从连接态（RRC_CONNECTED）释放到空闲态（RRC_IDLE）；5G 还增加了非激活态（RRC_INACTIVE），保留部分上下文，下次恢复连接更快。空闲时手机做三件事：

- **周期醒来听广播。** 按照不连续接收（Discontinuous Reception，DRX）周期，手机只在约定时刻短暂醒来，查看有没有呼叫自己的消息，其余时间关闭大部分射频电路，这是待机耗电低的关键。
- **默默测量、自主重选。** 手机持续测量周围小区的信号，发现更好的就悄悄“搬过去”驻留，称为小区重选，不必通知网络。
- **跨区才报到。** 网络把若干小区编成一个跟踪区（Tracking Area）。手机只有走出原先登记的跟踪区范围，或者周期定时器到期，才发一次跟踪区更新或注册更新，告诉核心网“我大概在这一片”。

这是一种精心设计的折中：报告太勤，手机费电、网络信令拥挤；报告太少，有来电时网络不知道去哪里找人。

## 5.2.4 来电：寻呼——在一片区域里喊名字

别人给你打电话或发来消息时，核心网只知道你在哪个跟踪区，不知道在哪个小区。于是它让该区域内的所有基站一起广播寻呼（Paging）消息，相当于在整栋楼的广播里喊“某某请到前台”。

1. 核心网向跟踪区内的基站下发寻呼，携带你的临时标识（而不是真实号码，以保护隐私）。
2. 你的手机在 DRX 醒来的时刻听到自己的“名字”。
3. 手机发起随机接入、建立 RRC 连接，发送服务请求。
4. 核心网恢复安全上下文，为通话建立专门承载（VoLTE、VoNR 中语音还要经过 IMS 系统的呼叫信令，见 5.4 节）。
5. 手机响铃。

从对方拨号到你的手机响铃，耗时一般在一两秒到几秒，其中寻呼周期、信号覆盖和网络负荷都有影响。如果你恰好在地下室没有信号，寻呼得不到回应，对方就会听到“暂时无法接通”。

## 5.2.5 信令为什么会“堵车”

信令单条很小，但数量极多。一部手机每天会经历数十到上百次空闲与连接之间的转换，大量物联网终端、频繁“心跳”的应用都会放大这个数字。公开的运营商与标准资料中曾多次讨论“信令风暴”：当大量终端在短时间内同时发起接入或注册，比如大型活动散场、网络故障恢复后的集中重连，控制面设备可能先于用户面达到瓶颈。为此，3GPP 设计了接入等级限制、随机化重试时间、延长 DRX、5G 的非激活态等机制来“削峰”。

由此可见，信令流决定了用户的数据流能否被正确启动和维持。开机注册拿到“通行证”，待机时以最低成本报告位置，来电时通过寻呼把人找到。下一节，我们就让通行证派上用场，跟随一个视频分组，看它在用户面上走完全程。
