# 5.1 无线信号流：从电磁波到比特

把手机举到眼前，打开一段短视频。画面流畅播放的这几秒钟里，手机和附近某座基站之间的空气中，正持续传递着一种看不见的东西：频率在几百兆赫到几吉赫之间（毫米波频段更高）的电磁波。它没有声音，也不占地方，却承载着视频的每一帧。前几章看的是系统由什么组成、各部分怎样连接，从这一节开始换一个角度，跟着系统里“流动的东西”走。第一种流动，就是空中的无线信号。它要回答的问题是：一串 0 和 1，怎样变成电磁波飞过空气，又怎样在另一端变回 0 和 1。

## 5.1.1 从比特到电波：发射端的四道工序

手机要上传一张照片，或基站要下发一段视频，原始材料都是比特（bit，二进制位）。这些比特不能直接“扔”进空气，要先经过发射链路上几道工序。用寄送易碎品来类比，大致是下面这样：

| 工序 | 做什么 | 寄包裹的类比 |
|---|---|---|
| 信道编码（Channel Coding） | 给数据加上有规律的冗余，让接收端能发现并纠正错误 | 往箱子里塞泡沫，磕碰了也不至于全坏 |
| 调制（Modulation） | 把几个比特映射成一个“符号”，用电波的幅度和相位来表示 | 把货物装进规格统一的箱子 |
| 资源映射与多天线处理 | 把符号放到特定的频率和时间格子上，必要时分配到多根天线 | 决定走哪条车道、哪个班次 |
| 射频发射 | 把基带信号搬到载波频率上，经功率放大后由天线辐射出去 | 装车上路 |

前三道工序在手机的基带芯片里完成，处理的是数字信号，这部分叫“基带”（Baseband）。第四道工序由射频（Radio Frequency，RF）部分完成：数字信号先在射频收发器中经数模转换器（DAC）变成模拟波形，再由混频器“骑”到载波上，最后经射频前端放大、滤波后送往天线。比如在一个 3.5 吉赫的 5G 频段，载波每秒振荡约 35 亿次，信息就体现在这个振荡的幅度和相位的细微变化里。最后功率放大器把信号放大，天线把电流的变化转换成向外传播的电磁场。

这里有一个容易误解的地方。载波频率高，并不等于数据就快。真正决定能装多少数据的，是载波周围占用的那一段频率宽度，即“带宽”（Bandwidth）。LTE 的单个载波最大为 20 兆赫，5G 新空口在中频段的单载波常见 100 兆赫，毫米波频段可以更宽。这些数字来自 3GPP 规范。带宽和速率的关系，第八章讲香农定理时再细说。

## 5.1.2 空中旅程：电波在路上遭遇了什么

电磁波离开天线后，以光速传播，几公里的距离只需要十几微秒。但这段路并不平坦，主要有三类遭遇：

- **衰减**：能量向四面八方扩散，距离越远，单位面积收到的能量越少。墙体、树木、人体还会吸收一部分。频率越高，穿墙和绕过障碍物的能力通常越弱。这也是毫米波基站覆盖范围有限的原因。
- **多径**：同一个信号经地面、楼宇、车辆反射后，沿多条路径先后到达。各路信号叠加时，有时互相加强，有时互相抵消。手机移动几厘米，信号强弱就可能明显起伏，这叫“多径衰落”。
- **干扰与噪声**：其他小区、其他用户的信号，加上电子器件自身的热噪声，混在一起进入接收天线。

所以，到达手机的已经不是发出时那个干净的波形，而是被削弱、被拉散、被污染的版本。手机右上角的信号格，粗略反映的就是这一路折损之后还剩多少。在 LTE 和 5G 中，手机测量的典型指标是参考信号接收功率（Reference Signal Received Power，RSRP），单位是 dBm。公开资料中常见的经验区间是：高于约 -80 dBm 算很好，低于约 -110 dBm 就比较弱。不过各厂商把 RSRP 换算成几格信号的规则并不统一。具体的传播原理留到 8.2 节溯源。

## 5.1.3 从电波到比特：接收端的“逆向拆箱”

接收端要做的事情，就是把发射端的工序倒过来做一遍，同时设法修复路上造成的损伤：

1. **天线接收与射频处理**：天线把微弱的电磁场重新变成电流。低噪声放大器先把信号放大，混频器再把它从载波频率“搬”回基带，模数转换器（ADC）随后把它变成数字样本。
2. **同步**：手机要先对齐时间和频率，知道每个符号从哪里开始。基站周期性发送的同步信号就是用来做这件事的，就像合唱前先听定音。
3. **信道估计与均衡**：基站在发送的数据中按规则插入了“参考信号”（Reference Signal）。这是收发双方事先约定好的已知内容。手机把收到的参考信号和原本应有的样子对比，就能推算出信道把信号扭曲成了什么样，然后对数据部分做反向校正。打个比方，这就像先看一张标准色卡被照片拍成了什么颜色，再据此给整张照片调色。
4. **解调**：根据校正后每个符号的幅度和相位，判断它最可能代表哪几个比特。
5. **信道译码**：利用发射端加入的冗余纠正错误。LTE 数据信道使用 Turbo 码，5G 新空口数据信道使用 LDPC 码（低密度奇偶校验码），控制信道使用 Polar 码（极化码），这是 3GPP 的标准化选择。译码完成后，还要做循环冗余校验（CRC）。校验通过，比特就交给上层；校验不通过，就请求重传。

这套逆向过程在手机里每秒要重复成千上万次。5G 新空口中，一个时隙的长度随子载波间隔不同而变化，常用配置下在 1 毫秒到 0.125 毫秒之间，更高的子载波间隔下还会更短，基带芯片必须在极短的时间内完成上述计算。正因为如此，基带芯片是手机里计算最密集的部件之一。

## 5.1.4 为什么不是“一次传对”：系统的自适应

既然路况多变，系统就不会用一套固定参数应付所有情况。手机会定期向基站报告信道质量，在 LTE 和 5G 中称为信道质量指示（Channel Quality Indicator，CQI）。基站据此为每个用户选择调制方式和编码速率：信号好时“装得满一些”，一个符号携带更多比特；信号差时“多垫泡沫”，速度慢一点，但更可靠。万一某一块数据仍然没有收对，混合自动重传请求（Hybrid ARQ，HARQ）机制会让基站补发。手机把补发的内容和之前收到的部分合并起来译码，不必从头再来。

这就是你走进电梯时视频先卡一下、却很少直接报错的原因。系统一直在测量、调整、补发，用速率的波动换取连接的稳定。调制编码如何选择、资源如何分配，第六章会展开讲。

## 5.1.5 小结

无线信号流可以概括为一条对称的链路：发射端把比特依次加冗余、装符号、上载波、辐射出去；电波在空中经历衰减、多径和干扰；接收端经过同步、信道估计、解调和译码，把比特还原出来，并通过质量反馈和重传形成闭环。

这条链路只负责把比特在空中搬运可靠。至于这些比特是谁的、要去哪里、什么时候该发，则要靠另一种流动来安排，也就是下一节要讲的信令流。
