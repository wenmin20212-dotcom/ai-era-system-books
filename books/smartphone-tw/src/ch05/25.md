# 5.3 快門瞬間的光電洪流：毫秒級的運算攝影接力

舉起手機對準窗外的晚霞，輕點螢幕上那個白色圓圈。「喀嚓」一聲，照片幾乎立刻出現在相簿角落。這個動作在你看來只用了一瞬間，手機內部卻完成了一場分工極細的接力：光子被轉換成電子，電子被量化成數字，數字被高速搬運、清洗、對齊、融合，最後壓縮寫入快閃記憶體。整條鏈路要在毫秒到幾百毫秒的尺度內跑完，任何一棒掉速，你就會感到「拍照卡頓」或「照片糊了」。

本節沿著資料流動的方向，把這場接力拆成六棒逐一說明。

## 5.3.1 第一棒：光電二極體累積光生電子

鏡頭把光線匯聚到影像感測器表面。感測器上排列著數以千萬計的像素，每個像素的核心是一枚**光電二極體**（Photodiode）。可以把它想像成一只接雨的小桶：曝光期間，落進來的光子打出電子，電子被收集在桶裡，光越強，桶裡的電子越多。

在常見的曝光時長裡，大約是幾十分之一秒，一個像素可以累積**數十萬個光生電子**。電子的數量就是這個像素記錄下的「亮度原始資訊」。不過此時它還只是一份類比電荷，處理器沒辦法直接使用。

## 5.3.2 第二棒：晶片上 ADC 量化為 14-bit RAW

電荷先被轉成電壓，再交給整合在感測器晶片上的**類比數位轉換器**（ADC，Analog-to-Digital Converter），由它把連續變化的電壓「切片」成整數。常見的精度是 **14-bit**，也就是每個像素的亮度被劃分為 2¹⁴ = 16384 個等級。

這樣得到的結果叫 **RAW 資料**：一張由灰階數值組成的矩陣，每個格子只記錄亮度，不包含完整顏色。感測器表面覆蓋著紅、綠、藍交替排列的濾色片，每個像素只「看見」一種顏色，顏色要到後面的環節才能還原。

> 打個比方：RAW 就像一份沒有整理過的原始調查問卷，資訊最完整，但還沒人統計和解讀。

## 5.3.3 第三棒：MIPI CSI-2 高速通道與零快門延遲

數千萬像素、每個 14 位元，單幀資料量就以數十 MB 計，而相機在取景時還在連續出幀。這些資料要從相機模組送到主機板上的 SoC，走的是 **MIPI CSI-2**（行動產業處理器介面聯盟制定的相機序列介面第二版）。它採用**差動訊號**：用兩根線傳輸一對相反的電壓，接收端只看兩者之差，外部干擾會同時作用在兩根線上而被抵消，所以能在細軟的排線上穩定跑高速。常見的速率是**每條通道（lane）2.5Gbps 以上**，多條通道並行，就像多線道高速公路。

資料抵達後，被直接寫進 **LPDDR**（低功耗雙倍資料率記憶體）中的一塊**環形緩衝區**。寫入由 **DMA**（Direct Memory Access，直接記憶體存取）完成，不必勞煩 CPU 逐字搬運。「環形」是指緩衝區首尾相接，新幀不斷覆蓋最舊的幀。

這樣安排的目的是**零快門延遲**（ZSL，Zero Shutter Lag）。你打開相機時，感測器其實已經在持續拍攝並存入緩衝區；按下快門的那一刻，系統直接取出「剛才那幾幀」，而不是從按鍵時刻才開始曝光。你覺得照片「抓住了瞬間」，原因就在此。

## 5.3.4 第四棒：硬體 ISP 的基礎清洗

取出的 RAW 幀先交給 **ISP**（Image Signal Processor，影像訊號處理器）。它是 SoC 裡專門為影像設計的固定電路，以管線方式做三件基礎工作：

1. **壞點修正**：感測器上難免有個別像素永遠偏亮或偏暗，ISP 用周圍像素的數值取代它們；
2. **暗角補償**：鏡頭邊緣進光少，畫面四角容易發暗，ISP 依預先校準的曲線把邊緣提亮；
3. **去馬賽克**（Demosaic）：根據相鄰像素的紅、綠、藍讀數，推算出每個像素完整的三種顏色。

這些步驟規則固定、運算量大，用專用硬體處理比通用 CPU 快得多，也省電得多。這正是第三章所說「專晶專用」的體現。

## 5.3.5 第五棒：NPU 多幀融合與神經網路降噪

手機感測器面積小，單幀容易雜訊多、亮暗細節難以兼顧。計算攝影的思路是：**一幀不夠，就用多幀拼**。此時 **NPU**（Neural Processing Unit，神經網路處理器）登場，負責兩項工作。

- **RAW 域光流對齊**：多幀之間手會抖、人會動。「光流」是估算畫面中每一塊區域在幀與幀之間移動方向和距離的方法，算清楚之後，把各幀「挪」到同一位置再疊加。
- **動態融合**：對運動物體所在區域降低疊加權重或只取一幀，避免出現半透明重影，也就是**運動鬼影**。

疊加之後，再用**深度神經網路降噪**：模型從大量樣本中學會區分「真實紋理」和「隨機雜訊」，比傳統濾波更能保留髮絲、樹葉等細節。之所以在 RAW 域就做融合，是因為此時資料尚未經過有損處理，保留的資訊最多。

## 5.3.6 第六棒：色調映射與寫入快閃記憶體

融合後的影像亮度範圍很寬，而螢幕和常見圖片格式能顯示的範圍有限。**色調映射**（Tone Mapping）負責「壓縮動態範圍」：暗部適度提亮、亮部適度壓低，讓天空和室內都看得清楚。隨後影像被編碼壓縮，寫入 **UFS 4.0**（通用快閃記憶體儲存第四代）快閃記憶體。UFS 支援讀寫同時進行，寫入快，連拍時就不容易卡住。

## 5.3.7 接力全景

| 棒次 | 執行者 | 輸入 → 輸出 | 關鍵作用 |
|---|---|---|---|
| 1 | 光電二極體 | 光子 → 電子（數十萬/像素） | 感光 |
| 2 | 晶片上 ADC | 電壓 → 14-bit RAW | 數位化 |
| 3 | MIPI CSI-2 + DMA | 感測器 → LPDDR 環形緩衝 | 高速搬運、ZSL |
| 4 | ISP | RAW → 清洗後的彩色資料 | 壞點、暗角、去馬賽克 |
| 5 | NPU | 多幀 → 單幀融合降噪 | 去鬼影、保細節 |
| 6 | 編碼 + UFS 4.0 | 影像 → 快閃記憶體檔案 | 色調映射、儲存 |

## 5.3.8 小結

一次快門，橫跨了光學、半導體、高速介面、記憶體架構、專用電路和神經網路六個領域。照片好不好看，不只取決於鏡頭和感測器，也取決於這條管線中最慢的那一環。下一節討論的是相反的場景：螢幕熄滅之後，這些模組如何安靜下來，只用微安培級電流維持「隨時待命」。
