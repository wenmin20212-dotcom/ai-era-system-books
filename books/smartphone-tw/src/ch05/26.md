# 5.4 熄屏時的休眠脈動：微安級的「假死」與喚醒

晚上睡前，你把手機扣在床頭櫃上，螢幕一黑，房間安靜下來。第二天早上拿起來，電量只掉了一小截。可就在這一夜裡，它沒有真正「關機」：微信訊息照樣推送進來，來電照樣能接通，你一抬手，螢幕還會自己亮起。

這說明熄屏後的手機處在一種「假死」狀態：大部分器官停止工作，少數哨兵繼續值班。前面幾節講的是射頻、快充、拍照這些高強度的流動，本節反過來看機身裡最微弱、持續時間卻最長的一種流動，也就是待機時的電流。

## 5.4.1 熄屏之後，誰被「拉閘」了

先打個比方。一棟辦公大樓到了深夜，辦公區的燈、空調、電梯都關了，只剩門口警衛室亮著一盞小燈。警衛盯著監視器，有人刷卡進門，他才去開一層樓的燈。

手機熄屏時的做法與此類似。螢幕熄滅後，幾個耗電大戶的**供電軌**會被徹底切斷。供電軌（Power Rail）指電源管理晶片給某一組電路單獨分配的供電線路，可以理解為大樓裡分區的電閘。被切斷的主要有三類：

- **主 SoC 的高效能運算核心**：平時跑應用程式、算介面的 CPU 大核和中核；
- **GPU（圖形處理器，Graphics Processing Unit）**：負責算繪畫面，螢幕不亮時沒有活可幹；
- **螢幕本身的供電**：顯示面板和驅動電路是手機裡最耗電的部件之一。

這裡說的是「切斷」，不是「降頻」。降頻好比把燈調暗，電閘斷開才是徹底不耗電。數位電路即使不做運算，電晶體也會有微小的漏電，晶片規模越大，漏電總量越可觀。所以在待機這件事上，把整塊電路斷電比讓它「低速空轉」省電得多。

## 5.4.2 常開硬體島：SoC 裡的「警衛室」

主系統都斷了電，那抬手亮屏是誰偵測到的？答案藏在 SoC 內部一塊特殊區域，叫**常開硬體島**（Always-On Island）。

「島」這個字很貼切。SoC 被劃分成許多電源域，每一塊都可以單獨開關。常開島是其中供電永不中斷的一小塊，和周圍斷電的區域互相隔離，好比夜裡停電的城市中，一座靠自備電源運轉的小島。

島上駐紮著一顆低功耗微控制器，通常稱為 **Sensor Hub（感測器中樞）**。它的結構比主 CPU 簡單得多，主頻低、電晶體少，幹活的方式也很專一：

1. 持續讀取**加速度計**和**陀螺儀**的資料。加速度計感知手機在各方向上的加速度和重力方向，陀螺儀感知手機旋轉的角速度；
2. 把這些資料串成隨時間變化的曲線，在裡面尋找「抬手」這一動作的特徵；
3. 只有當它算出抬手旋轉特徵曲線出現**上升沿**，也就是數值從平穩狀態突然明顯升高、符合「把手機從平放翻轉到面前」的規律時，才發出訊號喚醒主系統，點亮螢幕。

整個過程中，Sensor Hub 的電流消耗只有**微安級（μA）**。1 微安是 1 毫安的千分之一。手機打遊戲時電流常以「安」或數百毫安計，與之相比，Sensor Hub 就像警衛室裡那盞小檯燈和整棟大樓的中央空調之間的差距。

為什麼不讓主 CPU 自己來盯感測器？因為感測器資料是連續不斷湧來的。如果每來一點資料就叫醒一次主 CPU，它的大量電路要反覆上電、恢復狀態、處理資料、再斷電，單次喚醒本身就有不小的開銷。交給一個小而專一的微控制器全天候篩選，只把真正重要的事件上報，才能兼顧靈敏和省電。這正是第三章講過的「專芯專用」能效哲學在待機場景裡的體現。

## 5.4.3 5G 基頻的「打盹」節奏：非連續接收

還有一個問題：手機熄屏後為什麼還能接到電話？來電時，基地台會透過**傳呼通道**（Paging Channel）廣播一條訊息，大意是「某某號碼的手機，你有來電，請應答」。手機必須聽到這條廣播，才能接起電話。

但如果基頻晶片一直開著接收機，射頻通路長期處於工作狀態，電量會很快耗盡。於是 5G 基頻採用了**非連續接收**機制，英文是 Discontinuous Reception，簡稱 **DRX**。

DRX 的思路可以用一個場景說明：你在等一封重要的信，但不必整天守在信箱旁，只要和郵差約好每隔一段時間來查看一次就行。手機和基地台之間正是這樣「約好」的：

- 在**絕大部分時間**裡（具體比例取決於網路配置的 DRX 週期），基頻處於深度睡眠，接收電路基本關閉；
- 每隔**幾百毫秒**，基頻短暫甦醒**幾毫秒**，打開接收機，監聽一下傳呼通道上有沒有自己的訊息；
- 如果沒有，馬上回去睡覺；如果有，就完全喚醒，建立連線，把來電或資料交給主系統。

基地台知道手機按什麼節奏醒來，會在對應的時刻發送傳呼訊息，雙方的時脈必須對得上。這種節奏也帶來一個可以感知的折衷：甦醒間隔越長越省電，但訊息被聽到的時間也會稍晚一些。幾百毫秒的延遲，對接電話來說幾乎感覺不到，換來的是待機時間的大幅延長。

## 5.4.4 兩條脈動線的對照

把熄屏狀態下仍在工作的兩個「哨兵」放在一起看：

| 對比項 | Sensor Hub（常開硬體島） | 5G 基頻 DRX |
|---|---|---|
| 所在位置 | SoC 內部常開硬體島 | 基頻調變解調電路 |
| 監聽對象 | 加速度計、陀螺儀資料 | 基地台傳呼通道 |
| 工作方式 | 全天候低功耗讀取與計算 | 絕大部分時間深睡，週期性短暫甦醒 |
| 時間尺度 | 持續運行 | 每隔幾百毫秒醒來幾毫秒 |
| 功耗量級 | 微安級（μA） | 平均功耗極低，靠大幅縮短工作時間實現 |
| 喚醒條件 | 識別出抬手旋轉特徵的上升沿 | 傳呼通道中出現本機訊息 |
| 省電思路 | 用小晶片代替大晶片值班 | 用時間上的「斷續」代替「常開」 |

兩者的手段不同，一個是**空間上的分工**，讓最小的電路值班；一個是**時間上的切片**，讓必須工作的電路只在關鍵時刻上崗。手機的待機續航，基本就是這兩種思路疊加的結果。

## 5.4.5 小結：省電的關鍵在於「該睡就睡」

熄屏後的手機看起來靜止，內部其實保持著一種低而穩定的脈動：常開島上的 Sensor Hub 以微安級電流持續守望，基頻按 DRX 的節奏一呼一吸，其餘部分則被拉閘斷電。一旦出現抬手動作或來電傳呼，這套體系能迅速把整台手機喚醒。

本章前幾節看到的都是高峰時刻的能量與資料洪流，而這一節說明，系統設計同樣要處理低谷時刻的問題。下一節將把射頻、快充、計算攝影和休眠這四種流動放在同一張表裡，比較它們在時間、功率和資料量上的差異。
