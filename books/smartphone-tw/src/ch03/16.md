# 3.5 核心微型模組系統職能全景對照

前面四節，我們沿著運算、成像、射頻、觸覺與聲學幾條線索，把手機裡的微型模組逐一認識了一遍。現在不妨把它們放回同一部機器裡看。你手中這部手機，在點亮螢幕的那一刻，並不是某一顆晶片在單獨工作，而是十幾個子系統同時上崗。本節用一張全景對照表把它們的職責、衡量指標和背後的廠商整理到一起，再用一個小場景示範它們如何在毫秒之間交接任務。

## 3.5.1 一張表看清「誰做什麼」

下表按功能子系統劃分，每一列回答四個問題：硬體實體是什麼，它承擔什麼任務，用什麼指標衡量好壞，主要由哪些企業設計或製造。

| 功能子系統 | 核心硬體實體 | 承擔任務與功能本質 | 關鍵效能指標 | 代表性半導體與製造企業 |
|---|---|---|---|---|
| 通用調度與運算 | CPU 大中小核叢集 | 複雜邏輯判斷、系統回應與多執行緒調度 | 單核/多核 IPC、最高時脈（GHz） | ARM、高通、蘋果、聯發科 |
| 圖形算繪與顯示 | 行動 GPU 核心 | 3D 遊戲頂點轉換、著色器運算與 UI 畫格合成 | 浮點算力（TFLOPS）、每瓦效能 | 高通 Adreno、ARM Immortalis |
| 端側 AI 推論 | 專用 NPU 矩陣單元 | 本地大模型、電腦視覺與語音推論加速 | 稠密算力（TOPS）、量化支援（INT4/8） | 高通 Hexagon、蘋果 Neural Engine |
| 成像與光電轉換 | CIS 感光晶片 + ISP | 光子捕捉、類比數位轉換、RAW 域計算攝影演算法 | 靶面尺寸（如 1 吋）、動態範圍（dB） | 索尼 LYTIA、三星 ISOCELL、豪威 |
| 防手震與變焦機械 | 潛望三稜鏡 + 音圈馬達 | 毫秒級鏡片物理微移，補償手震與對焦 | 驅動力、對焦延遲（ms）、防手震角度 | 大立光、舜宇光學、阿爾卑斯 |
| 無線微波放大 | 射頻 PA 功率放大器 | 將發射訊號能量放大數千倍以抵達遠端基地台 | 輸出功率（dBm）、功率附加效率（PAE） | Skyworks、Qorvo、唯捷創芯 |
| 高頻訊號濾波 | BAW / SAW 濾波器 | 濾除頻帶外電磁雜波，實現全雙工隔離 | 插入損耗（dB）、帶外抑制比 | 博通（Broadcom）、村田製作所 |
| 瞬態觸覺模擬 | X 軸線性振動馬達 | 毫秒級水平定向往復震動，擬真按鍵回饋 | 穩態加速度（Grms）、啟停延遲（ms） | 瑞聲科技（AAC）、立訊精密 |

## 3.5.2 讀表的三把鑰匙

這張表資訊密集，橫著讀和直著讀能看到不同的東西。

**第一把鑰匙：看「功能本質」欄，分清通用與專用。** CPU 像一位什麼都能處理的總經理，擅長判斷和調度，但做重複性的大批量運算並不划算。GPU 更像生產線工人隊伍，同時處理成千上萬個像素；NPU（神經網路處理單元，Neural Processing Unit）專門做矩陣乘法；ISP（影像訊號處理器，Image Signal Processor）只服務於相機資料。越往下的模組越「專一」，同樣的任務交給它們，耗電往往遠低於讓 CPU 硬算。這正是 3.1 節所說的異質運算思路：讓合適的晶片做合適的事。

**第二把鑰匙：看「關鍵指標」欄，認出發表會參數的來歷。** 發表會上的 GHz、TFLOPS、TOPS、「1 吋大底」、dB，在這裡都能找到歸屬。需要留意兩點：
- 單一峰值數字不等於體驗。CPU 時脈高，若 IPC（每時脈週期執行的指令數，Instructions Per Cycle）低，實際速度未必快；GPU 浮點算力高，若每瓦效能差，玩久了就會因發熱降頻。
- 有些指標單位看似陌生，其實都指向「損耗」或「效率」。濾波器的插入損耗越小越好，PA 的功率附加效率（PAE，Power Added Efficiency）越高越省電。射頻部分的好壞，很大程度體現在續航和訊號上，而不是跑分裡。

**第三把鑰匙：看「企業」欄，體會分工格局。** 運算晶片的架構授權來自 ARM，再由高通、蘋果、聯發科設計成 SoC；感光晶片由索尼、三星、豪威供應；鏡頭和馬達來自大立光、舜宇光學、阿爾卑斯；射頻元件集中在 Skyworks、Qorvo、博通、村田，中國大陸也有唯捷創芯；振動馬達則有瑞聲科技、立訊精密。一部手機幾乎不可能由一家公司從頭造到尾，這一點將在第七章展開。

## 3.5.3 小場景：一次夜景快門裡的接力

紙面上的分工，要放進真實操作才看得清。設想你在昏暗的街邊舉起手機，按下快門：

1. **CPU 先接單。** 觸控控制器回報「快門被按下」，CPU 判斷這是拍照事件，喚醒相機流程，並調度各單元的頻率。
2. **機械元件同步動作。** 音圈馬達推動鏡片完成對焦，光學防手震持續反向補償手的晃動；若使用長焦，光線還要經過潛望三稜鏡轉折。
3. **CIS 連續曝光。** 弱光下，感測器會快速擷取多幀畫面，把光子轉成電訊號再轉成數位訊號。
4. **ISP 與 NPU 分工處理。** ISP 在 RAW 域對多幀進行對齊、降噪和合成；NPU 辨識場景中的天空、人臉、燈光，分區域最佳化。
5. **GPU 負責呈現。** 預覽畫面與成品縮圖由 GPU 合成到螢幕上。
6. **觸覺末梢收尾。** X 軸線性馬達給出一下短促的「喀噠」感，告訴你拍攝完成。

整個過程中，射頻 PA 若正在上傳雲端相簿，也會同時工作。此時發熱的主角通常是 ISP、NPU 與持續工作的 CIS 所在的 SoC 區域；系統面臨的物理瓶頸，是在極小的密閉機身裡同時控制功耗和溫度。這也是第六章要討論的溫控機制的出發點。

你可以把下面這段提示詞交給 AI 助理，替換方括號中的場景，讓它按本章框架複盤：

> 我正在閱讀《AI時代系統知識基礎讀物：智慧型手機》第三章。假設我在手機上執行以下操作：[例如：在弱光夜景下點擊相機拍照按鈕 / 在 5G 網路下啟動《原神》並開啟 60 幀極高畫質]。請基於本章的硬體功能分工框架，幫我複盤：
> 1. 【核心晶片協同】SoC 內部的 CPU、GPU、NPU 與 ISP 分別在毫秒尺度下分擔了哪些運算？
> 2. 【周邊模組介入】音圈馬達、CIS 感測器、射頻 PA 或 X 軸振動馬達在這一瞬間分別做出了什麼物理動作？
> 3. 【能耗與發熱短板】哪一個模組是主要發熱源？系統面臨的最大物理瓶頸是什麼？

拿到回答後，用上面的表格逐列核對：它有沒有把任務派給錯誤的模組？有沒有遺漏射頻或觸覺這類容易被忽視的元件？這種核對本身就是一次系統思維訓練。

## 3.5.5 小結

本章回答了「每個模組做什麼」：CPU 調度，GPU 算繪，NPU 推論，CIS 與 ISP 成像，馬達與稜鏡管機械，PA 與濾波器管電磁波，線性馬達管觸覺。分工清楚之後，新的問題隨之而來：這麼多模組，究竟如何塞進不到一公分厚的機身？下一章，我們進入物理與空間整合的世界。
