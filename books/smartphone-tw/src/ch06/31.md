# 6.4 硬體安全隔離區（TEE / Secure Enclave）：數位社會的金庫守衛

你把手指按在螢幕上，或者拿起手機看一眼，鎖定畫面就解開了；在超市收銀台前，再看一眼，付款完成。整個過程不到一秒。

但仔細想想，這件事有一點危險。你的指紋和臉部特徵不能像密碼那樣修改，一旦外洩就無法補救。而同一支手機裡，同時執行著幾十個來路各異的應用程式，其中難免有設計粗糙甚至居心不良的程式。手機怎樣保證這些最敏感的資料「放得進去，偷不出來」？

答案是在晶片內部劃出一塊與外界物理隔離的區域，相當於在一座繁忙的城市裡蓋一座金庫。本節就來看這座金庫的三道防線。

## 6.4.1 為什麼軟體防護不夠

前幾節討論的排程、溫控和感測器融合，主要由作業系統（OS）負責。照常理，安全似乎也可以交給作業系統：替敏感資料設定權限，不讓一般應用程式存取。

問題在於，作業系統本身也是軟體。它有數千萬行程式碼，難免存在漏洞。攻擊者一旦利用漏洞取得系統最高權限，也就是常說的「提權」或「越獄」，所有軟體層面的權限檢查都可能失效。這就像銀行把金庫鑰匙交給大廳經理保管，經理一旦被收買，金庫就等於沒有門。

所以工程師的思路是：**最關鍵的保護不能依賴作業系統，而要寫進硬體。**即使作業系統被完全攻破，攻擊者也拿不到金庫裡的東西。這類機制統稱為可信執行環境（Trusted Execution Environment，TEE）。

## 6.4.2 第一道防線：一根硬體訊號線劃出「兩個世界」

在主流行動處理器上，最常見的 TEE 方案是 ARM 公司的 TrustZone 技術。它的核心做法很直接：**在處理器匯流排上增加一根硬體訊號線，稱為 NS（Non-Secure，非安全）訊號。**

匯流排可以理解為晶片內部連接處理器、記憶體和周邊裝置的公共道路。CPU 每次存取記憶體，都會在這條道路上發出一次請求。TrustZone 為每次請求附上 NS 訊號，相當於替每輛車掛上車牌：

- 當 CPU 執行一般應用程式碼，或者執行一般作業系統程式碼時，請求帶著「非安全」標記，處在**普通世界**（Normal World）；
- 只有切換進入受保護模式後，請求才帶著「安全」標記，處在**安全世界**（Secure World）。

記憶體和周邊控制器在硬體層面檢查這個標記。一旦發現帶「非安全」標記的請求想讀取安全記憶體，**硬體匯流排會直接切斷這條讀取通道**。這不是軟體層面「拒絕回答」，而是物理通路被斷開，請求根本到達不了目標。

打個比方：普通世界和安全世界就像同一棟大樓裡的兩層，樓梯口裝著自動閘門。閘門不認人、不聽解釋，只看你胸前掛的是哪種顏色的識別證。作業系統即使被攻破，它的識別證顏色也不會變，仍然上不了樓。

## 6.4.3 第二道防線：獨立的安全晶片

TrustZone 的特點是同一組 CPU 核心在兩個世界之間來回切換，安全世界和普通世界仍然共用一部分硬體資源。為了進一步隔離，一些廠商走得更遠，在晶片中放入一個**完全獨立的安全子系統**，例如蘋果的 Secure Enclave（安全隔離區）和 Google 的 Titan 安全晶片。

這類方案通常包括三個關鍵元件：

| 元件 | 作用 | 類比 |
|---|---|---|
| 獨立的微型 CPU | 專門執行安全相關程式碼，不與應用處理器共用核心 | 金庫裡有自己的保管員，不受大廳調度 |
| 獨立的加密記憶體 | 記憶體中的資料以加密形式存放，外部即使讀到也看不懂 | 保險箱裡的文件全部用密文書寫 |
| 硬體真亂數產生器 | 利用電路中的物理雜訊產生亂數，用於產生金鑰 | 擲骰子由自然決定，而不是按公式「算」出來 |

其中真亂數產生器值得多說一句。一般軟體產生的「亂數」往往是按演算法推算出來的偽亂數，只要知道初始條件，理論上可以重現。而金鑰的安全性取決於它不可預測，所以安全晶片要從電路的物理雜訊中取得隨機性，讓攻擊者無從推算。

兩種路線可以這樣對照：

| 對照項 | ARM TrustZone | 獨立安全區（如 Secure Enclave、Titan） |
|---|---|---|
| 隔離方式 | 匯流排上的 NS 訊號劃分兩個世界 | 獨立處理器與獨立記憶體 |
| 處理器 | 與一般應用共用核心，分時切換 | 專用的微型 CPU |
| 隔離強度 | 依靠硬體存取控制 | 物理上更徹底的分離 |

## 6.4.4 第三道防線：只回答「是」或「不是」

有了金庫，還要規定金庫裡的東西怎麼用。以指紋和臉部辨識為例，整個流程體現了一條重要原則：**資料不出庫，只輸出結論。**

1. **特徵萃取**：感測器擷取到指紋或臉部資訊後，安全區不保存原始影像，而是從中萃取特徵，再轉換為**單向不可逆的雜湊範本**。所謂「單向不可逆」，就像把一塊肉做成絞肉，可以用來比對味道，卻無法還原出原來那塊肉。
2. **加密保存**：範本加密後保存，加密所依賴的根基固化在**物理熔絲**（eFuse）中。熔絲是晶片製造時可以一次性燒斷的微小電路，寫入後無法更改，相當於把鑰匙澆鑄在金庫的牆裡。
3. **只許比對**：之後無論是解鎖、支付還是登入，任何應用程式，**包括作業系統本身**，都不能讀取範本，只能向安全區發出請求：「請比對一下現在這根手指。」
4. **布林輸出**：安全區完成比對後，對外**只輸出 True 或 False**，也就是「相符」或「不相符」這樣的布林結果。

回到超市付款的場景：支付應用程式從頭到尾沒有接觸過你的指紋，它得到的只是安全區給出的一個「是」。就算這個應用程式被惡意竄改，它能偷走的也只有這個「是」，而這個結果對攻擊者幾乎沒有價值。

## 6.4.5 小結：信任從矽晶片底層長出來

把三道防線連起來看，手機的安全設計是一條由下而上的信任鏈：

- **物理層**：熔絲固化根金鑰，真亂數保證金鑰不可預測；
- **電路層**：NS 訊號線或獨立處理器把敏感區域與普通世界隔開；
- **介面層**：只開放「比對」請求，只輸出布林結果。

這樣，即使上層軟體全部失守，最底層的祕密仍然安全。這也說明，一支手機的可靠性不只取決於軟體寫得多好，也取決於晶片在設計之初就把「誰能存取什麼」寫進了硬體。
