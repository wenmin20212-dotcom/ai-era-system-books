# 1.1 点开一个应用之后：一秒钟里发生了什么

拿起手机，找一个你常用的应用，比如外卖、地图或者聊天软件，用手指点一下它的图标。图标轻微一闪，启动画面出现，片刻之后首页铺满屏幕：附近的餐馆、昨天的聊天记录、今天的天气。整个过程通常不过一两秒，快得让人很少去想：这一秒钟里，究竟有多少东西在动？

这一节就用慢镜头回放这一秒。我们不追求每个细节都准确到毫秒，而是要看清参与者有哪些、它们按什么顺序接力。后面八章要展开的几乎所有概念，都会在这一秒里露个面。

## 1.1.1 第一棒：手指、屏幕与操作系统

你的手指碰到屏幕时，触摸屏检测到电容变化，把坐标报告给手机的操作系统（Operating System，OS），例如写作时主流的 Android 或 iOS。操作系统判断这次触摸落在哪个图标上，确认你想打开哪个应用。

接下来操作系统要做几件事：从存储芯片里找到这个应用的程序文件，为它分配一块内存，创建一个“进程”（process，可以理解为程序运行起来之后的一个独立实例），然后把控制权交给应用自己的代码。这些工作属于操作系统的职责，本系列《操作系统》一册有详细讲解，这里只需要记住一点：**应用并不直接指挥硬件，它借助操作系统提供的服务运行**。

## 1.1.2 第二棒：应用本身醒来

控制权交到应用手里之后，应用里的代码开始一行行执行。这些代码最初由程序员用某种编程语言写成，再经过编译等步骤，变成手机能执行的形式（第二章会讲这个转换过程）。

启动阶段，应用通常要完成以下工作：

- **加载自身需要的模块**：比如负责画界面的部分、负责网络通信的部分。其中很多并不是这家公司自己写的，而是引用的现成“库”（library）。
- **读取本地数据**：上次登录留下的身份凭证、用户设置、缓存在手机上的图片和列表。
- **先画出一个“骨架”**：很多应用会先显示启动画面或灰色占位框，让你感觉它已经开始工作，而真实内容还在路上。

你看到的“秒开”，往往正是因为应用先用了本地保存的旧数据垫底，再悄悄去取新数据。

## 1.1.3 第三棒：一条请求穿过网络

首页上的餐馆列表、未读消息数量，并不存放在你的手机里，而是在远方的服务器上。于是应用通过网络发出一个**请求**（request），大意是：“我是某某用户，请把我附近的餐馆列表发给我。”

这条请求的旅程大致如下：

1. 应用先要知道服务器在哪。它拿着一个域名（类似 `api.example.com`），通过域名系统（Domain Name System，DNS）查到对应的网络地址，就像查电话簿找到号码。
2. 手机与服务器建立加密连接，通常使用 HTTPS（超文本传输安全协议），让路上的人看不到内容。
3. 请求经过 Wi-Fi 或移动基站，穿过运营商网络和互联网，到达这家公司的数据中心或云平台。

在数据中心门口，常常还有一个“分流员”，叫负载均衡器（load balancer），它把同一时刻涌来的大量请求分配给多台服务器，避免某一台被挤垮。

## 1.1.4 第四棒：服务器里的接力

请求到达服务器后，真正的“业务”才开始。以外卖应用为例，后台可能要依次或同时做这些事：

| 步骤 | 做什么 | 对应本书章节 |
|---|---|---|
| 核验身份 | 检查请求里的凭证是否有效、是否过期 | 3.4 身份认证与权限 |
| 执行规则 | 按距离、营业时间、配送范围筛选餐馆 | 3.2 业务逻辑层 |
| 查询数据 | 从数据库或缓存中取出餐馆信息 | 2.4 数据层、6.4 缓存 |
| 调用其他服务 | 向定位、推荐、优惠等内部服务要结果 | 4.2 服务与服务 |
| 记录痕迹 | 写下日志，供日后排查问题 | 3.5 日志与监控 |

在规模较大的公司里，这些步骤往往由许多个独立的小程序分别负责，它们之间也通过网络互相请求。于是你的一次点击，在后台可能引发几次乃至几十次内部调用。大型互联网服务一次页面请求触发数十个内部调用并不罕见，但具体数字因公司和功能差异很大。

结果汇总后，服务器把数据打包成一种双方约定好的格式（常见的是 JSON，一种用文字表示数据结构的格式），沿原路发回你的手机。

## 1.1.5 第五棒：回到屏幕上

手机收到数据，应用把它“翻译”成界面：计算每个卡片放在哪里、文字多大、图片显示多宽，再交给系统绘制到屏幕上。图片往往还要另外发请求去下载，所以你会看到文字先出来、图片稍后才一张张显现。

到这里，一秒钟的旅程才算走完。把它压缩成一条链，就是：

> 手指 → 操作系统 → 应用代码 → 本地数据 → 网络 → 负载均衡 → 服务器业务逻辑 → 数据库与其他服务 → 返回数据 → 界面绘制 → 你的眼睛

## 1.1.6 这一秒告诉我们什么

回看这条链，有三点值得记住。

第一，**一个应用远不止手机上的那个图标**。图标背后是手机上的代码、远方的服务器、数据库、网络，以及大量第三方代码，它们共同构成一个“软件系统”。

第二，**每一棒都可能出错**。网络慢、服务器忙、数据库卡住、某个内部服务挂掉，都会表现为同一个症状：转圈圈。理解了链条，才能理解为什么“应用打不开”的原因可以千差万别。

第三，**这一秒是无数人工作的结果**。写代码的、测试的、维护服务器的、设计界面的，他们的成果在这一秒里同时生效。而这套系统还在不断变化，你下周打开时，其中某些部分可能已经悄悄更新过了。

下一节，我们就从这一秒的观察出发，正式回答：软件系统到底是什么，它由哪些基本要素构成。
