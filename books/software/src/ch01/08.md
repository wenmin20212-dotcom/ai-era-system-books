# 1.5 本章骨架小结与实物探索任务

这一章，我们从手机屏幕上的一个图标出发，看到了一秒钟里发生的许多事：进程被创建，界面被绘制，网络请求发往远方的服务器，数据从数据库里取出，再一路返回到你眼前。合上这一章之前，先把散落的知识收拢成一副骨架，再动手在你自己的设备上验证一遍。

## 1.5.1 本章骨架回顾

第一章回答的是“这是什么”。可以把它压缩成下面几条：

- **一秒钟里的接力**：点开应用时，操作系统负责启动和分配资源，应用自身负责加载界面和本地数据，网络负责传递请求，服务端负责计算和查询，结果再回到界面。用户看到的“打开”，背后是多个环节的接力。
- **软件系统的四个要素**：代码（描述做什么、怎么做）、数据（被处理和保存的信息）、运行环境（硬件、操作系统、网络与云平台）、人（开发者、运维者、用户）。只盯着代码看，就看不懂软件为什么会出问题、为什么要不断更新。
- **系统的边界**：客户端（Client）运行在你的设备上，服务端（Server）运行在机房或云上，第三方服务（如地图、支付、推送、登录）由其他组织提供。一个应用的功能，常常是这三方共同完成的。
- **软件家族**：从单机程序、网页应用、移动 App，到云上服务和嵌入式软件，形态差异很大，但都可以用“代码—数据—环境—人”去拆解。

用一张对照表把这几层串起来：

| 观察层次 | 你能看到的现象 | 背后的系统要素 |
|---|---|---|
| 设备上 | 图标、启动画面、界面 | 客户端代码、本地数据、操作系统 |
| 网络中 | 加载转圈、断网提示 | 请求与响应、网络环境 |
| 远端 | 消息同步、订单状态 | 服务端代码、数据库、云平台 |
| 合作方 | 地图、支付、扫码登录 | 第三方服务与接口 |
| 人 | 版本更新、维护公告、客服 | 开发、测试、运维与产品团队 |

这张表就是后面八章的“索引”：第二章拆开每一格里的组成部分，第三章讲每部分的功能，第四章讲它们之间怎么连接，第五章看其中流动的请求、数据和代码。

## 1.5.2 实物探索任务

下面的任务不需要编程，只需要你手边的手机或电脑。建议边做边记录，把观察结果写成几行笔记。

1. **计时一次冷启动**。完全关闭一个常用应用（从后台划掉），再点开它，用手机秒表粗略记录从点击到能操作的时间；然后不关闭它，切到别的应用再切回来，比较两次的差别。想一想：哪些工作在第二次被省掉了？
2. **断网实验**。打开飞行模式，分别打开一个笔记类应用、一个视频应用和一个地图应用，记录哪些内容还能显示、哪些功能失效。由此推断：哪些数据存在本地，哪些必须向服务端请求？
3. **查看应用的“家底”**。在手机“设置—应用”中找到一个应用，查看它的安装大小、数据和缓存占用以及权限列表（具体菜单位置因系统和版本不同而异，以写作时的常见系统为准）。把权限对应到功能上：相机权限给了扫码，位置权限给了地图，还有哪些权限你说不出用途？
4. **寻找第三方的身影**。在一个购物或外卖应用里，留意登录页、支付页、地图页和分享按钮，记下哪些界面明显来自其他公司或平台。再翻看应用里的“隐私政策”，许多应用会列出它接入的第三方服务清单。
5. **给家里的软件分家族**。列出你家中运行软件的设备：手机、电脑、电视、路由器、洗衣机、汽车等，按“单机程序 / 网页应用 / 移动 App / 云上服务 / 嵌入式软件”归类。有些设备可能同时属于多类，这本身就说明了软件系统边界的模糊。

## 1.5.3 可以直接问 AI 的问题

做完实验后，可以把观察结果和下面的问题一起交给 AI，让它帮你继续展开。提问时附上你用的设备型号和应用名称，回答会更具体；对 AI 给出的具体数字和产品细节，要再找官方文档或可靠资料核对。

- “我关闭某应用后重新打开用了约三秒，切回后台再打开几乎瞬间完成。请从操作系统进程管理和应用缓存的角度，解释这两种启动的区别，并说明哪些部分属于操作系统、哪些属于应用自己。”
- “我开启飞行模式后，笔记应用还能看到旧笔记，视频应用却无法播放。请帮我分析这两类应用在本地存储和服务端依赖上的设计差别，以及‘离线优先’是什么意思。”
- “请用‘代码、数据、运行环境、人’四个要素，帮我拆解一台智能电视里的软件系统，并指出它和手机 App 在边界上的不同。”

## 1.5.4 从“认得”走向“拆开”

到这里，你已经能把一个应用看成一个系统，而不是一个图标：它有边界，有组成要素，有内外之分，也有家族归属。但“认得”还只是第一步。代码到底是怎样写成的？写好的代码又怎样变成机器能执行的动作？应用里那些不是开发者亲手写的部分从哪里来？数据又存放在哪里？下一章，我们拿起“解剖刀”，从源代码和编程语言开始，把软件系统一层一层拆开。
