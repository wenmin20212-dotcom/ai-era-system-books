# 9.4 本章骨架小结与实物探索任务

合上这本书之前，请再看一眼手机屏幕上那个你最常用的应用。序章里，它只是一个图标，点一下就打开。读到这里，你应该能在它背后看到一层层结构：源代码和运行时，数据库和接口，前后端的对话，代码流、发布流和故障流，还有模块化、事务、分布式限制这些原理。第九章补上的是最后一环：书里讲的骨架是稳定的，具体细节会不断变化，这部分要靠 AI 和读者手边的真实系统继续展开。

## 9.4.1 本章骨架回顾

第九章把“书 + 实物 + AI”的学习方式落到了具体的操作上，可以归纳为三条线：

- **读懂材料（9.1）**：软件给人看的东西主要有三类，即文档、报错信息和日志。把这些原文交给 AI 解释，通常比只用自己的话描述问题更准确。同时要注意两件事：一是先删除密码、令牌（Token）、手机号等敏感信息；二是 AI 的解释只是一个假设，需要回到官方文档或实际现象中去核对。
- **观察实物（9.2）**：浏览器开发者工具（DevTools）是普通人能够直接接触到的“系统透视镜”。元素面板显示表现层的结构，网络面板显示一次次请求和响应，控制台显示脚本运行时的报错，应用面板显示 Cookie 和本地存储。书中第四、五章讲的前后端对话和请求流，都能在这里亲眼看到。
- **提出问题（9.3）**：提问可以分三个台阶。第一阶问“是什么”，目的是建立概念。第二阶问“为什么这样设计、有什么取舍”，目的是理解机制。第三阶问“如果换个条件会怎样、怎样验证”，目的是接近工程判断。问题的层次上去了，AI 回答的深度往往也会跟着上去，但越深入越需要核验。

再往全书的方向看一步，九层认知阶梯是一个可以反复使用的框架：

| 层次 | 面对任意一个新软件时可以问的问题 |
|---|---|
| 对象 | 它的边界在哪里，哪些在设备上，哪些在云上？ |
| 结构 | 它由哪些语言、框架、数据存储和接口组成？ |
| 功能 / 连接 | 各部分分别负责什么，彼此怎样调用？ |
| 流动 | 请求、数据、代码和故障怎样在其中流转？ |
| 机制 / 技术 | 它靠什么应对并发、一致性、伸缩和安全问题？ |
| 原理 | 有哪些根本限制是任何技术都绕不开的？ |
| AI 协同 | 我该把哪些材料交给 AI，又该怎样验证它的回答？ |

## 9.4.2 实物探索任务

1. **一次完整的网络观察**：在电脑浏览器中打开一个你常用的网页应用，按 F12 打开开发者工具，切换到“网络”面板后刷新页面。找出页面加载时请求数量最多的资源类型，再找一个返回 JSON 数据的请求，看看它的状态码和响应内容。把观察结果写成三句话：请求发往哪里，带了什么，拿回了什么。
2. **制造并解读一个报错**：在浏览器地址栏中，把某个网址的路径故意改错，观察页面显示的错误信息，以及网络面板里的状态码，例如 404。然后把状态码和页面上的提示原文交给 AI，请它解释含义，再到 MDN 等公开文档中核对它说得对不对。
3. **读一段真实的更新日志**：打开手机应用商店，找到你常用应用的“更新说明”。再找一个开源项目在 GitHub 上的发布说明（Release Notes），比较两者的写法。想一想：哪些修改属于新功能，哪些属于缺陷修复，哪些可能和安全有关？
4. **画出你的应用骨架图**：任选一个应用，在一张纸上画出客户端、服务端、数据库和第三方服务（比如支付、地图、登录）之间的关系，并标出一次核心操作的请求路线。画完后把图描述给 AI，请它指出可能遗漏的部分，比如缓存、消息队列或 CDN（内容分发网络）。
5. **用三阶提问追一个概念**：从“缓存”“事务”“灰度发布”中选一个概念，按 9.3 节的阶梯连续向 AI 提三个问题，每一阶提一个。记下每次回答里有哪些新信息，以及哪一处需要你自己去核实。

## 9.4.3 可以直接拿去问 AI 的问题

- “我在浏览器开发者工具里看到一个请求，状态码是 304，响应几乎是空的。请从浏览器缓存和服务器的角度，一步步解释这代表什么，并告诉我怎样亲自验证。”
- “请用一个外卖应用做例子，按‘对象、结构、功能、连接、流动、机制、原理’七个层次，各用两三句话说明它是怎样构成和运转的。对于不同公司做法不一样的部分，请明确标出来。”
- “对于一个没有编程背景的人，如果想继续深入学习软件系统，接下来三个月可以怎样安排？请把动手观察、阅读和提问结合起来，并说明每个阶段怎样检验自己是否真的学会了。”

## 9.4.4 结语：骨架留在你手里

具体的框架、平台和工具也许过几年就会换代，写作时流行的做法未来也可能被替代。不容易过时的是这样一组问题：软件由什么组成，各部分怎样连接，其中流动着什么，靠什么机制保证正确，又受哪些原理限制。这本书提供的是这组问题的骨架。读者手边的设备是可以随时打开观察的实物，AI 则可以陪你一层层追问下去。下一次点开一个应用时，不妨先停一秒，想一想它背后正在发生的事情。
