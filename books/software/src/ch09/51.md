# 9.2 动手实验：用浏览器开发者工具观察一个网页应用

前面八章讲过的请求流、缓存、接口、日志，都发生在屏幕背后，平时看不见。其实你的电脑浏览器里就装着一套现成的观察工具，叫“开发者工具”（Developer Tools，常简称 DevTools）。在 Chrome、Edge、Firefox 这类桌面浏览器中，按 F12，或在 macOS 上按 Command+Option+I，就能打开它。快捷键和菜单位置以写作时的版本为准，以后可能调整，但它提供的观察能力已经稳定存在多年。

本节给你一份实验步骤：选一个常用的网页应用，比如一个新闻站点、一个在线文档或一个搜索页面，用开发者工具把它拆开来看。整个实验只读不写，不会改动任何服务器上的数据。

## 9.2.1 准备：认识开发者工具的几个面板

打开开发者工具后，通常能看到一排标签页。不同浏览器的叫法略有差别，下表列出主流浏览器中常见的几个面板，并对应到本书相关的章节：

| 面板（常见名称） | 能看到什么 | 对应本书哪一层 |
|---|---|---|
| 元素（Elements） | 页面的 HTML 结构和 CSS 样式 | 表现层（3.1） |
| 控制台（Console） | 脚本输出的信息、报错 | 日志与报错（3.5、9.1） |
| 网络（Network） | 页面发出的每一个请求及其响应 | 请求流、接口（5.1、2.5） |
| 应用/存储（Application/Storage） | Cookie、本地存储、缓存 | 认证、缓存（3.4、6.4） |
| 性能（Performance） | 一段时间内的加载和渲染过程 | 并发与异步（6.2） |

建议做实验时使用浏览器的无痕或隐私窗口，并且不在已经登录重要账户的页面上随意操作，原因在下文第四步会讲到。

## 9.2.2 在“元素”面板里看清表现层

在网页上任选一个按钮，右键点“检查”，开发者工具会自动跳到元素面板，并高亮这个按钮对应的那段 HTML 代码。你会发现，屏幕上一个圆角蓝色按钮，在代码里可能只是一行 `<button>` 标签，外观来自旁边列出的一组 CSS 规则。

可以试着双击某段文字，把它改成别的内容，页面会立刻跟着变。刷新一下，又恢复原样。这个小实验说明了一件重要的事：**你改的只是自己浏览器里的那份副本**。浏览器从服务器取回代码，在本地组装出页面，这就是第四章讲的“前端运行在你的设备上”。网上偶尔流传的“截图证据”，用这种方法几秒钟就能伪造，所以网页截图本身并不可靠。

## 9.2.3 在“网络”面板里追踪一次请求

切到网络面板，然后刷新页面。列表里会冒出几十到上百条记录，对于复杂的网页应用，这个数字可能更大。每一条都是一次请求，有的取 HTML，有的取图片、字体、脚本，有的是调用后端接口取数据。

点开其中一条，重点看这几项：

- **请求地址（URL）与方法**：常见的 GET 表示“取数据”，POST 表示“提交数据”。
- **状态码**：200 表示成功，304 表示“内容没变，用你本地缓存的那份”，404 表示找不到，5xx 表示服务器端出错。
- **响应内容**：接口返回的数据常常是 JSON（JavaScript 对象表示法，一种文本数据格式），你能直接读到一串带花括号的键值对。
- **耗时（Timing）**：一次请求被拆成 DNS 查询、建立连接、等待服务器响应、下载内容等阶段。

再做一个对照：在页面上执行一个操作，比如翻到下一页或搜索一个词，观察新出现的请求。你会看到页面并没有整体刷新，而是由脚本单独请求了一个接口，拿回数据后局部更新界面。这就是 5.1 节请求流在你眼前的真实样子。

如果勾选面板里的“停用缓存”（Disable cache）再刷新，比较一下传输的数据量和总加载时间，就能直观感受到 6.4 节说的缓存在做什么。

## 9.2.4 在“控制台”里读报错

很多网站的控制台里平时就有几行黄色警告甚至红色错误，页面却照常可用。这说明软件常常“带病运行”，非关键部件出错并不一定影响主功能，这也是可观测性要区分轻重缓急的原因。

把一条红色报错完整复制下来，按 9.1 节的方法交给 AI，请它解释“这条错误发生在哪个文件、大概是什么原因、对用户有没有影响”。注意报错里可能含有网址参数等信息，粘贴前先看一眼，去掉看起来像个人信息或长串令牌的部分。

## 9.2.5 在“应用”面板里看身份凭证

在应用或存储面板中找到 Cookie 一栏，你会看到网站在你浏览器里存放的若干条小数据，其中可能有一条就是登录后的会话凭证。3.4 节讲过，服务器靠它确认“这次请求还是你”。

这里有一条必须遵守的安全规则：**不要把 Cookie、令牌（Token）的值截图、复制或发给任何人，包括 AI 工具**。拿到它的人，在有效期内可能直接冒充你登录。一些诈骗手法正是诱导用户“打开 F12，复制这段内容发给客服”。理解了原理，你就能识别这种陷阱。

## 9.2.6 实验之后：把观察和骨架对上

做完四步，可以按下面的格式写一份简短记录，再请 AI 帮你检查理解是否准确：

1. 这个网页一次加载大约发出了多少个请求，哪类资源最多？
2. 我找到的一个数据接口地址是什么，返回的数据里有哪些字段？
3. 哪个请求耗时最长，耗在哪个阶段？
4. 控制台里有什么报错，AI 怎样解释它？

你会发现，几分钟的观察就能把“表现层—接口—请求流—缓存—认证—日志”串成一条看得见的链条。浏览器开发者工具看不到服务器内部的微服务、数据库和发布流程，但它站在系统边界上，让你确认书中讲的那些结构确实存在。至于怎样根据这些观察继续向深处提问，下一节的三阶提问阶梯会给出方法。
