# 2.1 源代码与编程语言：写给人看，也交给机器执行

打开手机上的计算器，输入“3+5”，按下等号，屏幕上出现“8”。这个动作背后，有人事先写好了一段文字，告诉机器：读取用户按下的数字，遇到加号就把两个数相加，再把结果显示出来。这段文字就是**源代码**（Source Code），它是一个软件系统最原始的“设计稿”。上一章我们把软件系统看成代码、数据、运行环境与人的组合，从这一节开始拆解，先拆的就是代码本身：它长什么样，用什么语言写成，为什么要写成那样。

## 2.1.1 源代码长什么样：一份写给两类读者的说明书

源代码本质上是一组纯文本文件，可以用记事本打开，和你写的作文没有物理上的区别。下面是一小段用 Python 语言写的代码，作用是计算购物车的总价：

```python
def total_price(items):
    total = 0
    for item in items:
        total = total + item.price * item.count
    return total
```

不懂编程也能猜出大意：定义一个叫“总价”的功能，把每件商品的单价乘以数量，累加起来，最后交出结果。这正是源代码的双重身份：

- **写给人看**：程序员要读它、改它、和同事讨论它。一个软件往往要维护许多年，读代码的时间远多于写代码的时间，所以变量名取得是否清楚、结构是否整齐，直接影响后来的人能不能看懂。
- **交给机器执行**：计算机的处理器（CPU）只认识由 0 和 1 组成的**机器码**（Machine Code），比如“把这个内存位置的数取出来”“把两个寄存器里的数相加”。源代码必须经过翻译，才能变成机器能执行的指令。

打个比方：源代码像一份菜谱，厨师（程序员）能读懂，学徒也能照着改良；但要让一台全自动炒菜机执行，还得把菜谱转成它能识别的一串控制信号。这个“翻译”环节就是下一节要讲的编译器与解释器。

## 2.1.2 编程语言为什么有这么多种

既然机器只认机器码，为什么不直接写机器码？早期确实有人这么做，但效率极低、极易出错。于是出现了**汇编语言**（Assembly Language），用 ADD、MOV 这样的助记符代替 0 和 1；后来又出现了更接近人类思维的**高级语言**（High-level Language），比如 C、Java、Python、JavaScript。层级越高，越像人话，离硬件越远。

| 层级 | 例子 | 特点 |
|---|---|---|
| 机器码 | 一串二进制数 | 处理器直接执行，人几乎无法阅读 |
| 汇编语言 | `ADD R1, R2` | 与处理器指令一一对应，依赖具体芯片 |
| 系统级高级语言 | C、C++、Rust | 能精细控制内存，常用于操作系统、浏览器、游戏引擎 |
| 应用级高级语言 | Java、Go、C#、Python | 开发效率高，常用于服务器端业务系统 |
| 网页与脚本语言 | JavaScript、TypeScript | 在浏览器中运行，负责网页的交互 |

语言之所以多，是因为没有一种语言能在所有方面都最好。它们在几个维度上做取舍：

- **性能与控制力**：C 和 Rust 都能精细控制内存，运行快；C 写错了容易崩溃或出现安全漏洞，Rust 则在编译阶段用严格的规则挡住大部分这类内存错误，代价是学起来更难。
- **开发效率**：Python 语法简洁，几行就能完成一件事，适合数据分析和快速试验，但通常运行得比 C 慢。
- **运行场景**：网页里的交互几乎只能用 JavaScript（或能转成 JavaScript 的语言）；安卓应用常用 Kotlin 或 Java，苹果设备上的应用常用 Swift，这是写作时各平台官方推荐的主流选择。
- **团队与生态**：一门语言有多少现成的库、多少人会用，往往比语法本身更影响选择。

所以，一个真实的软件系统常常是多语言的：你手机上的购物 App，界面可能用 Swift 或 Kotlin 写成，后台服务可能用 Java 或 Go，数据分析部分用 Python，网页版则用 JavaScript。

## 2.1.3 语言的共同骨架：几样基本积木

语言虽多，核心概念却高度相似。掌握下面几样积木，看任何语言的代码都能抓住大意：

1. **变量**（Variable）：给一块数据起名字，如上例中的 `total`。
2. **数据类型**（Data Type）：说明数据是整数、小数、文字还是真假值。有的语言要求事先写明类型（如 Java，称为**静态类型**），有的在运行时才确定（如 Python，称为**动态类型**）。静态类型能在运行前发现一部分错误，动态类型写起来更灵活。
3. **控制结构**：“如果……就……”的条件判断，以及“对每一件商品都做一遍”的循环。
4. **函数**（Function）：把一段完成特定任务的代码打包并命名，像 `total_price`，需要时调用即可。
5. **对象与模块**：把相关的数据和操作组织在一起，让大程序可以分块管理。这一点会在第六章“抽象与模块化”中展开。

这些积木组合起来，就能表达从计算器到网上银行的各种规则。一个大型软件的源代码，可能由成千上万个文件、几十万到上亿行代码组成——一般认为，大型操作系统或浏览器的代码量在千万行量级。它们都是由这些基本积木一层层搭起来的。

## 2.1.4 代码之外：注释、规范与“人”的部分

真实项目里的源代码并不只有给机器的指令。程序员会写**注释**（Comment），解释“为什么这样写”，机器在翻译时会直接忽略它们。团队还会约定**编码规范**，统一缩进、命名和格式，并用自动化工具检查。这些都不影响程序运行结果，却决定了代码能不能被多人长期协作维护。

这也解释了为什么本章说源代码“写给人看”在前。机器从不抱怨代码难读，抱怨的永远是三个月后接手的同事，或者三个月后的自己。

## 2.1.5 小结：从文字到动作的第一站

源代码是软件系统的源头：它是人用编程语言写下的规则，既是团队交流的文档，也是机器执行的依据。编程语言的多样性来自性能、效率、平台和生态之间的取舍，而它们共享变量、类型、条件、循环、函数等基本积木。不过，写好的代码此刻还只是一堆文本，它怎样被翻译、加载，并真正在你的手机或服务器上“动起来”？这就是下一节编译器、解释器与运行时要回答的问题。
