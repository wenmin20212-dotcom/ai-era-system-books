# 2.6 本章骨架小结与实物探索任务

把手机上常用的那个应用想象成一栋楼。第一章我们站在楼外，看清了它的轮廓：客户端、服务端、第三方服务，再加上写它、用它、维护它的人。第二章我们走进楼里，把墙板拆开，看到了钢筋、水管和电线。本节把这些“建材”收拢成一张清单，再给出几项可以马上动手的探索任务。

## 2.6.1 本章骨架回顾：五类构件

一个软件系统不论大小，拆开后大致都能找到下面五类构件。它们彼此衔接，共同把一个想法变成可以运行的软件。

| 构件 | 它是什么 | 一句话类比 | 本章关键词 |
|---|---|---|---|
| 源代码与编程语言 | 人写下的、机器能够处理的指令文本 | 建筑图纸 | 语法、可读性、语言的取舍 |
| 编译器、解释器与运行时 | 把代码变成机器动作的“翻译与执行环境” | 施工队与工地 | 编译、解释、虚拟机、垃圾回收 |
| 库、框架与依赖 | 别人写好、拿来复用的代码 | 预制件与标准构件 | 包管理器、版本号、依赖树 |
| 数据层 | 保存和读取数据的部分 | 仓库与货架 | 数据库、缓存、文件与对象存储 |
| 接口与界面 | 软件与软件、软件与人之间的约定 | 门窗与插座 | 应用编程接口（API）、用户界面（UI） |

把这张表压缩成一条线，就是：**人用语言写下代码 → 工具链把代码变成可执行的形态 → 运行时在设备上执行它 → 执行过程中大量调用依赖、读写数据层 → 通过接口与其他系统交换信息，通过界面与人打交道。**

## 2.6.2 三个值得记住的结构性认识

1. **代码只是冰山露出的一角。** 一个应用里，团队自己写的代码往往只占一部分，开源库、框架和运行时贡献了大量代码。现代应用里第三方代码占比可以相当高。这意味着软件的质量和安全，很大程度上取决于“用了谁的代码、用的是哪个版本”。
2. **“翻译方式”决定了运行特点。** 提前编译成机器码的程序启动快、执行效率高；边解释边执行的程序修改起来灵活；带即时编译（JIT）的运行时则在两者之间取得平衡。没有哪一种绝对更好，只有是否适合场景。
3. **接口是分工的边界。** 应用编程接口（API）把“谁负责什么”写成了明确约定。前端团队不必知道数据库建了哪些表，只要知道接口返回什么。第四章讨论前后端、微服务时，这条边界会反复出现。

## 2.6.3 实物探索任务

下面的任务不需要编程基础，用手边的手机或电脑就能完成。

**任务一：找到应用的“依赖清单”。** 在手机设置中打开“关于本机”或某个应用的“关于”页面，查找“开源许可”“第三方软件声明”之类的入口（写作时，许多 iOS 与 Android 应用都设有这类页面，名称各不相同）。数一数列出了多少个开源组件，看看有没有你在本章见过的名字。

**任务二：观察缓存的存在。** 在手机的应用管理中找到一个常用应用，分别记下“应用大小”“数据”“缓存”三项数字。清除缓存后再打开应用，留意首屏加载是否变慢、图片是否需要重新加载。想一想：被清掉的是什么，为什么清掉后应用仍然能用？

**任务三：看一眼真实的源代码。** 在浏览器中打开任意网页，按 F12 或右键选择“检查”（写作时 Chrome、Edge、Firefox 都支持），切换到“源代码”/“Sources”面板（Firefox 中叫“调试器”/“Debugger”）。你会看到 HTML、CSS 和 JavaScript 文件。不需要读懂，只要分辨哪些是网站自己的文件，哪些文件名带有 jquery、react、vue 之类的框架字样。

**任务四：亲手调用一次公开接口。** 在浏览器地址栏输入一个公开的、无需登录的 API 地址（例如一些开放数据平台提供的示例接口），观察返回的是一段由花括号和引号组成的 JSON 文本，而不是排好版的网页。对比同一份信息在应用界面上的样子，体会“接口给程序看，界面给人看”的区别。

**任务五：画出你的“五类构件图”。** 任选一个常用应用，在纸上画五个方框，依次填写：它的客户端可能用什么语言写成、在什么运行环境中执行、可能用了哪些库（参考任务一）、数据存在哪里（本机还是云端）、它对外提供或调用了哪些接口（如登录、支付、地图）。不确定的地方打问号，留给下一项。

## 2.6.4 可以直接问 AI 的问题

- “我在某个应用的开源许可页面看到了这些组件名称：（粘贴名单）。请按‘网络请求、图片处理、数据存储、界面组件、其他’分类，并用一句话说明每个组件大概做什么。”
- “请用中学生能懂的语言，对比编译型语言、解释型语言和带即时编译的语言，各举一个常见语言作例子，并说明它们分别适合什么场景。”
- “我画了一张某个应用的构件图，其中打问号的地方是：（列出）。请告诉我这些地方常见的技术选择有哪些，并提醒我哪些内容只能靠推测、无法从外部确认。”

向 AI 提问时，记得把它的回答与本章的骨架表对照：它说的东西属于哪一类构件？位于哪一层？这样，AI 给出的零散信息就能挂到稳定的框架上。

## 2.6.5 从“由什么组成”走向“各自做什么”
