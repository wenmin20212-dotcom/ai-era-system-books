# 6.2 规划与任务分解：先列计划还是边做边想

假设你对一个编程智能体说：“把这个项目里所有用到旧日期函数的地方换成新写法，并保证测试通过。”有的智能体会先回你一份清单：第一步搜索全部调用位置，第二步逐个修改，第三步运行测试，第四步修复失败项。有的则直接开始搜索，看到结果再决定下一步。两种做法都能把事情做完，但走的路不一样。上一节讲了“想一步、做一步、看一步”的循环，这一节回答一个更靠前的问题：一个大目标是怎样变成一串可执行的小步骤的？智能体应该先把计划列全，还是边做边想？

## 6.2.1 为什么必须分解：大目标无法一步执行

模型每次只能“说出”一个或几个具体动作，比如调用搜索工具、读取某个文件、写入一段代码。“保证测试通过”这样的目标不是动作，无法直接执行。任务分解（task decomposition）就是把目标拆成足够具体的子任务，具体到每一步都能对应某个工具调用或某段文字输出。

可以拿装修做类比。“把房子装好”没法动手，“先拆旧墙皮、再走水电、再贴砖”才能开工。分解要拆到什么粒度，取决于手里有什么工具。智能体能调用的工具越底层，计划就要拆得越细；工具越强，比如有一个能直接“运行全部测试并汇总报告”的工具，计划就可以粗一些。

分解还有一个容易被忽略的作用：它把模型的注意力限制在当前子任务上。第十八册讲过，模型处理很长、很杂的上下文时容易遗漏细节。把大任务拆开，每一步只关注一小块，出错的概率会下降，即使出错也容易定位。

## 6.2.2 两种基本路线：先规划后执行，边做边想

业界和学界常见的做法大致有两类。

| 对比项 | 先规划后执行（plan-and-execute） | 边做边想（交错式，如 ReAct 风格） |
|---|---|---|
| 做法 | 先生成完整步骤清单，再逐条执行 | 每一步根据上一步的观察结果决定下一步 |
| 优点 | 全局清晰，便于人审阅，步骤少时成本低 | 灵活，能应对意外情况 |
| 缺点 | 计划建立在执行前的猜测上，遇到意外容易失效 | 容易只顾眼前，绕远路甚至原地打转 |
| 适合 | 流程固定、环境可预测的任务 | 信息不全、需要边查边定的任务 |

“先规划后执行”像出发前把导航路线全部定好，“边做边想”像在陌生城市里每到一个路口问一次路。前者的风险在于计划依赖执行前的假设。比如计划写的是“修改五个文件”，搜索后却发现有二十个，而且其中三个是自动生成的文件，不该手改，原计划就不能照着执行了。后者的风险在于缺少全局视角：智能体可能修好一处后跑去处理一个无关的警告，忘了最初的目标。

## 6.2.3 现实中的折中：计划可以改，进度要看得见

写作时，主流编程智能体和研究型智能体大多采用折中方案，先列一份粗计划，执行过程中随时修订。常见的工程手段有下面几种。

- **待办清单（to-do list）**：一些编程智能体会把计划写成带勾选状态的清单，显示在界面上，完成一项就勾掉一项，发现新情况就增删条目。清单让用户看到进度，同时也随上下文反复交给模型，提醒它当前做到哪里、还剩什么没做。
- **重新规划（replanning）**：执行到关键节点，或某一步失败时，编排程序要求模型对照目标重新审视剩余计划，不再死守旧清单。
- **分层规划（hierarchical planning）**：高层只写“搜索、修改、测试”三个阶段，每个阶段内部再细分。部分多智能体系统让一个“规划者”负责高层计划，把子任务交给“执行者”完成，这与第四章 4.3 节讲的委派是同一种结构。

拿开头的日期函数任务来说，比较稳妥的过程是：先粗列四步，执行第一步搜索后，根据实际结果把“修改”细化为若干具体文件，并标出不该改的生成文件；测试失败时，插入“分析失败原因”这一步，不急着进入下一项。计划在执行过程中不断被修订，修订依据是每一步实际观察到的结果。

## 6.2.4 计划好不好，看三件事

计划写得再漂亮，也不等于事情能做成。读者在审阅智能体给出的计划时，可以检查三点。

1. **每一步是否可执行、可验证**。“优化代码”太空泛，“把函数 A 中的循环改为批量查询，并运行相关测试”就可以执行，也能检查结果。
2. **依赖顺序是否正确**。要先备份才能删除，要先读文件才能改文件。顺序错了的计划，执行时容易造成误操作。
3. **有没有明确的完成标准**。“测试全部通过”“表格包含十二个月的数据”这类标准，能让智能体知道什么时候该停。缺少完成标准是智能体空转、过度修改的常见原因，6.5 节会详细讨论。

这三点同样适用于给智能体下任务的人。你在任务说明中写清完成标准，模型做出的分解通常会更扎实。第二章讲过，指令是智能体的组成部分，规划的质量有一部分取决于指令写得好不好。

## 6.2.5 小结：计划是假设，执行是检验

先列计划和边做边想并不互相排斥。计划提供方向，相当于一个假设；执行带回真实信息，用来检验和修正这个假设。好的智能体会把两者组合成一个循环：计划、执行、观察、修订计划。第八章会说明，这种做法背后有搜索与规划理论以及控制论中反馈的原理支撑。下一节回到循环里最具体的一环，看模型怎样把计划中的一个步骤变成一次真实的工具调用。
