# 6.3 工具调用的机制：模型怎样“说出”一个动作

你让智能体“查一下明天上海的天气，再写进我的日程备注里”。几秒钟后，界面上出现一行灰色小字：“正在调用：天气查询……”，接着又是“正在调用：日历写入……”。这两行字背后有一个容易被忽略的事实：大语言模型本身只会做一件事，就是根据输入续写文字。它没有手，也连不上天气服务器。那么“调用工具”这个动作是从哪里来的？答案是模型“说”出了一段格式严格的文字，由外面的程序替它把这段文字变成真正的动作。本节就拆开这句“说出一个动作”。

## 6.3.1 从一句话到一张“工单”：结构化输出

在第四章我们从连接的角度认识了函数调用（Function Calling，也常称工具调用 Tool Use）。现在换到机制层面，看清一次调用的具体样子。

当智能体需要查天气时，模型并不会输出“我去查一下天气”这样的自然语言，而是输出一段机器能直接读懂的结构化文本，最常见的格式是 JSON（JavaScript 对象表示法，一种用花括号和键值对表示数据的通用格式）。示意如下：

```json
{
  "tool": "get_weather",
  "arguments": { "city": "上海", "date": "明天" }
}
```

可以把它看成一张“工单”：写明要找哪个部门（工具名）、办什么事（参数）。模型只负责填工单，真正跑腿的是编排程序。这种分工很关键：模型生成的内容始终只是文字，所有对外部世界的影响，都必须经过程序这道关口。这也是第七章讨论沙箱与权限时，能在这里设卡的原因。

## 6.3.2 模型怎么知道有哪些工具可用

模型之所以能填对工单，是因为每次请求时，编排程序都会把一份“工具说明书”放进上下文。每个工具的说明一般包含三项：

| 组成部分 | 作用 | 天气工具的例子 |
|---|---|---|
| 名称 | 让模型点名调用 | `get_weather` |
| 描述 | 用自然语言告诉模型何时该用 | “查询指定城市某天的天气预报” |
| 参数结构 | 规定要填哪些字段、什么类型、哪些必填 | city：字符串，必填；date：字符串 |

参数结构通常用 JSON Schema（JSON 模式，一种描述数据格式的规范）来写。模型读到这份说明，就像新员工拿到一张部门电话表加填表须知。

由此可以推出一个实用结论：**工具描述写得好不好，直接影响模型会不会用、会不会用对**。描述含糊，模型可能在不该用的时候乱用；参数说明不清，模型可能把“明天”填成格式错误的日期。许多开发者的经验是，调好工具描述往往比更换模型更见效。

至于模型为什么能稳定地输出这种格式，主要来自训练：主流模型厂商在训练中加入了大量“看说明、选工具、填参数”的示范数据。训练细节属于模型本身的话题，可参阅第十八册。写作时，OpenAI、Anthropic、Google 等公司的接口都提供了类似的工具调用功能，字段名称各不相同，但“名称—描述—参数”这一结构基本一致。

## 6.3.3 一次调用的完整往返

把镜头拉远，一次工具调用是一个由程序驱动的往返过程，和 6.1 节的推理—行动循环正好对应：

1. **提供菜单**：编排程序把用户任务、对话历史和工具说明一起发给模型。
2. **模型决策**：模型判断需要外部信息，于是输出一张调用工单，而不是直接回答。接口会用特殊标记表明“这是一次调用请求”，程序据此区分普通回复和动作。
3. **程序校验**：程序检查工具名是否存在、参数是否符合格式、这个动作是否需要人工确认。
4. **真实执行**：程序调用天气服务，拿到结果，比如“多云，18—24℃”。
5. **结果回填**：程序把结果作为一条“工具消息”追加进上下文，再次请求模型。
6. **继续或结束**：模型读到结果后，可以再发起下一次调用（写入日历），也可以给出最终答复。

有两点值得注意。第一，模型在第 2 步和第 6 步之间是“断开”的：它不会等待，每次都是程序把完整上下文重新送进去，它再接着往下想。第二，有些接口允许模型在一次输出里同时发出多张工单，即并行调用，比如同时查北京和上海的天气，由程序并发执行后再统一回填，从而节省时间。

## 6.3.4 当工单填错时

既然动作是“说”出来的，就会有说错的时候。常见的问题有以下几类：

- **格式错误**：少了括号、字段类型不对。部分接口提供“严格模式”或约束解码（在生成时限制模型只能输出符合格式的内容），可以大幅减少这类问题。
- **参数编造**：用户没提供订单号，模型却凭空填了一个看似合理的号码。这是幻觉在动作层面的表现，危害比说错一句话更大。
- **选错工具**：两个工具描述相近，模型选了不合适的那一个。
- **不该调用却调用**：本可以直接回答，却多绕一圈，白白增加成本。

对应的工程做法也很朴素：程序校验格式后把报错信息原样回填，让模型自己修正；必填信息缺失时，引导模型先向用户提问；涉及付款、删除、发送等不可逆的动作，一律交给人确认。这些做法会在 6.5 节的失败与恢复中继续展开。

## 6.3.5 小结：说与做之间隔着一个程序

工具调用的机制可以浓缩成一句话：**模型负责“说”出一张格式规范的工单，程序负责校验、执行，并把结果送回给模型。**理解了这一点，就不会把智能体想成一个自己伸手去操作电脑的“幽灵”。它的每一个动作都留有文字记录，每一步都可以检查、拦截和复现。下一节我们将看到，随着工具调用越来越多，上下文会迅速变长，智能体需要靠总结、压缩和检索来管理自己的记忆。
