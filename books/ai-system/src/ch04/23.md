# 4.3 集群之内：高速网络、并行策略与集合通信

新闻里常出现这样的说法：某公司建成了“万卡集群”，用来训练新一代大模型。一万块 GPU 放在一起，听上去像是把一万台电脑堆进同一个大仓库。真正的难点却不在“堆”，而在“连”。上一节讲的是一台服务器里的八块左右 GPU 如何紧密协作，这一节要走出机箱，看看成百上千台服务器怎样被网络连成一个整体，又怎样分工合作，像一台巨大的计算机那样训练同一个模型。

## 4.3.1 从一台服务器到一座“计算工厂”

先用一个类比。假设要在一周内抄完一部百万字的大书，一个人做不到，就请一千个人。人多了，问题也跟着来：书要怎么拆分？每个人抄完的部分怎样核对、合并？如果大家每抄一页都要互相确认，时间就耗在走路和传话上了。

AI 集群面对的是同样的问题。训练大模型时，单块 GPU 的显存装不下全部参数，单块 GPU 的算力也要算上极长的时间，只能把任务拆给很多 GPU。拆开之后，它们必须频繁交换中间结果。按公开资料中的常见描述，大模型训练集群的规模在千卡到万卡量级，更大规模的集群也已见诸报道。规模越大，“传话”的成本越高，网络就越可能成为瓶颈。

所以一个训练集群通常由三部分组成：

- **计算节点**：装有多块 GPU 或其他加速器的服务器，是干活的“工人”；
- **高速网络**：把节点连起来的网卡、交换机和光纤，是工人之间的“传送带”；
- **存储与管理系统**：存放训练数据和检查点（模型的阶段性存档），并负责调度任务、监控故障。

## 4.3.2 高速网络：比家里的网线快在哪里

家里的宽带速度一般是百兆到千兆比特每秒。AI 集群里，单个网络端口的带宽常见为数百吉比特每秒，一台服务器往往配有多张网卡，总带宽比家用宽带高出几个数量级。

带宽之外，**延迟**同样重要。训练过程中，GPU 要不断停下来等其他 GPU 的数据，哪怕每次只多等几微秒，重复数百万次后也会累积成可观的浪费。为此，集群网络普遍采用 **RDMA**（Remote Direct Memory Access，远程直接内存访问）技术。普通网络通信要层层经过操作系统和 CPU，RDMA 则让一台机器的网卡直接读写另一台机器的内存，省去中间环节，好比快递员不经前台、直接把包裹送到收件人桌上。在 AI 集群中，网卡甚至可以直接读写 GPU 显存。

目前主流的集群网络大致有两条技术路线（写作时的情况）：

| 路线 | 特点 | 常见场景 |
|---|---|---|
| InfiniBand（无限带宽网络） | 为高性能计算设计，原生支持 RDMA，延迟低；生态主要由英伟达旗下业务提供 | 许多大型训练集群 |
| 以太网 + RoCE（基于融合以太网的 RDMA） | 在通用以太网上实现 RDMA，设备来源广、成本相对可控，需要精心调优以避免拥塞丢包 | 云厂商和越来越多的自建集群 |

网络的连接方式叫**拓扑**。常见做法是“胖树”（Fat-Tree）类拓扑：服务器先连到机柜顶部的交换机，这些交换机再连到上一层交换机，越往上链路越多，尽量保证任意两台机器之间都有足够的通路。有的系统采用其他拓扑，例如谷歌的 TPU 集群就使用了环面（Torus）结构和光路交换技术，这属于特定厂商的设计，并非通用方案。

## 4.3.3 并行策略：一千个人怎样分工抄书

网络是路，**并行策略**决定车怎么跑。训练大模型时，常见的分工方式有以下几种：

1. **数据并行**：每块 GPU 都持有一份完整的模型，各自处理不同批次的数据，算完后把结果汇总取平均。好比每个人都拿着同一份抄写规范，各抄不同章节。这种方式简单，但要求每块 GPU 都装得下整个模型。
2. **张量并行**：把模型中某一层的大矩阵切成几块，分给几块 GPU 同时计算。好比一页纸太大，几个人各抄一栏。它的通信极其频繁，通常只在一台服务器内部、借助上一节讲的高速互连来做。
3. **流水线并行**：把模型按层切成几段，第一组 GPU 算前几层，算完交给下一组，像工厂流水线一样传递。难点在于避免下游空等上游，即减少流水线中的“气泡”。
4. **专家并行**：用于“混合专家模型”（MoE，Mixture of Experts），把不同的“专家”子网络放在不同 GPU 上，每个令牌只被送到少数几个专家那里处理。

实际训练很少只用一种，而是组合使用，业内常称“3D 并行”或更多维的混合并行。一般的规律是：通信最密集的切分放在服务器内部，通信较少的切分跨服务器进行。**这正是第四章“建立关系”的核心：计算怎样切分，取决于连接有多快。**

## 4.3.4 集合通信：所有人同时“对答案”

无论哪种并行方式，都离不开一类特殊的通信操作，叫作**集合通信**（Collective Communication）：不是两台机器一对一说话，而是一群机器按约定的模式同时交换数据。最典型的是 **All-Reduce**（全归约）：每块 GPU 手里有一份计算结果，操作完成后，每块 GPU 都得到所有结果的总和或平均。数据并行每走一步，都要做一次这样的“全员对答案”。

如果让所有 GPU 都把数据发给一个“组长”，组长汇总后再发回去，组长的网络会被挤爆。常见的解法是**环形 All-Reduce**：把 GPU 排成一个环，每块只和左右邻居传递一小份数据，几轮之后人人都拿到完整结果。这样每块 GPU 的通信量基本不随集群规模增大而上升，网络负载也更均衡。除此之外还有树形等多种算法，由通信库根据拓扑自动选择。

负责这些操作的软件叫**集合通信库**。英伟达 GPU 生态中常用的是 NCCL（NVIDIA Collective Communications Library），其他芯片厂商也有各自的对应实现。深度学习框架在背后调用它们，写模型的工程师通常不必亲手编排每一次传输。

## 4.3.5 小结：规模越大，连接越关键

把视角拉回到本书的锚点：你在手机上提的问题，由一个大模型来回答，而这个模型很可能是在成千上万块 GPU 上、经过数周乃至数月的协同计算训练出来的。在这个过程中，高速网络提供通路，并行策略决定分工，集合通信负责同步，三者缺一不可。集群规模越大，还会冒出新的工程问题，例如某块 GPU 或某条光纤出故障时，怎样从检查点快速恢复，避免整个训练任务停摆。

训练集群把能力“造”出来之后，这些能力还要穿过数据中心的大门，抵达千万用户的终端。下一节，我们就沿着这条路继续向外走，看看云服务、API 网关与你手中的设备是怎样连接起来的。
