# 5.1 数据流：从原始文本到训练批次

你在手机上问 AI“清蒸鲈鱼要蒸几分钟”，它答得头头是道。这份“知道”并不是凭空出现的：在模型训练之前，大量网页、书籍、代码和对话文本经过一条长长的管道，被清洗、切分、编码、打包，最后一批一批送进 GPU。第二章把“数据”当作一个组成部分来看，这一节换一个视角，跟着数据走一遍，看它在系统里怎样流动、在哪里被改变形态。

## 5.1.1 起点：原始文本从哪里来

大模型的训练语料通常有几类来源。下表是公开技术报告中常见的分类，具体比例因公司和模型而异，多数厂商并不完整公开。

| 来源类型 | 典型例子 | 特点 |
|---|---|---|
| 公开网页 | 网络爬取存档，如非营利项目 Common Crawl | 量最大，质量参差不齐 |
| 书籍与百科 | 公有领域图书、维基百科 | 语言规范，知识密度高 |
| 代码 | 开源代码仓库 | 有助于逻辑与编程能力 |
| 学术与专业文本 | 论文预印本、专利 | 专业性强 |
| 授权或合成数据 | 购买的数据集、由模型生成的数据 | 可控性高，需防止质量退化 |

就数量级而言，公开资料中常见的说法是：当前主流大语言模型的预训练语料在“万亿个令牌”这一量级。原始网页存档的体量更大，往往以拍字节（PB，约一百万 GB）计。这里要先记住一点：原始数据和最终喂给模型的数据之间，有很大的落差。

## 5.1.2 第一道工序：清洗、去重与过滤

原始网页里充斥着导航栏、广告、乱码、重复转载和低质量内容。数据管线（Data Pipeline，指把数据从来源一步步加工到可用形态的自动化流程）的前半段，主要做“减法”：

1. **抽取正文**：从网页的 HTML 代码中剥离菜单、按钮、脚本，只留下正文文字。
2. **语言识别**：判断每段文本是中文、英文还是其他语言，按需分流。
3. **去重**：同一篇文章可能被转载成千上万次。工程上常用“近似去重”技术，比如给每篇文档计算一个“指纹”，指纹相近的只保留一份。重复数据会让模型过度记忆某些内容，浪费算力。
4. **质量过滤**：用规则（如符号比例、句子长度）或用一个小型分类模型给文本打分，筛掉垃圾内容。
5. **安全与隐私处理**：过滤有害内容，尝试删除身份证号、电话等个人信息。

经过这几步，留下来的数据往往只占原始数据的一小部分。这有点像自来水厂：江河里的水要经过沉淀、过滤、消毒，真正进入水管的是处理过的水。数据质量直接决定模型上限，业界常说“垃圾进，垃圾出”，就是这个意思。

## 5.1.3 第二道工序：分词，把文字变成数字

计算机不认识“鲈鱼”这两个字，只认识数字。于是要用分词器（Tokenizer）把文本切成一个个令牌（Token，模型处理文字的最小单位），再给每个令牌编号。

主流做法是“子词”切分，常用算法之一叫字节对编码（BPE，Byte Pair Encoding）。它的思路是：先从单个字符或字节出发，统计语料中哪两个相邻片段最常一起出现，就把它们合并成一个新单位，反复合并，直到词表达到预定大小。公开资料中，常见词表规模在数万到十几万个令牌之间。

结果是：高频词往往自成一个令牌，罕见词被拆成几段。一个汉字可能是一个令牌，也可能占一个以上，这取决于具体模型的分词器。所以同一句话，在不同模型里的“令牌数”并不相同——这也是不同 AI 服务按令牌计费时，同样一段中文费用可能不同的原因之一。

分词之后，“清蒸鲈鱼要蒸几分钟”就变成了一串整数，例如“[3812, 5307, 921, ……]”（数字仅为示意）。从这一刻起，文字的流动就变成了数字的流动。

## 5.1.4 第三道工序：配比、打包与组成批次

整理好的数字序列还不能直接送进 GPU，还要经过几步“装箱”：

- **数据配比**：网页、代码、书籍各取多少，是重要的工程决策。比如提高代码比例，常被认为有助于推理能力。配比通常靠小规模实验摸索，各家做法不同，多属内部经验。
- **切成固定长度**：模型一次能读入的长度叫上下文长度（Context Length）。训练时把长文档切段、把短文档拼接，凑成等长的序列，中间用特殊的“文档结束”令牌隔开，避免浪费位置。
- **打乱顺序**：如果模型连续读一万篇菜谱，再连续读一万篇法律条文，学习会不稳定。打乱让每一批数据都尽量“混合口味”。
- **组成批次**：把许多条序列叠在一起，形成一个批次（Batch）。GPU 擅长同时处理大量相同形状的数据，批次就是为了喂饱它而设计的“标准货箱”。在多卡训练中，一个大批次还会被拆分给成百上千张卡各算一部分。

最后，批次通过数据加载器（Data Loader）从存储系统读出，经主机内存、总线送到 GPU 的显存里。这一段看似平淡，却很关键：如果读盘和预处理太慢，昂贵的 GPU 就只能空转等数据。因此大型训练系统通常会提前把数据预处理成紧凑的二进制格式，并在 GPU 计算当前批次时，后台同时准备下一批，像流水线一样衔接。

## 5.1.5 小结：一条把“世界文本”压成“数字货箱”的管道

把整条数据流串起来，可以写成：

> 原始文本 → 抽取与清洗 → 去重与过滤 → 分词编号 → 配比与切段 → 打乱与组批 → 加载进显存

每一步都在改变数据的形态：从杂乱的网页，变成干净的文档，再变成整数序列，最后变成整齐的张量批次。对普通读者来说，记住三个要点就够了：模型学到的东西受语料来源和质量约束；文字在进入模型前已经被分词器“翻译”成了数字；数据供应的速度也是系统性能的一部分。

批次一旦进入显存，数据流就交棒给计算流。下一节，我们跟着一个批次，看它怎样穿过模型完成一次前向传播与反向传播。
