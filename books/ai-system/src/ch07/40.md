# 7.3 深度学习框架与模型格式

打开一个开源模型的下载页面，你会看到一串文件：几个体积动辄数 GB 的大文件，后缀可能是 `.safetensors`、`.bin`、`.gguf` 或 `.onnx`；旁边还有 `config.json`、`tokenizer.json` 这样的小文件。页面上常写着“支持 PyTorch”“可用 llama.cpp 运行”之类的字样。这些后缀和名字指向本节的两个主题：**深度学习框架**是“做出模型和运行模型的工具”，**模型格式**是“把模型装箱、交给别人的方式”。前一节讲的芯片和内存是硬件，本节讲的是人与硬件之间那层最常被提到的软件。

## 7.3.1 框架是什么：把数学变成可以执行的程序

第六章说过，模型的核心运算是一层层的矩阵乘法，训练时还要算梯度、更新参数。如果每个研究者都直接给 GPU 写底层代码，一个模型可能要写几个月。深度学习框架（Deep Learning Framework）就是为此而生的软件工具箱，它主要做四件事：

- **张量运算**：提供“张量”（Tensor，可以理解为多维数字表格）这种基本数据类型，以及加法、矩阵乘、卷积等现成运算。
- **自动微分**（Automatic Differentiation）：开发者只写前向计算，框架自动推出每个参数的梯度。这是反向传播能被大规模使用的关键。
- **硬件调度**：同一行代码，框架负责把它交给 CPU、GPU 或其他加速器上的高效算子库执行，例如英伟达 GPU 上的 cuDNN、cuBLAS 等库。
- **分布式与工具**：数据加载、多卡并行、保存与恢复训练进度等。

一个类比：框架像一家厨房的标准化设备。厨师（研究者）只需决定菜谱（模型结构），灶具、温控、计时由设备负责；换一家厨房（换一种芯片），只要设备接口一样，菜谱基本不用改。

## 7.3.2 主流框架：各有来路

截至写作时，公开资料和学术论文中最常见的框架大致如下（具体格局变化很快，仅作参考）：

| 框架 | 主要发起方 | 常见特点 |
|---|---|---|
| PyTorch | 最初由 Meta（原 Facebook）开发，现由 Linux 基金会下的 PyTorch 基金会托管 | “边写边执行”的动态图风格，调试直观，在学术研究和开源大模型中使用广泛 |
| TensorFlow | 谷歌 | 早期以静态计算图著称，在工业部署和移动端（TensorFlow Lite，现更名为 LiteRT）有较长积累 |
| JAX | 谷歌 | 以函数变换和编译为核心，与谷歌 TPU 配合紧密 |
| 飞桨 PaddlePaddle | 百度 | 国产开源框架，配套中文文档和产业工具 |
| 昇思 MindSpore | 华为 | 与华为昇腾芯片协同设计 |

这里有一个规律值得记住：**框架常常和芯片“结伴而行”**。芯片厂商希望自己的硬件被主流框架良好支持，框架方也希望在更多硬件上跑得快。所以判断一款新 AI 芯片能否被大规模采用，“软件生态是否成熟、主流框架能否顺畅运行”往往和峰值算力一样重要。

## 7.3.3 从“写出来”到“跑得快”：图与编译

研究者写的是 Python 代码，但 GPU 并不认识 Python。中间还要经过几步翻译：

1. **捕获计算图**：框架记录下模型由哪些运算、按什么顺序组成，形成一张计算图（Computational Graph）。
2. **图优化与编译**：深度学习编译器把多个小运算合并成一个大运算（称为“算子融合”），减少数据在显存里来回搬运。第 7.2 节讲过，搬运数据往往比计算本身更耗时，所以这一步收益明显。PyTorch 2.x 中的 `torch.compile`、谷歌的 XLA、开源的 TVM 都属于这一类技术。
3. **生成底层代码**：最终调用针对具体芯片优化过的算子。

训练用的框架追求灵活，部署时则更看重速度和省资源，因此出现了专门的推理引擎，如英伟达的 TensorRT、开源的 vLLM、llama.cpp 等（第 2.4 节已有介绍）。它们读取的往往不是训练时的原始代码，而是一个“装好箱”的模型文件——这就引出了模型格式。

## 7.3.4 模型格式：把参数装进箱子

一个训练好的模型，本质上由三部分组成：**结构描述**（有多少层、每层多宽）、**权重**（上亿到上千亿个数字）、**配套信息**（分词器、数据精度等）。模型格式就是规定这些内容如何存进文件。常见几种：

| 格式 | 来源 | 装了什么 | 典型用途 |
|---|---|---|---|
| PyTorch 检查点（`.pt`/`.bin`） | PyTorch | 主要是权重，依赖 Python 的 pickle 序列化 | 研究与继续训练 |
| Safetensors（`.safetensors`） | Hugging Face 公司推出 | 只存纯张量数据 | 开源模型分发，写作时已十分普及 |
| ONNX（`.onnx`） | 开放神经网络交换格式，由微软、Meta 等发起 | 结构 + 权重的通用计算图 | 跨框架、跨硬件部署 |
| GGUF（`.gguf`） | llama.cpp 项目 | 权重（常为量化后）+ 元数据 | 在个人电脑、手机上本地运行 |

这里有一个与安全相关的细节：pickle 格式在加载时可以执行任意代码，若下载了来路不明的文件，理论上可能被植入恶意程序。Safetensors 只存数字、不存代码，加载时不会执行程序，这是它被广泛采用的重要原因。所以下载模型时优先选 `.safetensors`，是一条实用的安全习惯。

再看下载页上的那些小文件：`config.json` 写着模型结构的超参数，`tokenizer.json` 规定文字如何切成令牌。没有它们，光有权重就像只有砖块却没有图纸，无法还原模型。

## 7.3.5 为什么格式之争重要

格式看似是技术细节，实际上决定了模型能在哪里运行。同一个开源模型，研究者用 PyTorch 格式发布；社区把它转成 GGUF 并量化，普通笔记本也能跑；企业转成 ONNX 或 TensorRT 引擎，部署到数据中心。**格式是连接“训练世界”和“使用世界”的接口标准**，也是第 7.4 节模型压缩和第 9.2 节本地动手实验的前提。

回到开头的下载页：大文件是权重，小文件是图纸和说明书，后缀告诉你该用哪类工具打开。读懂这几个文件名，你就看清了从一行 Python 代码到你手机上一次回答之间，那条由框架、编译器和格式铺成的软件通道。下一节，我们看看这些模型如何被“瘦身”，装进更小的设备里。
